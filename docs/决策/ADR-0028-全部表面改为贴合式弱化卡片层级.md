# ADR-0028：全部表面改为贴合式弱化卡片层级

- 状态：已确认
- 日期：2026-08-09
- 相关文档：[ADR-0012](ADR-0012-视觉方向改为HeroUI风格.md)、[ADR-0023](ADR-0023-视觉修复方向定稿.md)、[ADR-0024](ADR-0024-主窗口分组侧边栏导航.md)、[设计方向与状态规范](../设计方向与状态规范.md)、`src/styles/tokens.css`、[DESIGN.md](../../DESIGN.md)

## 背景

HeroUI 方向（[ADR-0012](ADR-0012-视觉方向改为HeroUI风格.md)）落地后，主窗口的观感与 cc-bar（Swift 版用量统计）对比存在明显差距，产品所有者判断「比 cc-bar 难看很多」。对照 cc-bar 的 `Main/DesignSystem.swift`、`StatsView.swift` 与 `docs/设计风格.md`，差距可归为四点：

1. **卡片靠「浮起」表达层级**：静止阴影（`--shadow-lane`）＋1px 边框＋刻意拉大的卡／画布色差三重强调同时上，页面 = 六张带影子的盒子堆叠，成为 Dashboard 卡片墙。
2. **没有视觉锚点**：cc-bar 顶部有 22pt 大数字 KPI 行做全页主角；CC Trace 的总 Token／总花费只是「按 Provider」标题行右侧一行小字，信息平铺。
3. **字号零碎**：11 / 11.5 / 12.5 / 13 / 15 / 24px 并存，数字与标签同量级，层级拉不开。
4. **结构装饰化**：区块标题带 `700 + 0.04em tracking + 尾部 flex 横线`，横线不承载信息。

cc-bar 的「弱化卡片」机制：卡片背景贴近画布、无静止阴影、仅 hairline 描边兜底；层级交给文字（大数字 22pt／标题 13pt／标签 11pt 三级）；交互色单一；状态色只在状态载体出现。产品所有者确认采用该机制，同时保留 CC Trace 自己的身份：HeroUI 语义色家族（含余量四档）、状态三维体系、Provider 四色与 squircle 色块语言。不引入毛玻璃材质（WebView 跨平台限制，主窗口整窗玻璃本就排除）。

## 决策

以下取值推翻 [ADR-0012](ADR-0012-视觉方向改为HeroUI风格.md) 的「阴影驱动层级」、[ADR-0023](ADR-0023-视觉修复方向定稿.md) 第 1 节的「阴影加档」、[ADR-0024](ADR-0024-主窗口分组侧边栏导航.md) 第 1 节选中态与第 5 节总览摘要形态：

### 1. 层级改为「描边勾勒 + 卡片贴合」

- **删除 `--shadow-lane`**：卡片静止时不带阴影，不再用投影制造「浮起」。交互 hover 的反馈只通过描边加深或底色变化表达，不动布局。
- **新增 `--border-hairline`**：1px 低对比描边，浅色 `rgb(16 16 20 / 8%)`、深色 `rgb(255 255 255 / 10%)`，承担卡片与画布的边界兜底。Web 渲染下 0.5pt 不可靠，hairline 用 1px + 低透明度实现 cc-bar 0.5pt 描边的视觉等价。
- 卡片背景维持浅色 `#FFFFFF`／深色 `#1C1C1F`：与画布（`#F4F4F5`／`#0E0E11`）的色差保留（[ADR-0023](ADR-0023-视觉修复方向定稿.md) 的 canvas 加深结论仍有效，色差是层级的一部分），不再叠加阴影。
- **保留 `--shadow-panel`**：紧凑面板悬浮层阴影是窗口层级阴影，不是卡片层级，不受影响。

### 2. 主窗口新增 KPI 总览行

推翻 [ADR-0024](ADR-0024-主窗口分组侧边栏导航.md) 第 5 节「独立总览大卡拆掉、摘要挂『按 Provider』标题行右侧」：

- 用量页在日期筛选器下方新增 KPI 行：总 Token／总花费／各可见 Provider 花费，每源一卡。
- 卡片形态与其余卡片同族：hairline 描边、无阴影、`0.875rem` 圆角。
- 数字是全页**唯一的大字号**：`22px / 600 / letter-spacing -0.02em / tabular-nums`；标签 `11px` 次文字；Provider 卡标签前带 7px squircle 色块（对齐侧边栏与图例的色块语言）。
- 标题行右侧的原摘要行删除，KPI 行承担同一职责（同范围口径，过滤后数据一致）。
- 不做 delta 对比（cc-bar 有、首版不引入，避免范围膨胀）。

### 3. 侧边栏选中态改蓝底白字

推翻 [ADR-0024](ADR-0024-主窗口分组侧边栏导航.md) 第 1 节「选中态用 track 底色 + 主文字色表达」：

- 选中项使用 `--action-primary` 蓝底 + `--action-on-primary`（新增 token，`#FFFFFF`）白字。
- `--action-soft` 语义改为 hover 态基底；`--action-on-soft` 保留定义但不再是选中态真值。

### 4. 字号 scale 收敛

- 数字档：KPI 22px／600；紧凑面板主百分比 32px／600（不变，已对齐 cc-bar）。
- 标题档：13px／600（区块标题、卡片标题）。
- 正文档：12.5px／400。
- 标签档：11px／400 次文字。
- 小说明：10.5px。
- 消除 11.5px（`0.71875rem`）等奇数小数；表格列头等小标签允许保留 `0.02em` tracking。
- 区块标题删除尾部装饰横线（`::after` flex 线）与 `0.04em` tracking，标题只承担命名。

### 5. 全部表面统一

- **紧凑面板**：Provider lane 删除 `--shadow-lane`（面板内不再「卡中卡」），改 hairline 描边；内容层保持实色。Overall Signal 状态点 tooltip 改用 `--shadow-panel`（它是悬浮层）。
- **设置页**：`sw-card` 删除 lane 阴影，改 hairline。
- **时间线**：`timeline__section` 删除阴影，改 hairline；移除 `--usage-card-shadow` 变量。
- **用量页三卡**（Provider／图表／模型表）：删除阴影，改 hairline，字重收敛（650/620 → 600）。
- 组件统一消费 `--border-hairline`，不在组件里各自 `color-mix` 边框。

## 与 cc-bar 的差异（不照搬的部分）

- 不引入 `regularMaterial` 毛玻璃或半透明卡片背景（WebView 跨平台、主窗口实色原则不变）。
- 语义色保留 HeroUI 家族（cc-bar 用 Apple 系统色）；状态三维（live／stale／error）是 CC Trace 独有，砍不了。
- 深色卡保持实色 `#1C1C1F` 而非半透明（实色画布下半透明没有意义，`#1C1C1F` 已是贴合的等价物）。

## 理由

- 「弱化卡片」不是美学偏好，是信息层级工程：卡片融入背景后，层级只剩文字（数字独大）与描边（边界勾勒），扫视时焦点唯一。
- 静止阴影在每个卡片上重复出现，视觉上「所有东西都在强调自己」，等于没有层级；描边是安静的边界，只有信息在说话。
- KPI 行给页面一个视觉锚点：22px 数字是整页唯一的大字号，其余全部退到 12.5px 以下，这正是 cc-bar 被认可的核心机制。
- 蓝底白字选中态提供确定性导航反馈，cc-bar 用 accent 蓝底、HeroUI 导航惯例也一致。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 保留 HeroUI 阴影方向，只修细节 | 产品所有者确认阴影盒子墙是「丑」的主要来源，局部微调不解决层级问题 |
| 全面照搬 cc-bar（毛玻璃、系统色、Apple 系状态色） | WebView 跨平台不适用；CC Trace 的语义色体系与状态模型已有测试与文档绑定，砍掉是降级不是升级 |
| KPI 行带 delta 对比 | 需要前一周期间口与数据，超出本次视觉改造范围，首版不引入 |

## 后果

- `src/styles/tokens.css`：删除 `--shadow-lane`（浅色、深色共 3 处），新增 `--border-hairline`、`--action-on-primary`；`--action-soft` 注释更新为 hover 基底。
- 涉及组件：`MainView.vue`（KPI 行、删摘要、删标题横线）、`UsageProviderCard.vue`、`UsageDailyChart.vue`、`UsageModelTable.vue`、`MainSidebar.vue`、`ProviderLane.vue`、`OverallSignal.vue`、`SettingsView.vue`、`TimelineView.vue`。
- `docs/设计方向与状态规范.md` §1／§3.4／§6／§7.6／§12、`DESIGN.md` 同步改写。
- 实机走查仍属第 16 阶段；浏览器预览验证结果写入执行清单对应条目。

## 复审条件

- 若浅色下 hairline 描边不足以区分卡片与画布（低对比度环境），加深 `--border-hairline` 透明度一档，不需推翻方向。
- 若深色下 10% 白描边过重，退回 8%；若不够，允许到 12%。
- 若 KPI 行在最小窗口（内容区 720px−176px）下挤压，允许折为两行（`auto-fit` 已预留），不改卡片语义。
