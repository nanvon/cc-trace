# ADR-0004：紧凑面板两个平台统一 380px

- 状态：已确认
- 日期：2026-07-25
- 相关文档：[设计方向与状态规范](../设计方向与状态规范.md) 第 5.3 节、[桌面壳验证记录](../桌面壳验证记录.md)

## 背景

第 7 阶段的设计方向建议紧凑面板在 macOS 使用 `360px`、Windows 使用 `380px`，理由是两个平台的系统区域弹层习惯不同。Tray 桌面壳实现时统一使用了 `380px`。

## 决策

紧凑面板在两个平台统一为 `380 × 470`，最小 `340 × 420`，最大 `420 × 560`。平台差异只体现在锚点位置（Menu Bar 图标下方 / Tray 附近）和外壳材质，不再体现在宽度。

## 理由

- 两个平台展示的是同一份内容：两个 Provider lane、总体状态、全局操作。20px 的宽度差不改变任何断点或换行决策。
- 内容宽度一旦按平台分叉，长账号名、长模型名和中英文的截断验证就要做两遍。
- 平台得体来自锚点、材质和窗口行为，不来自宽度差异。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 保留 360／380 双宽度 | 需要双份文本截断与布局验证，收益不可感知 |
| 按内容自适应宽度 | 紧凑面板每次打开宽度会变，破坏“稳定 lane”与肌肉记忆 |

## 后果

- 设计方向文档中的双宽度建议已作废，第 5.3 节改为记录实测值。
- 尺寸真值在 `src-tauri/tauri.conf.json`，文档与配置必须同时修改。

## 复审条件

- Windows 实机验证发现 `380px` 在高 DPI 或不同缩放下明显不合适。
- 首版之后紧凑面板需要承载新内容。
