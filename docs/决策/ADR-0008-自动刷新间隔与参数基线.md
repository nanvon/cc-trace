# ADR-0008：自动刷新间隔 15／30／60 分钟，默认 30 分钟

- 状态：候选值与默认值部分已被 [ADR-0022](ADR-0022-自动刷新间隔与手动刷新间隔同步ccbar.md) 撤销（改为 1/2/3/5/10 分钟，默认 2 分钟）；工程参数基线的归属关系与「手动刷新不绕过退避」等未被触及的部分继续有效。
- 日期：2026-07-25
- 相关文档：[产品范围](../产品范围.md) 基础设置、[技术架构](../技术架构.md) 首版参数基线

## 背景

产品范围只写了“可配置的自动刷新间隔”，没有候选值和默认值；技术架构只写了“加入轻微抖动”，没有节流、超时和退避数值。第 8 阶段的交互原型里已经出现了 15／30／60 分钟三个选项，但没有任何文档记录这个决定。参数缺失会让验收无法判定对错，也会让实现把数值散落在代码常量里。

## 决策

- 用户可选自动刷新间隔：`15`、`30`、`60` 分钟，默认 `30` 分钟。
- 首版不提供“关闭自动刷新”。
- 工程参数（抖动、手动刷新节流、请求超时、429 与网络退避、快照降级阈值、启动与唤醒刷新）按技术架构“首版参数基线”表。
- 退避期内手动刷新不发起真实请求，只展示可再次尝试时间。

## 理由

- 额度是慢变量：主窗口是 5 小时或周窗口，分钟级刷新没有额外信息价值，只增加限流风险。
- 30 分钟默认值在“信息足够新”和“请求足够少”之间取中，且与三个候选值形成对称。
- 不提供关闭：应用的唯一价值是“不用主动查就知道额度紧不紧”，关闭自动刷新会让它退化成一个手动查询器；用户真想省请求可以选 60 分钟。
- 参数写进文档而不是代码常量，才能在验收时逐项对照。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 提供 5 分钟等更短间隔 | 额度变化慢，提高限流概率而无信息收益 |
| 提供“关闭自动刷新” | 与产品核心价值冲突，60 分钟已覆盖该需求 |
| 自由输入任意间隔 | 增加校验与异常值处理，首版无对应需求 |
| 按额度紧张程度动态调整间隔 | 行为不可预测，用户无法解释请求时机；可作后续评估 |

## 后果

- 三个候选值与默认值必须同时出现在设置界面、i18n 文案和验收清单里。
- 参数调整必须先改技术架构的参数基线表，再改代码。

## 复审条件

- Provider 实测出现频繁限流，或 `Retry-After` 长期大于当前退避上限。
- 用户反馈需要更长间隔或需要临时暂停刷新。
