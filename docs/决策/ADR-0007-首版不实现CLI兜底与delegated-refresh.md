# ADR-0007：首版不实现 CLI 额度兜底与 delegated refresh

- 状态：已确认
- 日期：2026-07-25
- 相关文档：[额度领域模型](../额度领域模型.md) 第 3.3 节、[产品范围](../产品范围.md)

## 背景

旧版 Claude Code 支持两条额外恢复链（证据等级“代码已确认”，见 [04-账号凭据Provider与额度协议](../cc-bar-reference/04-账号凭据Provider与额度协议.md)）：

- **delegated refresh：** token 刷新失败时定位本机 Claude CLI，通过受控 probe 目录、PTY 和可选 watchdog 让 CLI 自己完成受信任刷新，带 5 分钟冷却。
- **CLI 额度兜底：** 手动整体刷新、API 已失败且当前没有快照时，运行 `claude` CLI 的 `/usage`、`/status`、`/exit` 交互，清理 ANSI 后解析文本。

旧版还记录了一个未决风险：CLI 兜底成功时不清除既有退避，与 API 成功清除退避的行为不一致。

## 决策

首版都不实现。Claude Code 的额度只来自官方 OAuth usage 接口；token 刷新失败归为 `error`，由用户在对应 CLI 重新登录。

## 理由

- 两者都需要启动外部进程、分配 PTY、解析终端输出，与首版“权限克制：只申请首版能力真正需要的权限”直接冲突。
- 解析 CLI 的交互输出依赖对方的文案与 ANSI 格式，是最脆弱的一类数据来源，任何上游改版都会静默失效。
- Windows 上的 PTY、进程发现和 CLI 行为需要一套完全独立的实现与验证，首版没有验证预算。
- 旧版已记录的退避清除不一致说明这条路径的状态语义本身还没收敛，不适合原样继承。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 只做 delegated refresh，不做额度兜底 | 仍需 PTY 与外部进程，权限成本不变 |
| 只在 macOS 提供 | 两平台能力不一致，且违反“核心能力一致”的产品承诺 |
| 用文档告知用户手动跑 CLI | 这其实就是首版做法：`error` 文案指向在对应 CLI 重新登录 |

## 后果

- token 过期或被吊销时，CC Trace 只能提示用户去 CLI 重新登录，不会自动恢复。
- 首版对 Claude Code 的额度可用性完全依赖官方接口，接口故障时只有旧快照。

## 复审条件

- Provider 闭环后发现 token 失效频率高到影响日常使用。
- 出现不需要 PTY 的官方刷新或诊断入口。
