# ADR-0034：项目身份与未归属口径

- 状态：已确认
- 日期：2026-10-01
- 相关文档：[ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md)、[数据存储与用量索引](../数据存储与用量索引.md)、[信息架构与核心流程](../信息架构与核心流程.md)、[产品范围](../产品范围.md)

## 背景

cc-bar v1.1.1 有独立的项目分析页，它的项目身份来自「把日志里的 cwd 归一为稳定项目路径」。归一过程有意做了隐私分级，因为不是所有路径都能安全访问：

- 家目录以外（可移动卷、网络宗卷、其他用户目录）与 TCC 保护目录（桌面、文稿、下载、音乐、图片、影片）下不做任何文件系统调用，只按字符串归组，状态标 `unverified`。非沙盒应用访问这些路径会触发系统的「文件与文件夹」授权弹窗。
- 家目录内且不在保护目录下的路径才做存在性检查、符号链接解析与 Git 根探测。
- worktree 归入主仓库：worktree 根目录的 `.git` 是一个文件，内容为 `gitdir: <主仓库>/.git/worktrees/<名称>`，`commondir` 指回主仓库 `.git`。三处路径任一落在禁查范围内就按独立项目处理。
- 不可归到任何项目的事实（Cursor 远端计量、补录与早期按天汇总历史）单列为**未归属**分组，不分摊到任何项目。
- cc-bar 自己的探针目录（`ccbar-codex-wakeup`、`claudeprobe` 等）单列为系统项目。

本仓库此前没有项目概念：`conversations` 只存脱敏展示名 `project_hint`（路径尾段），且 [产品范围](../产品范围.md) 与 [ADR-0018](ADR-0018-用量数据用SQLite与JSON分域.md) 明确「数据库与 command 载荷不包含明文项目路径」。

## 决策

### 1. 推翻「项目路径不落库」这条边界

`conversations` 表新增 `project_key`（项目身份键，规范化路径）与 `worktree_path`（对话自身工作目录），command 载荷可以携带它们。理由是项目页的核心信息就是「哪个目录花了多少」，没有路径就没有这个页面；而路径对本机用户不是秘密。

数据边界改为：

- **仍然不进库与日志**：原始消息正文、token、凭据、邮箱以外的账号字段、JSONL 原始行、外部文件绝对路径（日志文件自身的位置）。
- **进库、不进日志**：项目路径与 worktree 路径。它们只出现在 `conversations` 表与 command 载荷里，**不进任何日志与诊断信息**。
- 隐私模式开启时，界面按 [ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md) 的隐私模式规则遮挡路径、分支与对话身份；遮挡在展示层，不在存储层。

### 2. 归一规则

1. cwd 为空、等于根目录或家目录 → **未归属**。
2. cc-trace 自己的探针目录 → **系统项目**（单独一条，不混进用户项目）。
3. 其余路径：先做纯文本规范化（去尾部分隔符、限长），得到候选身份键。
4. 只有「在家目录内且不在受保护目录下」的路径才允许文件系统检查：
   - 存在则解析符号链接；
   - 目录则向上找最近的 Git 根；
   - 命中 Git 根时身份键用 Git 根，否则用规范化后的原路径；
   - 结果标记为 `available` / `unavailable`。
5. 不允许检查的路径按字符串归组，标记 `unverified`（界面不声称它存在，也不声称它是 Git 仓库）。
6. worktree（`.git` 是文件）归入主仓库身份，明细里单独展示 worktree 路径与分支。

受保护目录在 macOS 上是 `Desktop`、`Documents`、`Downloads`、`Music`、`Pictures`、`Movies`；Windows 上对应 `%USERPROFILE%` 下的同名目录（含被 OneDrive 重定向后的路径），另加体积敏感的同步目录判定位置见批次 5 实现说明。判定一律大小写不敏感，拿不准时**不检查**：宁可少查一次，也不弹一次授权框。

### 3. 未归属分组

- Cursor 远端计量、补录与早期按天汇总历史的事实行标 `unattributed = 1`，项目页最后一行显示为未归属分组，不参与项目排序以外的任何聚合。
- 未归属条目**不进入对话列表**：它们没有对话身份（Cursor 不提供会话 id）。

## 理由

- 「路径不进库」这条边界的收益是防止隐私泄露；它的成本是项目页无法成立。收益可以通过「不进日志、隐私模式遮挡」保留，成本却只能通过允许路径落库消除——所以按收益/成本重新划分，而不是整体保留或整体放弃。
- 分级检查不是洁癖：一次误触发的系统授权弹窗会让用户对整个应用产生不信任，而 Git 根探测失败的代价只是项目按目录而非仓库聚合。
- 未归属必须显式存在：把无法归属的用量摊进某个项目会伪造数据，直接丢弃则与「总用量」对不上账。

## 替代方案

1. **只存路径哈希**。被否决：项目页要展示路径与「在文件管理器中显示」，哈希无法支撑这两个功能。
2. **所有路径都做 Git 根探测**。被否决：会触发系统授权弹窗，且网络宗卷上的探测有超时风险。
3. **不做 worktree 归组**。被否决：同一仓库的多个 worktree 会被拆成多个项目，用户看不到仓库真实总量。

## 后果

- schema v7 的 `conversations` 新增 `project_key`、`worktree_path`、`unattributed` 三列；查询新增项目维度分组与项目过滤。
- 既存数据在重扫或「重新计算用量」后补齐项目身份；未重扫前这些行按未归属之外的旧行为（`project_hint` 仍可用于展示名）。
- 项目页是新增视图，导航与信息架构在批次 5、批次 10 同步。

## 复审条件

- Windows 实机验证发现路径规范化或 Git 探测在盘符、UNC 路径、符号链接（junction）上的行为与 macOS 不等价时。
- 隐私模式被要求覆盖存储层（而不只是展示层）时。
