# ADR-0027：本地用量数据重建进入首版

- 状态：**已确认**
- 日期：2026-08-09
- 确认依据：产品所有者确认需要与 cc-bar「重新计算用量」（`forceRescan`）等价的数据修复能力，
  并确认同时修复入库冲突「只增不减」导致的官方 cost 永不采纳问题。
- 相关文档：[产品范围](../产品范围.md)、[技术架构](../技术架构.md)、[测试策略](../测试策略.md)、
  [OpenCode数据源](../OpenCode数据源.md)

## 背景

CC Trace 的用量数据源是**只读增量扫描**（Codex／Claude Code JSONL 水位、OpenCode SQLite 水位），
水位只进不退。已确认的真实故障：OpenCode 在 8/7–8/8 期间入库时尚未写 cost 字段，
CC Trace 把 3336 条（约 78%）条目的 `api_equivalent_cost_nanos` 存为 NULL；之后 OpenCode
补写了历史 cost，但增量扫描不会重读旧数据，这些条目的费用永久缺失。应用内没有任何
入口可以修复这类数据（`usage_reprice` 只重算 codex/claude，`usage_scan_start` 是增量）。

cc-bar 已有等价能力：设置页「重新计算用量」全量重扫，且 scan-state 失效（版本、指纹、
generationID 不符）时自动全量重建。CC Trace 首版只补**用户可触发的重建**，自动失效机制留作后续。

## 决策

### 1. 重建语义

- 新增 command `usage_rebuild_data`：按 `sources` 参数（`None` 或空 = 全部数据源；
  支持任意子集）删除该数据源的 `usage_entries`、无引用的 `conversations` 与
  `scan_files` 水位行；含 OpenCode 时重置 `opencode_state`（水位回到 0），随后立即触发
  一次全量重扫（复用现有 `start_scan` 启动路径与后台线程）。
- 重建是**破坏性**操作：删除的是 CC Trace 自己的派生数据（可随时从外部数据源重建），
  不触碰、不修改任何外部文件（JSONL 与 OpenCode 库只读）。
- 重建期间扫描已在运行时返回 `ScanBusy`（与 `usage_reprice` 相同），由前端提示稍后再试。
- `quota_events`（额度事件历史）、设置、价格目录不受重建影响。

### 2. 入口与交互

- 设置视图「用量与计价」组新增「重新计算用量」按钮，与价格目录更新按钮同卡。
- 交互：首次点击进入确认态（按钮变「确认重新计算？」、危险色，10 秒未确认自动退回）；
  确认后删除并全量重扫，按钮进入「重新计算中…」禁用态，前端每秒轮询
  `usage_scan_status`，扫描结束后显示完成文案；busy 失败显示错误文案。
- 首版 UI 只提供「全部数据源」一个入口；命令层已支持单源子集，单源 UI 留作后续。
- 不做自动失效重建（cc-bar 的 fingerprint／generationID 校验），留作后续。

### 3. 入库冲突改为「官方直存源无条件覆盖」

- `usage_entries` 的 `ON CONFLICT(source, dedup_key) DO UPDATE` 原条件为「新 token 总和
  大于旧值才更新」，用于防止价格表驱动的 codex/claude 被上游倒算。
- 改为：`source IN ('codex','claude')` 保持「只增不减」；其他数据源（pi、opencode，
  官方 cost 直存、不参与价格表）**无条件覆盖**——上游补写或修正的 cost／token 必须被采纳，
  否则重建之后同一问题仍会复发。
- 已知小影响：pi／opencode 重复入库时 `duplicate_entries` 统计口径变化（覆盖计为 inserted），
  不影响数据正确性。

## 与 cc-bar 的差异

- cc-bar 的 `forceRescan` 清空内存聚合后全量重扫，无磁盘删除；CC Trace 重建删除
  `usage_entries`／`conversations`／水位后全量重扫，效果等价（CC Trace 派生数据在 SQLite，
  删除即清空）。
- cc-bar 有 scan-state 失效自动重建；CC Trace 首版不做（见上文）。
- cc-bar 支持在设置页更新价格目录后自动触发重算；CC Trace 已有 `usage_reprice` 重计价
  路径，不因本 ADR 改变。

## 代价与风险

- 全量重扫耗时取决于外部数据规模（本机 Codex＋Claude 约数万条），重建期间用量页显示
  「扫描中」占位，完成后自动刷新；扫描可被现有 `usage_scan_cancel` 取消。
- 删除操作在同一事务内完成，中途失败不会留下半删状态（SQLite 事务回滚）。
- `rebuild_data` 的 SQL 条件由静态枚举常量拼接（`source` 值不来自 command 输入），
  无注入风险。

## 复审条件

- 若后续引入 cc-bar 式自动失效重建，本 ADR 的第 2 节「不做」相应撤销并更新文档。
- 若 pi 或 opencode 改为价格表驱动，重新评估第 3 节的无条件覆盖是否仍成立。
