# ADR-0024：主窗口改为分组侧边栏导航

- 状态：已确认
- 日期：2026-08-08
- 修订：2026-08-09，Provider 卡恢复 Token 分类明细（输入／输出／缓存读／缓存写），见文末修订节
- 修订：2026-08-10，Provider 卡底部条由缓存命中率条改为 Token 占比条（命中率只留数字），见文末修订节
- 修订：2026-08-09，第 1 节「选中态用 track 底色＋主文字色」与第 5 节「总览摘要挂标题行右侧」被
  [ADR-0028](ADR-0028-全部表面改为贴合式弱化卡片层级.md) 推翻（选中态改蓝底白字、新增 KPI 总览行）；
  侧边栏结构与数据源全局过滤不受影响。
- 相关文档：[ADR-0020](ADR-0020-主窗口改为本地用量页.md)、[ADR-0023](ADR-0023-视觉修复方向定稿.md)、[信息架构与核心流程](../信息架构与核心流程.md)、[产品范围](../产品范围.md)、[设计方向与状态规范](../设计方向与状态规范.md)、`src/views/MainWindowView.vue`、`src/components/MainSidebar.vue`
- 对照的评审稿：[`prototypes/visual-refresh/`](../../prototypes/visual-refresh/index.html) 第 2～3 节

## 背景

[ADR-0020](ADR-0020-主窗口改为本地用量页.md) 确认主窗口为本地用量页，Timeline 与 Conversations 作为第二、三视图进入首版，当时的导航形态是「用量页顶部文字按钮 + 设置二级视图返回」。2026-08-02 的 `visual-refresh` 评审稿把主窗口导航形态评审为**分组侧边栏**（视图组 + 数据源组 + 设置钉底），标注为「未来形态，首版不实现」。2026-08-08 产品所有者决定**按评审稿完整实现**，并将产物注记中「对话／时间线是未来视图，首版不做」正式撤销——这两个视图已经实现并进入首版。

## 决策

主窗口导航改为**左侧 176px 分组侧边栏**，正式撤销 [ADR-0020](ADR-0020-主窗口改为本地用量页.md) 第 7.6 节「设置不与用量并排，也不形成常驻侧边栏或 Tab」与 [信息架构与核心流程](../信息架构与核心流程.md) §2.3 的对应表述。

### 1. 侧边栏结构

- **视图组**：用量、对话、时间线三个视图项。产物「后续」chip 不实现——三个视图都已进入首版，正常列出、可点击。
- **数据源组**：全部 / Codex / Claude Code / Pi / OpenCode。产物只有两个数据源（2026-08-02 产物早于 Pi 与 OpenCode 进入首版），按现状列出全部四个源。
- **设置钉底**：侧边栏底部固定设置项，与数据源无关，用分隔线隔开。
- 选中态：`sb-item.on` 用 track 底色 + 主文字色表达；数据源组点按「全部」或单个源。

### 2. 数据源全局化

- 侧边栏数据源选中态是**全局状态**：跨用量、对话、时间线页面共享，切换视图时保留。
- **不持久化**：只存在内存（Pinia `usage` store 的 `sourceFilter`），重启后回到「全部」。设置页的「统计服务」开关仍然持久化并继续生效，两者是不同维度——开关决定哪些服务参与统计，侧边栏决定当前查看哪一个。
- 时间范围留在各页面内，不随数据源共享。
- 选中单个源后页面所有区块纯过滤收窄：总览摘要、Provider 卡、图表、模型表只显示该源数据，数字纵向对账仍成立。

### 3. 设置钉底与数据源组隐藏

- 进入设置视图时**隐藏数据源组**（设置无数据源维度，避免「改了没反应」的错觉），视图组保留以便返回。
- 对话、时间线视图下数据源组**保留显示**（产物未定义，因为当时这两个视图不做；现在已实现，数据源过滤对它们同样有意义）。
- 原「返回用量」按钮移除，返回语义由侧边栏承担；用量页顶部的时间线／对话／设置文字按钮全部移除，入口统一进侧边栏。

### 4. 窗口尺寸维持 1600×1100

产物注记建议主窗口 `960 → 1180px`（当时窗口是 960px）。本决策**不采纳 1180**：现状窗口已是 1600×1100（ADR-0020 后随设置同窗定稿），且数据源扩展为四个源后 Provider 卡需要更宽的内容区。侧边栏 176px 照产物实现，窗口尺寸维持 [设计方向与状态规范](../设计方向与状态规范.md) §5.3 的表值不变。

### 5. 用量页内容布局（与 ADR-0023 共用同一套卡片语言）

- 独立总览大卡（总 Token + 总花费两行读数）**拆掉**，摘要挂「按 Provider」标题行右侧：`总 Token X · 总花费 $Y`，钱为主、Token 为次。
- Provider 卡：色点 + 名称 / 费用 + 总 Token / Token 分类两行（输入、输出、缓存读、缓存写，每行两列）/ Token 占比条（4px，Provider 品牌色降饱和）＋缓存命中率数字（success 绿）。Token 分类对齐 cc-bar By service 卡片，见文末修订节；Fast 等效 Token 与倍率不上卡。
- Provider 卡网格 4 列；选中单个源时收为 1 列。
- 图表高亮语义：非所选范围透明度对齐评审稿（产物 CSS 实际取值 `0.35`，注记的"20%"以 CSS 为准）。
- 按模型表按产物 **7 列**：模型 / 输入 / 输出 / 缓存命中 / 缓存写入 / 总 Token / 花费，「命中率」列删除（命中率已由 Provider 卡承担）。

### 6. 设置页形态（内容零增减）

设置页按产物第 3 节形态重构：640px 单列阅读宽度居中、卡片式分组（`sw-card` 14px 圆角 + lane 阴影）、行式条目（label 左、控件右）、toggle 开关与 segmented 控件。**设置项零增减**，内容与现有 i18n 完全一致。刷新间隔选项现状为 1/2/3/5/10 分钟五档，保留 `select`（产物 segmented 三档放不下五档，且产物注记明确「设置项零增减」）；语言与外观三档照产物改 segmented。

## 理由

- 产品所有者明确要求「完完整整按评审稿还原」，导航形态是评审稿的核心主张之一。
- 视图已经进入首版，侧边栏是三个视图 + 设置共四个目的地的自然导航形态；顶部堆三个文字按钮 + 二级视图返回在四个目的地时已不可扩展。
- 数据源全局化让「查看某一家服务」成为跨页面的一致性操作，与设置页持久化的统计开关职责分离、互不冲突。
- 选中态不持久化符合评审稿「时间范围留在页面内」的同类原则：全局视图状态的边界是「切换视图保留」，不是「重启后保留」；持久化会与设置页统计开关产生两个可持久化数据源维度，语义重叠。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 维持顶部按钮 + 二级返回 | 四个目的地已不可扩展，产品所有者明确不满意现状样式 |
| 侧边栏 + 数据源选中态持久化 | 与设置页统计开关语义重叠，且评审稿未要求 |
| 窗口改 1180px | 现状 1600×1100 已定稿且容纳四个 Provider 卡更从容，产物 1180 按双源 + 占位卡计算 |

## 后果

- 新增 `src/components/MainSidebar.vue`；`src/views/MainWindowView.vue` 外壳加侧边栏；`MainView.vue` 布局重构、顶部按钮移除；`UsageProviderCard.vue` 改三要素卡；`UsageModelTable.vue` 去命中率列；`SettingsView.vue` 卡片形态重构、返回按钮移除；`ConversationsView.vue` 源过滤改为读 `sourceFilter`。
- `usage` store 新增 `sourceFilter`（内存态）。
- [信息架构与核心流程](../信息架构与核心流程.md) §2.3、[设计方向与状态规范](../设计方向与状态规范.md) §5.3/7.6/12、[产品范围](../产品范围.md) 首版完成标准同步更新。
- 快捷键不变（`⌘,` 等）；产物注记的 `⌘1/⌘2` 视图快捷键保持「待切片时定」，本 ADR 不引入。

## 复审条件

- 若实机验证发现 176px 侧边栏在中英文 + 200% 文字缩放下拥挤，调整侧边栏宽度或让 `sb-item` 允许换行，不需要推翻侧边栏形态。
- 若四个 Provider 卡在 1600px 窗口下仍显拥挤（Pi / OpenCode 接入后卡均宽约 300px），考虑恢复横向滚动或两行排布，作为布局微调处理。

## 修订（2026-08-09）：Provider 卡恢复 Token 分类明细

产品所有者实际使用后要求卡片显示详细 Token，而不是只给总和。本修订推翻第 5 节「输入／输出／缓存命中／缓存写入四指标行删除，交还按模型表」：

- Provider 卡新增 Token 分类两行：输入／输出一行、缓存读／缓存写一行（每行两列，左标签右数值，复用命中率行的字号体系）。
- 缓存读 / 缓存写合计口径与按模型表一致（`cacheReadInputTokens`、`cacheWrite5m + cacheWrite1h`），数字仍与模型表对账一致。
- 按模型表 7 列不变，卡与表并存，不互相替代。
- Fast 等效 Token 与倍率不上卡：Pi 与 OpenCode 无 Fast 概念，且 Fast 明细已由按模型表与对话详情承载。

## 修订（2026-08-10）：Provider 卡底部条改为 Token 占比

产品所有者评审后决定：卡底部的条不再表达缓存命中率，改为 **Token 占比**（该源 `totalTokens` ÷ 可见源合计，与统计服务过滤归一化口径一致），对齐 cc-bar By service 卡片「条 + 占比」形态：

- 占比条复用余量条形态（Provider 品牌色降饱和，条宽取样式真值），配占比数字（主文字色）。
- 缓存命中率**只保留数字**，常驻 success 绿，位于占比条下方一行；命中率分母口径不变（见 [数据存储与用量索引](../数据存储与用量索引.md) §2.1.1）。
- 理由：命中率是质量比值，用条表达会造成「条长 = 用量大小」的认知错位；cc-bar 的每日用量图已改按 Token 展示，占比口径向 Token 收敛更自洽；四源并排时占比条直接回答「谁是 Token 大头」。
- 占比分母由 `MainView.vue` 传入（`sourceSummary.tokens.totalTokens`）；合计为 0 或未加载时显示「—」。
- cc-bar 的 By service 条（现为花费占比）另行排期同步改为 Token 占比，本 ADR 不覆盖。
