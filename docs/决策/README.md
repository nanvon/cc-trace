## 补写说明

ADR-0001 至 ADR-0005 对应的决策在 2026-07-25 之前已经确认并写入规范文档，但当时没有单独记录理由。这几份 ADR 是事后补写，理由与替代方案依据现有文档和 cc-bar 只读参考重建。如果与当时的实际考量不符，直接更正对应文件。

ADR-0006 至 ADR-0008 是 2026-07-25 文档补全过程中新提出并获授权采纳的决策，其中带“待确认”标记的部分尚未经过真实数据验证。

ADR-0009 与 ADR-0010 是 2026-07-25 第 11 阶段收口时提出并获授权采纳的决策，两者都涉及提前使用后续阶段的能力，理由与边界见各自文件。

ADR-0011 是 2026-07-25 实机查看后由产品所有者确认的窗口结构修正。它推翻规范与原型中“设置使用独立窗口”的旧结论；旧结论此前没有单独 ADR。

ADR-0013 至 ADR-0015 是 2026-07-27 启动第 12 阶段时提出并获授权采纳的决策，三者都推翻了更早确认的结论：ADR-0013 推翻“不读 macOS Keychain”，ADR-0014 局部推翻第 4 阶段“不写回外部凭据文件”的数据边界，ADR-0015 推翻“桌面壳实机验证前不开始 Provider 最小闭环”的门禁。

ADR-0016 在 2026-07-28 经两次修订：开发期固定签名由自签名证书改为免费 Apple ID
的 Apple Development 证书；GitHub 公开发布则改用无需上传证书的 ad-hoc 签名。两个修订
都保留“不购买 Apple 开发者账号、不做公证”的原决策。

ADR-0017 是 2026-07-27 产品所有者实机查看界面后提出的三项修正，一并记录在同一份 ADR 里，因为它们出自同一次评审：推翻信息架构“不把多个 Provider 数字塞进系统区域”，推翻设计规范“紧凑面板动作不依赖图标”，并新增额度余量四档色这个此前不存在的着色维度。前两项是推翻，第三项是新增。
2026-07-28 进一步明确系统区域与卡片主行都使用 Provider 标准化输出的第一项，不再固定查找 5 小时窗口。

ADR-0018 于 2026-07-30 由产品所有者确认，同时明确授权先完成 Rust 数据切片、后补 GitHub Release 实跑。被推翻的只是依赖引入顺序，macOS 双架构与 Windows MSVC 的发布验证仍未完成。

ADR-0021 于 2026-07-30 由产品所有者确认：价格来源、优先级、刷新与 Fast 语义同步当日
更新后的 cc-bar；CC Trace 利用 SQLite 只重算派生列，不照搬 cc-bar 的 JSONL 重扫实现。

ADR-0022 于 2026-08-03 由产品所有者确认：自动刷新候选值、默认值与手动刷新最小间隔同步
cc-bar，明确接受 ADR-0008 曾经否决的限流风险作为已知代价；429 退避与本地用量扫描间隔
不在本次范围内，维持原设计。

ADR-0026 于 2026-08-09 由产品所有者确认：推翻「首版不实现 Statuspage 状态链」的结论，
Codex／Claude Code 官方服务状态进入首版，行为对齐 cc-bar（5 分钟独立循环、失败保留旧值、
unknown 不显示、开关默认开）；两条状态链保持分离。

ADR-0025（非隐私模式）与 ADR-0026（Statuspage）均为 2026-08-09 由产品所有者确认；
编号按当日确认顺序排列。
