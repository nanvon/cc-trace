# ADR-0012：视觉方向改为 HeroUI 风格

- 状态：已确认
- 日期：2026-07-27
- 相关文档：[设计方向与状态规范](../设计方向与状态规范.md)、[DESIGN.md](../../DESIGN.md)、`src/styles/tokens.css`

## 背景

第 7 阶段确认的 Reset Rail 方向以直轨道、克制描边和near-中性配色为核心，强调"扫描效率高于视觉表演"的 `Operate` 界面哲学。第 11 阶段桌面壳落地后，产品所有者用 shadcn、HeroUI 两套探索稿和一份介于两者之间的自定折衷方向（Trace Rail：等宽数字、带刻度细轨道、阴影驱动层级）逐一比对，结论是：

- 纯 shadcn 方向"太素"，克制到失去个性。
- 折衷的 Trace Rail 方向同样"不好看"——试图两头讨好没有产生更好的结果。
- HeroUI 方向（更大圆角、阴影驱动层级、更饱和且更常出现的语义色、发光主按钮、呼吸感状态点）最符合产品所有者的期待。

产品所有者明确要求"完完整整完完全全按照 HeroUI 这份 Artifact 的样式来，彻底摒弃之前的"，不做保留、不做折衷。

## 决策

CC Trace 的视觉方向由 Reset Rail 全面改为 **HeroUI 风格**：

- **形状**：圆角从 7/11px 提升到 12/14px（`--radius-small` / `--radius-medium`）；紧凑面板外壳维持 16px。
- **层级**：Provider lane 静止时即带阴影（新增 `--shadow-lane`），不再要求"交互时才增强阴影"；卡片保留极淡描边，浅色/深色下都不去掉，与 HeroUI 卡片一致。
- **颜色**：交互色从 Trace Blue `#2F67D8` 换成 HeroUI primary `#006FEE`（深色 `#338EF7`）；成功/警示/错误三个语义色同步换成 HeroUI 的 `#17C964` / `#F5A524` / `#F31260`；背景与卡片表面色值刻意非常接近（`#FAFAFA` vs `#FFFFFF`），层级主要靠阴影而不是色差表达。
- **进度表达**：Reset Rail 的直轨道、25/50/75% 刻度和终点标记全部去掉，换成 HeroUI 的圆角进度条（pill track）。组件从 `ResetRail.vue` 更名为 `QuotaProgress.vue`。
- **状态解释**：紧凑面板和主窗口都改用 tint 底色的提示条（neutral 灰调、warning/critical 换成对应语义色），不再是紧凑面板一行纯文字。

### 正式撤销的反目标条款

`设计方向与状态规范.md` 第 2 节原有两条反目标与本决策直接冲突，正式撤销：

- ~~不做传统 SaaS Dashboard 卡片墙~~ —— HeroUI 的阴影卡片语言本质上就是这一类。
- ~~不使用……发光状态点~~ —— 保留其余表述（不使用渐变标题、彩色 Icon Tile、玻璃堆叠、徽标堆叠），仅这一项撤销。

其余反目标条款（暖米色衬线模板、新闻排版、终端黑底霓虹、大号百分比遮蔽重置时间、动态重新排序）继续有效，与 HeroUI 方向不冲突。

### 关于"扫描效率优先于视觉表演"

第 1 节原有的 `Operate` 界面哲学不再作为形状/阴影/颜色克制的直接推论——HeroUI 本身就带有更多视觉表现。产品所有者知情并接受这个取舍：额度信息的阅读路径（剩余多少 + 何时重置同一行、失败保留旧值、三个状态维度独立可辨）继续保留，但不再用它反过来限制视觉语言必须克制。

## 理由

- 三轮设计探索（shadcn、Trace Rail 折衷、HeroUI）已经比对过，HeroUI 是产品所有者明确选定的结果，不是未经验证的猜测。
- 折衷方案已经被验证效果不佳；继续在两者之间找平衡不会产生更好的结果，直接采用一套完整、内部自洽的语言风险更低。
- HeroUI 的 token 结构（背景/表面/文字/边框/语义色分层）与现有 `tokens.css` 的变量命名天然兼容，只需替换取值，不需要重新设计变量结构，改动可控。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 保留 Reset Rail | 产品所有者已明确否决，认为不如 HeroUI 好看 |
| Trace Rail 折衷方向（shadcn 圆角 + HeroUI 部分细节） | 已实际做出稿子并被否决："都不好看" |
| 只改色值，保留直轨道形状 | 产品所有者要求"完完整整完完全全"贴合 HeroUI，不是局部混搭 |

## 后果

- `docs/设计方向与状态规范.md` 第 1、2、3、3.4、5.2、6、7.2、9、12 节需要同步改写。
- `DESIGN.md`（英文镜像）需要同步改写。
- `src/styles/tokens.css` 色值、圆角、阴影 token 全部替换；`--rail-height`、`--rail-radius`、`--rail-tick` 三个 Reset Rail 专属几何 token 删除。
- `src/components/ResetRail.vue` 更名为 `QuotaProgress.vue`（`git mv` 保留历史），内部实现从直轨道换成圆角进度条；`ProviderLane.vue` 的引用同步更新，并移除左侧色条（spine）。
- `src/components/StatusExplanation.vue` 两个变体都换成 tint 底色提示条。
- 状态语义、三维契约、`src/lib/status.ts` 的 `RailTreatment` 类型名和字段名未改动——这是纯视觉层替换，不是状态模型变更，符合 [ADR-0009](ADR-0009-合成数据下沉Rust并提前使用正式契约.md) 的分层原则。
- `RailTreatment` 类型名虽然仍带"Rail"字样，但它描述的是数据处理方式（filled/faded/loading/empty），不是轨道形状，本次不改名，避免无关的类型重命名扩大改动范围。
- 第 8 阶段遗留的"两个平台紧凑面板是否自然出现"等验证重点不受影响，仍需实机复核；本次改动不改变桌面壳结构、窗口尺寸或交互流程。

## 复审条件

- 若后续实机验证发现阴影在 Windows WebView2 或低对比度显示器下不可靠（HeroUI 的层级高度依赖阴影可见度），需要补充描边兜底方案，参照本 ADR 采用的"浅色不描边、深色补描边"模式，不需要整体推翻本决策。
- 若产品所有者后续认为 HeroUI 风格的语义色使用频率造成状态可信度下降，重新评估第 3.3 节使用规则，而不是自动退回 Reset Rail。
