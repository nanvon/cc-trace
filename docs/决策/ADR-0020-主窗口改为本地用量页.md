# ADR-0020：主窗口改为本地用量页，不再显示额度

- 状态：已确认
- 日期：2026-07-30
- 最近修订：2026-08-08（额度历史 Timeline 作为主窗口第二个视图，见第 8 节；主用量页结构不变）
- 相关文档：[信息架构与核心流程](../信息架构与核心流程.md)、[产品范围](../产品范围.md)、[数据存储与用量索引](../数据存储与用量索引.md)、[文案与国际化](../文案与国际化.md)、[设计方向与状态规范](../设计方向与状态规范.md)
- 评审草图：[`prototypes/visual-refresh/`](../../prototypes/visual-refresh/README.md)（2026-08-03 起为视觉 + 导航形态唯一评审参考，含用量页、数据源切换响应与设置页）
- 对照实现：Swift 版 cc-bar 的 Statistics Tab，见 [cc-bar-reference/02](../cc-bar-reference/02-页面窗口与交互地图.md) 第「主窗口」节

## 背景

产品所有者 2026-07-30 指出：主窗口再把 Codex、Claude Code 的额度显示一遍不对，紧凑面板已经有了。

诊断确认这不是观感问题，而是**当前实现确实是同一个东西换了尺寸**：`src/views/MainView.vue` 与 `src/views/CompactView.vue` 使用同一组 `OverallSignal` + `ProviderLane`，差别只有 `variant` 从 `compact` 换成 `full`。

按 [信息架构与核心流程](../信息架构与核心流程.md) 原 §6.2，主窗口额度总览相对紧凑面板的真实增量只有两块：

1. 异常的完整解释与恢复建议（紧凑面板只给短说明）；
2. 全部专项额度列表。

两块都是**条件性**的——两个 Provider 都正常时，这个页面没有任何紧凑面板没有的信息。

同时，[ADR-0018](ADR-0018-用量数据用SQLite与JSON分域.md) 落地的 `usage.db`（`usage_entries`、`conversations`、`quota_events`）与七个 Rust command，**前端只有紧凑面板的今日／本周费用一个消费方**。首版最大的已实现能力没有界面。

## 决策

### 1. 三个表面按「时间尺度」分工，不按「详细程度」

| 表面 | 回答的问题 | 时间 | 数据源 |
|---|---|---|---|
| 系统区域 + 紧凑面板 | 现在额度紧不紧 | 此刻 | `quota-cache.json` 当前快照 |
| 主窗口 | 我到底是怎么用掉的 | 过去一段时间 | `usage.db` 历史聚合 |
| 主窗口设置视图 | 应用应如何运行 | — | `settings.json` |

按「详细程度」分工必然产生重复，因为详细程度是连续量，没有天然切割线。按「时间尺度」分工时，两个表面的数据源和查询形态本身就不同，结构上不会重叠。

### 2. 主窗口不显示额度

主窗口不显示剩余百分比、重置时间、额度状态点或任何额度读数。它是纯粹的本地用量页。

设置仍是主窗口内的二级视图，[ADR-0011](ADR-0011-设置并入主窗口.md) 不受影响。

### 3. 页面结构：筛选 → 总览／Provider → 时间 → 模型

从上到下四段，纵向单列，不用 Tab，不用侧边栏：

1. **筛选行**：日期快捷八档（今天｜昨天｜本周｜本月｜本年｜7 天｜30 天｜全部）+ 日期范围选择器。选自定义范围时八档一起取消选中。
2. **总览／按 Provider**：总览作为按 Provider 区域左侧的小卡片，两行分别显示**总 Token**与**总花费**；右侧是 Codex 与 Claude Code **左右并排**，各自显示自己的花费、总 Token、输入、输出、缓存命中、缓存写入，以及带轨道的缓存命中率。总览卡不显示输入／输出／缓存维度。
4. **每日花费**：按 Provider 堆叠的日柱图。
5. **按模型**：一套表头 + 两个 Provider 分组的表格。

不设独立的 `[全部｜Codex｜Claude]` 筛选器——两个 Provider 已经并排铺开，再加筛选器就是两套机制表达同一件事。

快捷日期档位与右侧日期范围选择器使用同一份日期状态：选择快捷档位会回填对应的起止日期，手动选择日期范围时若恰好命中某个快捷档位则重新选中该档位，否则保持自定义状态。选择器只处理日期；查询使用本地起始日 `00:00:00` 到结束日次日 `00:00:00` 的半开区间，实际覆盖结束日整天。单日范围的每日图表额外向前展示 14 个本地日历日，所选范围高亮，页面总量与 Provider／模型统计仍严格按原始范围计算。

### 4. 模型表分组，但表头与排序共用

一套 `<thead>`，每个 Provider 一个 `<tbody>`。

- 点击表头时**两组同时按该列排序，分组边界固定**，Codex 组永远在 Claude 组上方。排序若能跨组重排，分组就失去意义；两组各排各的则一次点击产生两种顺序。
- 分组行显示该 Provider 的**小计**，不是只有一个名字：分组小计相加等于底部合计，列可以纵向对账。
- 分组行与合计行不参与排序，钉在各自位置。小计跟着数据行被排走会切断对账关系。
- 行内不再重复 Provider 圆点，圆点只在分组行上。

### 5. 颜色：品牌识别用色相，状态和结构各自克制

- **Provider 是分类维度**（无序），使用品牌识别区分：Codex 对齐 cc-bar 的石墨灰，浅色 `#6c6c70` / 深色 `#98989d`；Claude 采用橙色，`--cat-claude` 浅色 `#d97757` / 深色 `#f0a080`。Codex 的灰色在两种外观下保持同一色系，避免把 Provider 颜色误读成状态色。
- 品牌色不参与可用性、风险、额度余量或交互状态判断；即使个别色相接近状态色，也只能通过 Provider 文案和固定位置识别，不能单靠颜色传达状态。
- **彩色只出现在趋势图、Provider 卡片标识与表格分组圆点**，其余全为中性色。整页视觉落点唯一。
- Token 维度若需要分段表达，用**单色相明度阶**而不是多色相：四种 Token 是有序量（从便宜到贵），彩虹配色既丢掉顺序又与状态色抢语义。

`--cat-*` 是本 ADR 新增的**分类色**类别，与既有的状态基调（`src/lib/status.ts`）、额度余量分档（`src/lib/quotaTone.ts`）是三个互不相干的着色维度。

### 6. Token 数量在界面上显示为整数

中文使用万／亿，英文使用 `K` / `M` / `B`，紧凑数值四舍五入为整数，不显示小数位；完整整数保留在 `title` 与无障碍文本中。数值用 `tabular-nums` 与主字号，单位字符小一号并弱化。格式规则由 [文案与国际化](../文案与国际化.md) §3.2 拥有。

### 7. 技术选型

| 用途 | 选择 | 理由 |
|---|---|---|
| 图表 | `echarts` + `vue-echarts` | 桌面应用本地加载，体积不是首要约束；堆叠柱、tooltip、图例交互开箱即用 |
| 日期范围 | `VCalendar 3.1.2` 的 `VDatePicker` | 只引入日期范围所需的轻量日历能力；直接使用官方 `range` model 与 Range Inputs Slot 完成输入框、弹层起止日期选择、键盘导航、本地化与今日上限，页面只做查询所需的日期边界适配 |
| 表格 | **不引库** | 单页 6～15 行加一个 `computed` 排序，TanStack Table 是负收益 |
| 容器尺寸 | `@vueuse/core` 的 `useResizeObserver` | ECharts 容器尺寸变化必须手动 `resize()` |
| 数字格式 | 原生 `Intl` | 不引额外依赖 |

不引入 Element Plus、Naive UI 或 PrimeVue：为一个日期组件引入整套 UI 库会与 [ADR-0012](ADR-0012-视觉方向改为HeroUI风格.md) 的手写 HeroUI 风格组件正面冲突。日期组件只使用 `VCalendar`，并通过 `@popperjs/core` 定位弹层。

ECharts 配置是 JS 对象，读不到 CSS 变量。需要一处 `src/lib/chartTheme.ts` 从 `tokens.css` 读取色值构建 theme，并在浅色／深色切换时重建。这是必付成本，不是可选项。

| [产品范围](../产品范围.md) 后续版本评估 | 「复杂日期范围、自定义筛选与数据导出」不进首版 | 日期范围选择器进首版；自定义筛选与数据导出仍不进 |

## 理由

- **重复是结构性的，不是实现没做完。** 两个表面用同一组组件、同一份 `quota` store，差别只有 `variant`。继续沿原路线做下去，主窗口只会变成「更大的紧凑面板」。
- **已实现的能力没有界面是更大的浪费。** `usage.db` 三张表、七个 command、脱敏 Fixture 与定向测试都已落地，前端只消费了一个金额。
- **不算扩范围。** [产品范围](../产品范围.md) 已把「按时间、Provider、模型、速度聚合的用量查询」写进首版必须，本 ADR 只是给它界面。
- **日期范围选择器比固定档位更省。** 它替代的是「为了不做区间而设计更多固定档」的复杂度；快捷档位与 `VDatePicker` 共用同一份半开区间状态，不是两套查询机制。VCalendar 的单面板范围选择也避免了两个原生日期控件之间来回校正。
- **单日图表需要上下文。** 今天只有一根柱时，用户无法判断它是低用量还是筛选窗口太窄；沿用 cc-bar 的近 14 日上下文，在不改变总量口径的前提下提供趋势参照。
- **并排比堆叠更适合两个 Provider。** 这一页的核心问题是「哪个更烧钱」，左右并排能一眼横扫；上下堆叠要靠记忆比较。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 保留额度总览，再加一个用量视图，顶部分段切换 | 就是 cc-bar 的 Statistics／Settings 结构，额度页与紧凑面板的重复原样保留 |
| 单页纵向滚动，额度摘要在最上，用量在下 | 模型表与后续 Conversations 需要分页，与长页滚动互相干扰 |
| 主窗口保留一条额度状态带作为上下文 | 产品所有者明确否决。它确实能承接异常解释，但会把「主窗口不看额度」这条清晰的分工重新模糊化 |
| 时间轴用拖拽刷选（brush）代替日期选择器 | 产品所有者判断交互成本高、难以命中。八档快捷 + 范围选择器达成同样的区间能力 |
| Token 六维全部画进图表与构成条 | 每日构成基本恒定，柱内比例几乎不变，读不出信息；且推理输出是 `output_tokens` 子集，进不了百分百堆叠 |
| 费用也按 Token 类型拆分展示 | 产品所有者明确要求价格只到 Provider 粒度 |
| 引入 Element Plus／Naive UI 取用其 DatePicker 与 Table | 与手写 HeroUI 风格组件冲突，且为两个组件引入整套体系 |

## 后果

- `src/views/MainView.vue` 整体重写；`OverallSignal`、`ProviderLane`、`QuotaProgress` 的 `variant="full"` 分支在主窗口不再有使用者，需要确认是否还有其他调用点再决定删减。
- 新增 `src/lib/chartTheme.ts`（ECharts 主题与 CSS 变量桥接）。
- 新增依赖：`echarts`、`vue-echarts`、`@vueuse/core`、`v-calendar`、`@popperjs/core`。日期范围直接由 `VDatePicker` 提供，查询仍接收原来的日期边界区间。
- `src/styles/tokens.css` 新增 `--cat-codex`、`--cat-claude` 及其浅底变体，并同步 [设计方向与状态规范](../设计方向与状态规范.md) §3.4 映射表。**两处必须同时修改。**
- `usage_get_summary` 已复核现有契约：Rust 已支持按日、Provider、模型和速度分组，并返回缓存命中率所需的分项；前端通过按 Provider 拆分的日／模型查询组合出页面数据。
- i18n 新增 `main.*` 下的用量页文案与 `a11y.*` 下的表格排序说明，中英文同时提交。
- ADR 定稿时只有评审草图，草图是静态 HTML，不连数据、不含交互；2026-08-01 已完成首版 Vue
  页面与本地摘要接入，但尚未进行浏览器、实机或双平台验证。

## 未解决问题

### 异常解释的落脚点

主窗口不再显示额度后，`no_credentials`、`unsupported`、`offline`、`rate_limited`、`error` 的**完整解释与恢复建议没有归宿**。

[文案与国际化](../文案与国际化.md) §4 目前写着「紧凑面板用一行短说明；主窗口用标题／影响／下一步三级结构」，该分工已随本 ADR 失效。

> 待确认：倾向让紧凑面板的异常 Provider 可展开——正常时保持现有紧凑形态，出错时该条 `ProviderLane` 长出详情区。若不解决，用户在任何表面都拿不到「影响」与「下一步」，[产品范围](../产品范围.md) 首版完成标准里的「加载、成功、无凭据、离线、旧快照、刷新受限和错误状态完整」将不成立。

### 缓存命中率的分母

已确定采用 [数据存储与用量索引](../数据存储与用量索引.md) §2.1.1 的标准化 `input_tokens`，
即 `缓存命中 ÷ (输入 + 缓存命中 + 缓存写入)`。Provider 卡、模型行、Provider 小计与总计统一
使用这一口径；输入为 `0` 时显示 `—`。

### 主窗口的 `⌘R`

> 待确认：原规范里 `⌘R`／`Ctrl+R` 在主窗口刷新额度。主窗口不再显示额度后，它应当改为触发一次增量扫描、保持刷新额度、还是在主窗口不绑定。

## 8. 2026-08-08 修订：额度历史 Timeline 作为第二个视图

产品所有者在批量开发任务中明确要求实现「额度历史 Timeline 界面」（对应 cc-bar F-18），这
推翻了本 ADR 第 2 节「主窗口不显示任何额度读数」的部分边界。本修订按「推翻要显式」记录结论：

- **主用量页本身仍不显示任何额度读数**：第 2 节对主用量页的约束不变，只对新增的 Timeline 视图开口。
- Timeline 是主窗口的**第二个视图**（子路由 `timeline`），不是用量页的底部追加；入口是用量页顶部的
  独立按钮（与「设置」并列），不从用量页底部加卡片。这符合本 ADR「复审条件」对第二视图的约定——
  不得直接追加到本页底部。
- Timeline 展示的是**历史**额度事件（`quota_events` 中整数剩余值变化点），不是当前快照读数；它
  不订阅额度事件，只读一次查询。语义上是「额度过去怎么变化的」，与用量页「过去怎么用掉的」同属
  历史维度，不与紧凑面板的「现在紧不紧」重叠。
- 每个 Provider 只展示其**活动序列**（最新事件点所属的身份与窗口），旧身份／旧窗口序列不展示，
  对应 cc-bar F-18 的「主账号镜像去重」。首版无导入账号，镜像去重只到序列级。
- Conversations 界面按同批开发任务一并进入首版（参考 cc-bar F-17）：列表＋全生命周期详情的
  独立视图，子路由 `conversations`／`conversations/:key`，入口与 Timeline 相同。契约扩展：
  `UsageConversationQuery` 增加 `project` 精确筛选与 `sort`（Recent／Tokens／Cost），新增
  `usage_get_conversation_breakdown` 返回模型／速度拆分行。
- 导航形态仍未采用 `prototypes/visual-refresh/` 的分组侧边栏（仍为首版不实现）；是否升级为侧边栏
  由后续界面数量一起决策。
- `quota_events` 的查询契约此前并不存在（「Rust 契约已就绪」不成立），本次一并新增
  `usage_get_quota_history` command 与 `QuotaHistory` DTO。

## 复审条件

- 若实机确认 ECharts 打包后体积或首次渲染明显拖慢主窗口，先尝试按需引入收敛，再考虑换 Chart.js；不因此回退到手写 SVG。
