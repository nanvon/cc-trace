# ADR-0015：第 12 阶段先于桌面壳实机验证启动

- 状态：已确认
- 日期：2026-07-27
- 相关文档：[执行清单](../Tauri桌面端重新开发执行清单.md)、[桌面壳验证记录](../桌面壳验证记录.md)、`CLAUDE.md` 第 4 节门禁

## 背景

`CLAUDE.md` 与 [执行清单](../Tauri桌面端重新开发执行清单.md) 都规定「macOS／Windows 桌面壳未经实机验证，不开始 Provider 最小闭环」。第 11 阶段当前状态是：设置同窗改造后的自动化检查已于 2026-07-26 在 macOS 主机通过，[桌面壳验证记录](../桌面壳验证记录.md) 的 18 项实机走查清单 macOS 需重跑、Windows 从未跑过（没有 Windows 主机）。

2026-07-26 已经有过一次有限例外：产品所有者允许提前实现 Codex 与 Claude Code 的**离线**响应解析，该例外明确不授权读取凭据、发起网络请求或接入缓存。

2026-07-27 产品所有者在知悉「macOS 实机走查未重跑、Windows 从未验证」的前提下，明确要求开始第 12 阶段。

## 决策

第 12 阶段正式启动，不等待第 11 阶段实机走查完成。具体边界：

- 允许：凭据发现（含 [ADR-0013](ADR-0013-macOS读取ClaudeCode钥匙串凭据.md) 的 Keychain 来源）、真实网络请求、token 刷新与回写（[ADR-0014](ADR-0014-token刷新结果回写外部凭据.md)）、`quota-cache.json`、身份变化处理、真实 Provider 接入 `AppCore`。
- 不允许：把桌面壳的实机走查项标记为已通过。第 11 阶段的 18 项走查清单与「尚未完成」三项审计仍然有效，状态保持「进行中」。
- 不允许：把 Windows 上的任何行为写成已验证。Windows 侧的凭据发现、Keychain 缺席、透明窗口表现全部保持「未验证」。
- 第 12 阶段清单最后一项「在 macOS、Windows 验证相同闭环」在获得 Windows 主机前无法勾选，本决策不豁免它。

第 12 阶段与第 11 阶段的剩余实机验证并行推进；两者的验证结果分别记录，不互相顶替。

## 理由

- 门禁的目的是避免「桌面壳结构还会大改时就把业务逻辑铺开」。当前桌面壳的窗口拓扑、三维契约、调度与设置持久化都已收敛并通过自动化检查，[ADR-0009](ADR-0009-合成数据下沉Rust并提前使用正式契约.md) 保证接入真实 Provider 只替换 `providers/` 内部实现，不改契约、调度、命令与前端。返工风险主要落在 Provider 模块内部，而不是整个应用结构。
- Windows 实机验证在可预见的时间内无法完成（没有主机）。把第 12 阶段无限期挂在这个门禁后面，等于让首版停摆。
- 提前接入真实 Provider 会暴露凭据来源、token 刷新与响应字段的真实形态，这些正是 [额度领域模型](../额度领域模型.md) 第 6 节「待复核清单」需要的输入；晚做不会让它们更便宜。
- 这是产品所有者在知情前提下的决定，不是绕过评审的技术判断。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 先跑完 macOS 实机走查再开始 | 产品所有者已选择并行推进；走查本身不阻碍 Provider 模块内部实现 |
| 等到有 Windows 主机再开始 | 时间不可控，首版停摆 |
| 只做不出网的部分 | 2026-07-26 的例外已经用尽这个空间，剩余工作全部需要真实网络与凭据 |

## 后果

- 第 11 与第 12 阶段同时处于「进行中」，执行清单的阶段状态总表与 `CLAUDE.md` 第 4 节需要同步。
- 若实机走查发现桌面壳需要结构性改动，第 12 阶段已完成的部分可能需要重新验证。风险由 [ADR-0009](ADR-0009-合成数据下沉Rust并提前使用正式契约.md) 的分层边界控制，接受该风险。
- 真实 Provider 接入后，第 11 阶段「验证 Vue 层不能取得秘密」这一项从「需要 Provider 接入后验证」变为可立即验证，应在本阶段一并完成。
- 双平台验收（第 16 阶段）仍然要求 Windows 实机，本决策不改变该要求。

## 复审条件

- 若 macOS 实机走查暴露出需要改动窗口拓扑或状态契约的问题，暂停第 12 阶段剩余工作，先修桌面壳。
- 若 Windows 主机在第 13 阶段前到位，优先补跑第 11 阶段 Windows 走查，再继续首版实现。
