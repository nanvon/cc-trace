# ADR-0032：额度主体与多账号

- 状态：已确认
- 日期：2026-10-01
- 相关文档：[ADR-0005](ADR-0005-状态使用三维模型.md)、[ADR-0017](ADR-0017-系统区域显示额度数字与余量分档.md)、[ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md)、[额度领域模型](../额度领域模型.md)、[状态与错误模型](../状态与错误模型.md)

## 背景

cc-bar v1.1.1 的 Codex 支持导入多个副账号：用户在设置里粘贴一份 `auth.json`，该账号与当前登录账号在紧凑面板、悬浮窗与额度历史里并排展示，各自独立刷新、独立退避、独立失败。删除某个导入账号不影响其余账号。

本仓库此前的契约以 `ProviderId` 为键：`AppCore` 的 `runtimes`、`providers` 两张表是 `BTreeMap<ProviderId, _>`，`quota-cache.json` 每个 Provider 一条，`quota://refresh-state` 事件只带 `provider`。一个 Provider 只有一份快照，无法表达「同一个 Provider 的两个账号同时存在，其中一个失败另一个正常」。

## 决策

### 1. 展示与调度单位改为「额度主体」

- 新增契约 `QuotaSubject { subjectId, provider, kind, label, orderIndex }`。
- `subjectId` 是缓存、退避、刷新事件与历史序列的键：主账号用 Provider 短名（`codex`、`claude`、`antigravity`、`cursor`、`commandCode`），导入账号用 `codex:imported:<n>`。
- `ProviderSnapshot` 增加 `subjectId`、`kind`（`primary` / `imported`）、`label`（导入账号的展示名；主账号为 `null`，账号在 `identity` 里）。
- `ProviderId` 降为归属与展示顺序的表达：`ProviderId::ORDER` 固定为 Codex → Claude → Antigravity → Cursor → Command Code。
- 列表顺序由 `AppCore::ordered_subjects()` 一处产出：Provider 顺序 → 主账号在前 → 导入账号按用户顺序。界面、托盘、缓存都不再各自排序。

### 2. 命令与事件

- `quota_refresh` 的参数由 `provider` 改为 `subject_id`；省略时刷新全部主体。
- `quota://refresh-state` 载荷增加 `subjectId`。
- 关闭额度轮询的服务（设置里 `services.<provider>.quota = false`）不发请求，界面继续展示上一次快照。

### 3. 缓存

`quota-cache.json` 结构版本升到 v2，每条记录带 `subjectId` / `kind` / `label`。旧版本缓存直接弃用并重新获取：缓存是可重建的派生数据，不为它保留迁移代码（与 [ADR-0018](ADR-0018-用量数据用SQLite与JSON分域.md) 的数据域划分一致）。

## 理由

- 三个状态维度（`refresh` / `freshness` / `availability`）是**每个账号独立**的事实：一个导入账号 401 不该把主账号标成错误。以 `ProviderId` 为键时这个事实无处存放。
- 托盘与悬浮窗要按账号逐行展示，缓存要能只重取一个账号；把账号做成 Provider 的子维度比把账号摊平成一堆伪 Provider 更少歧义：`ProviderId` 的语义（服务）保持不变，界面上「服务分组 + 账号条目」的层级可以直接从契约推出。
- 导入账号的数量与顺序由用户决定，属于运行时可变状态；把它放进契约而不是散在界面状态里，可以让 Rust 侧一次算清顺序。

## 替代方案

1. **把每个导入账号当成一个新 `ProviderId`**。被否决：`ProviderId` 会随用户操作增长，服务状态链、价格表、颜色、i18n 全部要跟着长；而且「Codex 有几个账号」变成了类型层面的问题。
2. **在 `ProviderSnapshot` 内嵌 `accounts[]`**。被否决：三个状态维度、退避时间、身份都会变成二级结构，调度与缓存的键仍要另建一套，等于把复杂度推到更深处而不是消掉。
3. **不做多账号**。违背 [ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md) 的功能基准。

## 后果

- `quota-cache.json` 升到 v2；`AppCore` 的 `runtimes` / `providers` 改为以 `subjectId` 为键，`ProviderRuntime::new` 接收 `QuotaSubject`。
- 前端 `useQuotaStore.ordered`、缓存与事件处理改为以 `subjectId` 匹配；紧凑面板与悬浮窗按主体逐个渲染。
- 导入账号的凭据存储与生命周期（增删、排序、凭据落盘位置）单独决策，见批次 2 的凭据 ADR。

## 复审条件

- 出现第二个支持多账号的服务时（当前的账号存储与排序规则假定导入只发生在 Codex 上）。
- 额度历史需要跨账号对账时，重新评估 `subjectId` 是否要携带身份哈希。
