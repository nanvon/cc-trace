# ADR-0036：诊断导出与更新检查进入首版

- 状态：已实现（2026-10-01，批次 8），Windows 与 macOS 实机均未验证
- 日期：2026-10-01
- 相关文档：[ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md)、[日志与诊断](../日志与诊断.md)、[产品范围](../产品范围.md)

## 背景

[日志与诊断](../日志与诊断.md) 原先写明「不提供日志导出按钮」「debug 不提供界面开关」，[产品范围](../产品范围.md) 把高级诊断列为后续评估项。cc-bar v1.1.1 有诊断包导出、详细日志开关与检查更新，[ADR-0031](ADR-0031-功能基准改为cc-bar-v1.1.1.md) 已把功能基准改为 cc-bar 的实际行为，上述边界不再成立。

## 决策

1. **详细日志开关**：设置里的 `verboseLogging` 控制 `debug` 级别是否写入。环境变量开启 `debug` 的方式保留。
2. **诊断包导出**：Rust 侧生成单个脱敏 `.txt`，由系统保存对话框选择位置。内容为版本、平台、设置摘要（不含悬浮窗坐标）、各额度主体的三维状态与错误类型和时间戳、导入账号数量、脱敏后的日志尾部 400 行。不含路径、账号与任何秘密。前端没有 dialog 或 fs 权限，返回值不带保存路径。
3. **脱敏规则**：在写入诊断包前统一处理邮箱、JWT、常见密钥前缀、`Bearer` 值、`key=value` 中的秘密与路径、Windows 与 Unix 绝对路径、长十六进制与长随机串。「秘密永不落盘」的原则不变。
4. **检查更新**：请求 GitHub Releases 的 latest 接口，比较版本，结果为已是最新／有新版本／失败／被限流。只提示并打开固定的 releases 页面，不自动下载或安装；前端不能传入任意 URL。启动时是否检查由设置 `checkUpdatesOnLaunch` 控制。
5. 日志文件放在配置目录的 `logs/` 下，单文件 1 MB，保留 3 个。

## 与 cc-bar 的差异

- 诊断包是单个 `.txt`，cc-bar 是 zip。没有引入 zip 依赖，内容等价。
- 业务事件（刷新、退避、身份变化）尚未逐点接入日志，目前只有启动、更新检查、诊断导出与详细日志切换。

## 后果

- [日志与诊断](../日志与诊断.md) 第 1、3 节按本 ADR 更新。
- 新增依赖 `tauri-plugin-dialog`。

## 复审条件

- Windows 或 macOS 实机发现保存对话框、打开目录或打开链接的行为不等价时。
- 需要 zip 诊断包或业务事件日志全覆盖时。
