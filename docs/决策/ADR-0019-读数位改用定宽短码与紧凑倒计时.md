# ADR-0019：读数位改用定宽短码与紧凑倒计时

- 状态：已确认
- 日期：2026-07-30
- 相关文档：[文案与国际化](../文案与国际化.md)、[设计方向与状态规范](../设计方向与状态规范.md)、`src/lib/format.ts`、`src/lib/labels.ts`、`src/components/QuotaProgress.vue`
- 对照实现：Swift 版 cc-bar 的 Menu Bar popover（`../cc-bar/MenuBar/PopoverRootView.swift`、`Core/L10n.swift`）

## 背景

产品所有者 2026-07-30 拿 cc-bar 的 popover 截图对照 CC Trace 的紧凑面板，指出两件事：

1. **显示不下。** 邮箱和重置时间会被省略或挤压，而 cc-bar 同样 380px 宽却处处放得下。
2. **术语冗长。** cc-bar 用 `5HOUR`、`WEEKLY`、`6d2h`、`1h42m`、`3d22h`，CC Trace 用「5 小时窗口」「14:30 重置」「上次成功刷新 3 分钟前」。产品所有者明确要求术语与时间格式按截图那样。

诊断确认这不只是观感偏好，而是当前实现的**结构性缺陷**：

- `QuotaProgress.vue` 的 `primary` 排布把大百分比、窗口名、重置时间放进同一 flex 行，而窗口名在该排布下既没有 `overflow: hidden` 也没有 `min-inline-size: 0`。中文下 `Opus 4.1 每周窗口` + `7月31日 14:30 重置` 已接近边界，英文下必定溢出，被 `.panel` 的 `overflow: hidden` 裁掉。
- `.signal__meta` 既无 `nowrap` 也无省略，而头部右侧图标按钮组 `flex-shrink: 0`：英文副标题会让头部换行，再经 `ResizeObserver` 把窗口顶高。
- `.lane__account` 的 `max-inline-size: 42%` 在 380px 下只有约 140px，常见长度的邮箱刚好卡在临界。

根因是**在固定宽度容器里放了会变宽的读数**：`6d2h` 最长 6 个字符（`23h59m`），`7月31日 14:30 重置` 在 4 到 11 个字符之间浮动。变宽读数下没有能算得准的布局。

## 决策

### 1. 读数位的窗口名改为语言中立的大写短码

`5HOUR`、`WEEKLY`、`ALL`、模型名大写（`OPUS`）；无法识别时 `CURRENT` / `MODEL`。唯一实现是 `src/lib/labels.ts` 的 `windowCode()`。

Claude Code 的周窗口读作 `ALL`（全模型合计），Codex 的周窗口读作 `WEEKLY`，与 cc-bar 一致。

短码**不进 i18n**：两种界面语言下都是这一套大写拉丁短码。完整窗口名由 `windowLabel()` 继续提供给进度条的无障碍名称与短码的 `title`，因此短码不是这个信息的唯一载体；短码本身对辅助技术 `aria-hidden`，避免读出无意义的「5HOUR」。

### 2. 重置时间的主显示改为紧凑倒计时

`<1m`、`43m`、`4h37m`、`3d22h`，无空格、无单位词，只保留两个最高量级，最长 6 个字符。实现是 `src/lib/format.ts` 的 `compactDuration()`，规则与 cc-bar 的 `compactRelativeReset` 相同。

绝对本地时刻改由 `title` 与 `aria-label` 承担（`quota.resetsAt` + `formatAbsolute`），[文案与国际化](../文案与国际化.md) 第 3.2 节「相对时间必须同时提供绝对值」仍然成立。

`resetsAt` 缺失时读数位显示 `—`，旁边的「重置」标签仍在，完整说明（「重置时间未知」）由 `title` 与 `aria-label` 给出。

### 3. 头部副标题改为紧凑形态

`1m 前已刷新` / `refreshed 1m ago`；不足一分钟说「刚刚已刷新」，从未成功过说「尚未成功刷新」。

`quota.lastSuccess` 换成 `quota.refreshedAgo` 与 `quota.refreshedJustNow`。

### 4. 倒计时需要每分钟推进一次

绝对时钟不需要重算，倒计时需要。新增 `src/lib/useNow.ts`：全应用共用一个 60 秒计时器，最后一个使用者离开时停表，页面重新可见时立刻校准。没有它，读数会冻在渲染那一刻，要等下一次额度刷新（15～60 分钟）才跳一次。

精度默认**停在分钟**：[文案与国际化](../文案与国际化.md) 第 3.2 节「相对时间不做秒级自动跳字」不变；唯一例外是头部副标题「最近成功刷新」在刷新后 1 分钟内秒级跳字，见文末 2026-08-09 修订。

### 5. 主读数排布改为两列

- 左列：大百分比（数字与 `%` 分设字号，`%` 为一半字号并退到 75% 不透明度）在上，窗口短码在下，整列居中。
- 右列：全宽进度条、紧凑倒计时、「重置」标签。

次级额度行改为固定短码列（`3.5rem`），多条次级额度的短码、轨道起点与读数因此竖向对齐。

行尾倒计时右对齐并留出最长分支的宽度，`43m` 与 `23h59m` 之间不推动轨道。

### 6. 身份行去掉 chip，只压缩账号

套餐从带边框的 chip 改为与账号并置的纯文字，分隔符 `·` 由样式提供（语言中立，不需要为它拼接文案）。

`.lane__account` 去掉百分比上限，改为吃满整行剩余宽度；宽度不足时**只有账号收缩**，套餐永远完整——套餐决定额度上限，属于要读的信息；账号只用来确认「是不是我这个号」，截断后仍然认得出来。

### 7. `.numeric` 不再切换字体族

只保留 `font-variant-numeric: tabular-nums`。等宽字体族会让读数比比例字体宽约一成——在 380px 面板里这点余量正好是溢出与否的差别；中英文混排（「1m 前已刷新」）还会因为 CJK 回退而字形错位。

`--font-data` 保留给 `.utility-label`。

## 推翻的既有结论

| 出处 | 原结论 | 现结论 |
|---|---|---|
| [文案与国际化](../文案与国际化.md) §3.1 | 格式化统一使用 `Intl.DateTimeFormat` 与 `Intl.NumberFormat` | 增加紧凑时长这一例外：`Intl` 产不出 `6d2h`，它也刻意语言中立 |
| [文案与国际化](../文案与国际化.md) §3.2 | 重置时刻主显示绝对本地时间，相对时长只作次级补充 | 主显示紧凑倒计时，绝对时刻退到 `title` 与无障碍名称 |
| [文案与国际化](../文案与国际化.md) §3.2 | 窗口长度用产品语言而非秒数（`5 小时窗口`） | 读数位用大写短码；产品语言保留给 `title` 与无障碍名称 |
| [文案与国际化](../文案与国际化.md) §3.2 | 最近成功刷新用相对时间，超过 24 小时改绝对日期 | 改紧凑形态；`formatPast` 保留给提示条里的解释句 |
| [文案与国际化](../文案与国际化.md) §3.2 | 相对时间不做秒级自动跳字（含头部副标题） | 头部副标题「最近成功刷新」在刷新后 1 分钟内秒级跳字；倒计时与其他相对时间仍停在分钟，见 2026-08-09 修订 |
| [设计方向与状态规范](../设计方向与状态规范.md) §7.2 | 主额度读数行是「大百分比、窗口名、重置时间同一行」 | 改两列排布，见第 5 条 |
| [ADR-0012](ADR-0012-视觉方向改为HeroUI风格.md) | 套餐用 HeroUI chip | 改纯文字并置——chip 的边框与内边距在 380px 下吃掉约 45px，正是邮箱被截的原因之一 |

[ADR-0017](ADR-0017-系统区域显示额度数字与余量分档.md) 的**余量四档色、状态点、图标按钮组与系统区域位图不受影响**；被本 ADR 局部推翻的只是它照 Artifact 稿确定的 `primary` 读数行排布。三维状态契约、状态优先级与组合矩阵完全不涉及。

## 理由

- **定宽是第一性的。** 变宽读数在固定宽度容器里没有可预测布局，只能靠省略号和挤压兜底——这正是产品所有者看到的现象。`6d2h` 有 6 字符上界，`tabular-nums` 之后宽度才真正稳定。
- **倒计时回答的是用户真正问的问题。** 「还有多久恢复」比「几点几分恢复」更直接；后者还要求用户自己做减法，并且知道现在几点。
- **短码对目标用户零学习成本。** CC Trace 的用户就是 Codex 与 Claude Code 的使用者，`5HOUR` / `WEEKLY` 是他们在 CLI 里已经见过的说法。
- **信息没有丢，只是换了层级。** 完整窗口名与绝对时刻都还在 `title` 与无障碍名称里，屏幕阅读器拿到的仍是完整句子，不是短码。
- **紧凑不等于把解释也砍掉。** 提示条里的解释句继续用自然语言（「5 分钟前的数据」），`formatPast` 因此保留：定宽读数位与解释性文字是两个信息层级，不是重复实现。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 只补 `min-inline-size: 0` 与省略号，术语不动 | 能止住溢出，但读数会长期处于「随时可能被截」的状态，且产品所有者要的正是术语精简 |
| 保留绝对时钟，只缩短前后缀 | 宽度仍随日期浮动（当天 5 字符、跨天 11 字符），没有解决根因 |
| 中文另给一套短词（`5小时` / `每周` / `全部`） | 保住了 i18n 完整性，但两种语言宽度不同，固定短码列失去意义；产品所有者已选择两种语言共用大写短码 |
| 短码不设 `aria-hidden`，让辅助技术直接读 | 屏幕阅读器会读出「5HOUR」这种无意义的字符串，而进度条的无障碍名称已经有完整窗口名 |
| 用秒级 tick 让倒计时更准 | 面板会每秒重排一次，且分钟以下的精度对「还有多久」没有决策价值。修订后仍成立，只对头部副标题的 1 分钟窗口开例外，见文末 |

## 后果

- `src/lib/format.ts` 新增 `compactDuration` / `compactReset` / `compactAge` / `splitPercent`，删除 `formatResetClock`（被倒计时取代）。`formatPast` 保留给提示条。
- `src/lib/labels.ts` 新增 `windowCode`；`src/lib/useNow.ts` 是新文件。
- `QuotaProgress.vue` 新增 `code` prop（短码），`label` 的用途收窄为 `title` 与无障碍名称。
- i18n 两种语言同步：新增 `quota.resetLabel`、`quota.refreshedAgo`、`quota.refreshedJustNow`；`quota.lastSuccess` 删除；`quota.resetsAt` 保留但用途改为 `title` 与无障碍名称。
- `src/lib/format.test.ts` 与新增的 `src/lib/labels.test.ts` 守住定宽上界（`≤ 6` 字符）与短码分支；上界是这个格式存在的理由，必须有测试。
- **紧凑面板的内容高度变了**，但 `tauri.conf.json` 的初始高度 392 未调整：运行时由 `setCompactHeight` 同步，初始值需要实机量过再定，凭估算改反而会让首帧跳动。列入 [桌面壳验证记录](../桌面壳验证记录.md) 的走查项。
- 本轮只跑过 `vue-tsc --noEmit`、`vitest run` 与 `eslint`，**macOS 与 Windows 实机均未验证**。9pt 级别的小字号在实机上的可读性、深色模式下的短码对比度、以及长模型名在 `3.5rem` 短码列里的截断表现都需要实机复看。

## 复审条件

- 若实机确认 `0.625rem` 的短码在 Retina 上偏小，先上调短码字号，不回退成中文长句。
- 若某个 Provider 的模型名长到 `3.5rem` 列放不下且截断后无法辨认，给该窗口定义专属短码，不加宽固定列——加宽会把进度条挤没。
- 若后续要让用户在倒计时与绝对时刻之间切换（cc-bar 有 `resetTimeDisplay` 设置和 hover 切换），那是 [产品范围](../产品范围.md) 的「基础设置」扩项，需要单独决策。

## 修订（2026-08-09）：头部副标题 1 分钟窗口内秒级跳字

产品所有者确认「刚刚已刷新」这一行在刷新后 1 分钟内应显示秒级读数（`32s 前已刷新`），1 分钟之后保持分钟级。本次修订只推翻了第 4 条「精度停在分钟」里**最近成功刷新副标题**这一处，并收窄了「用秒级 tick 让倒计时更准」这一否决项的适用范围：

- `compactAge` 1 分钟窗口内返回 `32s` 形态，不足 1 秒仍说「刚刚已刷新」（`src/lib/format.ts`）。
- `useNow.ts` 泛化为 `createTicker(stepMs)`，新增秒级通道 `useNowSeconds`；分钟级 `useNow` 行为不变。
- `refreshed()` 在窗口内读秒级时钟、窗口外切回分钟级，因此只有这一行在 1 分钟内每秒重排，倒计时（重置、重试）与提示条全部不受影响（`src/lib/useTimeText.ts`）。
- 秒级只存在于这 1 分钟窗口：窗口一过自动回到分钟级，不长期占用每秒重排。
- 本轮只跑过 esbuild 语法校验与 `format.test.ts`；**macOS 与 Windows 实机均未验证**。
