# ADR-0025：非隐私模式显示完整邮箱

- 状态：已确认
- 日期：2026-08-09
- 相关文档：[产品范围](../产品范围.md)、[技术架构](../技术架构.md)、[额度领域模型](../额度领域模型.md)、[日志与诊断](../日志与诊断.md)、[文案与国际化](../文案与国际化.md)、[桌面壳验证记录](../桌面壳验证记录.md)、`src-tauri/src/providers/credentials/mod.rs`

## 背景

首版沿用「前端只接收脱敏账号信息」的边界：`ProviderIdentity.account_hint` 只携带
`n***@example.com` 形式的脱敏提示，完整邮箱不进入 command 载荷与本地缓存。该结论最初
来自「凭据最小暴露」的保守假设（cc-bar 参考实现的账号展示同样只做提示）。

实机验证与产品决策推翻了这个假设：账号行展示的目的是**确认「是不是我这个号」**
（`ProviderLane.vue` 既有注释），脱敏 hint 在本地单机应用中无法承担这个目的——用户
看不到自己的完整邮箱，无法确认当前展示的是哪个账号。数据在本机、显示在本机，
「完整邮箱进前端」的风险面是本地展示，与「token 进载荷」的风险面（可被截获复用）
不同级。2026-08-09 产品所有者确认：非隐私模式显示完整邮箱，隐私模式行为不变。

## 决策

1. `ProviderIdentity.account_hint` 改为 `ProviderIdentity.account`，携带**完整账号**
   （邮箱或 account id），经 command 载荷与 `quota-cache.json` 传到前端。
2. 隐私模式语义不变（cc-bar F-24 边界）：开启时紧凑入口隐藏账号标识，仅 UI 隐藏、
   不承诺隐私隔离；关闭时显示完整账号。隐藏逻辑仍在 `ProviderLane.vue` 层，契约不感知。
3. 删除 `Secret::hint`——展示脱敏不再有调用者，避免无人使用的脱敏工具演变成第二套展示规则。

## 理由

- **需求来源是产品所有者确认**：非隐私模式显示完整邮箱是明确验收要求，脱敏 hint
  无法满足「确认当前账号」的展示目的。
- **风险面不同级**：完整邮箱只在本机展示链路（command 载荷、本地缓存、渲染进程）
  中流转，不落日志、不进错误文案、不参与身份比较明文。既有「凭据只在 Rust 内存」
  的边界未受影响——邮箱从凭据结构读出后即转为展示数据。
- **隐私模式仍提供显式关闭手段**：需要在公共场合隐藏账号的用户可以开启隐私模式，
  行为与 cc-bar F-24 一致。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 保留脱敏 hint 不动 | 不满足产品要求：无法确认完整账号 |
| 新增 `account` 字段、保留 `account_hint` 双字段 | 前端只有一处消费，双字段制造两套展示真值，违反「只做任务需要的最小改动」 |
| 只改展示、载荷仍传 hint（前端拿不到明文） | 明文不在前端就无法显示，方案不成立 |
| 由前端自行拼接邮箱 | 前端拿不到完整邮箱，同样不成立；且拼装逻辑会变成第二套数据源 |

## 复审条件

- 若后续引入云端同步、崩溃上报或第三方分析，完整邮箱必须重新评估：上述任何一条
  通道都不许携带账号明文，需要时回到脱敏 hint 或本地摘要。
- 若隐私模式需要覆盖主窗口（当前只覆盖紧凑入口），修改 `ProviderLane.vue` 的显示
  条件即可，无需改契约。
