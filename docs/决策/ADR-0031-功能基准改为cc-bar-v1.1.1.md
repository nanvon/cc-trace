# ADR-0031：功能基准改为 cc-bar v1.1.1

- 状态：已确认
- 日期：2026-10-01
- 相关文档：[ADR-0003](ADR-0003-独立应用身份不迁移数据.md)、[ADR-0006](ADR-0006-首版只支持Codex-OAuth凭据.md)、[ADR-0007](ADR-0007-首版不实现CLI兜底与delegated-refresh.md)、[产品范围](../产品范围.md)、[信息架构与核心流程](../信息架构与核心流程.md)、[cc-bar 增量能力迁移评估](../cc-bar增量能力迁移评估.md)

## 背景

本仓库上一次与 cc-bar 对齐是 2026-08-10（[ADR-0029](ADR-0029-主窗口与对话页对齐cc-bar的功能与布局.md)，对照 cc-bar v1.0.12 前后）。cc-bar 主线此后推进到 **v1.1.1**（`63d0f7e`，2026-09-30，tag `v1.1.1`），从 v1.0.12 起有 172 个提交，其中大量是用户可见能力：

- 额度服务从两个扩到五个（新增 Antigravity、Cursor、Command Code），Claude Desktop 成为 Claude Code 的等价凭据来源。
- 本地用量数据源从两个扩到五个（新增 DSH、Cursor 远端计量）；Cursor 用量来自服务端计量，进统计但不进对话页。
- 主窗口从「用量页 + 对话页」扩到四个视图：概览、对话、**项目**、**额度**（周期与时间线合并）。
- 新增桌面悬浮窗（置顶、不抢焦点、可拖动、边缘吸附、位置记忆）。
- 新增周期记录（用满预估、可信度、官方已用比例）、项目身份与未归属口径、隐私模式全覆盖、脱敏诊断包导出、检查 GitHub Release 更新。
- 设置页改为按服务分组的四组开关矩阵（额度／菜单栏／悬浮窗／统计）。

产品所有者 2026-10-01 要求：把 cc-bar v1.1.1 的完整功能与信息架构移植到 Windows，载体是本仓库。

## 决策

### 1. 功能基准

**功能基准是 cc-bar v1.1.1 的实际行为，不是本仓库现有文档记录的产品范围。** 两者冲突时以 cc-bar 为准，并按仓库规则更新 `docs/` 与 ADR。

不变的是**视觉风格**：继续使用 `docs/设计方向与状态规范.md` 与 `DESIGN.md` 的设计语言（贴合式弱化卡片层级、既有 token、既有排版规则），不照搬 SwiftUI。

### 2. 进入首版的能力（推翻既有范围边界）

以下能力从「明确不做」或「后续版本评估」移入首版，推翻 `docs/产品范围.md` 对应条目与 `AGENTS.md` 中与之冲突的阶段门禁：

1. **三个新额度服务**：Antigravity、Cursor、Command Code；推翻 [ADR-0006](ADR-0006-首版只支持Codex-OAuth凭据.md) 「首版只支持 Codex OAuth 凭据」的范围限制（该 ADR 的凭据形态判断本身仍成立，本次只扩大服务集合）。
2. **Codex 多账号导入**（粘贴 `auth.json`）、personal access token 模式、Reset Credits 入口。
3. **Claude Desktop 作为 Claude Code 的等价凭据来源**（文件缺失时回落，不是新增服务）。
4. **本地用量数据源扩到五个**：新增 DSH（多帧 zstd 容器）与 Cursor 远端计量。
5. **项目分析页**；**额度页**（周期记录 + 时间线）；概览页的用量构成四维面板、高消耗对话、粒度日／周／月与范围分档。
6. **桌面悬浮窗**与按服务分组的四组开关矩阵（额度／菜单栏／悬浮窗／统计）。
7. **隐私模式全覆盖**（账号、项目、对话、路径、分支、ID）。
8. **脱敏诊断包导出**与**检查更新**（GitHub Release 静态清单，启动自动 + 手动）。
9. **cc-bar 的粒度与范围模型**：日／周／月粒度，范围分档，单周期图表的上下文扩展。

### 3. 明确不变的两条

1. **托盘形态不变**：Windows 上托盘只能是静态图标 + tooltip，cc-bar 菜单栏的多段百分比标签在 Windows 托盘上物理上做不到，不追求复刻。设置里的「系统区域承载哪个额度窗口」决定 tooltip 写主要额度、周额度还是两者。
2. **不迁移 cc-bar 的数据**：产品所有者 2026-10-01 明确本应用仍处开发阶段，旧数据直接弃用，不写一次性导入器。**故 [ADR-0003](ADR-0003-独立应用身份不迁移数据.md) 继续有效，其状态不变。**

### 4. 平台差异的处理原则

Windows 与 macOS 在凭据存储、文件路径、系统托盘、窗口几何与 DPI、系统事件、时区上不同。每项差异在实现前查官方文档与上游源码，交付说明标注证据来源与证据等级。**Windows 行为在实机验证前一律标注未验证**，按 `docs/桌面壳验证记录.md` 的规则记录平台与日期。

## 理由

- cc-bar 是本项目的功能母本，两者面向同一批用户与同一批数据源。功能基准落后一个 minor 版本会让 Windows 版缺少用户已经在 macOS 上依赖的能力，这不是「首版克制」而是功能缺失。
- 本仓库已经具备承载这些能力的地基：请求级 `usage_entries`、额度历史表、按 Provider 分层的额度契约、服务状态链、价格目录。新增服务的边际成本主要在凭据发现与协议解析，不在数据层重建。
- 反过来，视觉与信息层级是 CC Trace 已经定稿并经过产品所有者逐轮确认的部分，改视觉不会带来功能收益，只会丢掉已有验证。

## 替代方案

1. **只移植「影响大」的子集**（如只加项目页与悬浮窗，不做新服务）。理由不成立：额度服务是本应用的第一功能，缺三个服务等于功能不完整；而项目与悬浮窗单独存在也没有意义。
2. **照搬 SwiftUI 视觉**。被否决：违反「唯一不变的是视觉风格」，且 SwiftUI 的材质与布局语义在 Web 渲染层不能等价表达。
3. **做一个 v1.0.12 → v1.1.1 的增量清单，只补齐增量**。已采用，即本 ADR 第 2 节；但它不是「只做增量」的保守方案，而是完整移植。

## 后果

- `docs/产品范围.md`、`docs/信息架构与核心流程.md`、`docs/设计方向与状态规范.md`、`docs/数据存储与用量索引.md`、`docs/测试策略.md`、`AGENTS.md` 的阶段状态表需要同步重写（批次 10 落地）。
- 数据层需要 schema v7 起的一系列迁移（六源、项目归属、周期表）。
- 契约需要支持多额度主体（见 [ADR-0032](ADR-0032-额度主体与多账号.md)）。
- Windows 侧全部行为在实机验证前标未验证；本地只跑快速校验，Windows 编译由 CI 矩阵（`windows-latest`）验证。

## 复审条件

- cc-bar 再次出现 minor 版本级的能力扩张时。
- Windows 实机验证发现某项能力在 Windows 上无等价实现（例如需要系统级权限或不存在对应数据源）时，该项按「简化或不做」重新评估并更新本节。
