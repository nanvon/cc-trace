# ADR-0002：首版使用单应用结构

- 状态：已确认
- 日期：2026-07-25（补写）
- 相关文档：[技术架构](../技术架构.md)

> 本记录事后补写，理由依据现有文档重建。

## 背景

早期规划草案曾建议 `apps/desktop` + `packages/*` + `crates/*` 的多包结构（见 [archive/草案-跨端重构方案](../archive/草案-跨端重构方案.md) 第 8 节）。首版实际只有一个桌面应用入口。

## 决策

在仓库根目录建立单个桌面应用：`src/` 为 Vue 前端，`src-tauri/` 为 Rust 核心。根目录的 `pnpm-workspace.yaml` 只用于 pnpm 依赖构建许可配置，不声明子包。

只有出现第二个应用入口、可独立发布的共享包，或需要单独测试发布的 Rust 核心时，才拆分 workspace。

## 理由

- 首版只有一个可交付物，多包结构带来的构建配置、版本协调和跨包引用成本没有对应收益。
- 提前拆包会把模块边界固定在还没被验证的猜测上。
- 单应用结构下，Rust 内部仍按 `providers`／`scheduler`／`storage`／`platform`／`contracts` 分模块，边界清晰度不依赖包拆分。

## 替代方案

| 方案 | 不采用的原因 |
|---|---|
| 立刻建 monorepo | 首版无第二个消费者，纯增成本 |
| 把 Rust 核心拆成独立 crate | 尚无独立测试或发布需求 |

## 后果

- 未来引入移动端或 CLI 时需要一次真实的结构迁移。
- `pnpm-workspace.yaml` 存在但不声明子包，容易被误读为 monorepo，已在技术架构中明确说明。

## 复审条件

- 出现第二个应用入口或需要独立发布的共享包。
- Rust 核心需要脱离桌面应用单独测试或发布。
