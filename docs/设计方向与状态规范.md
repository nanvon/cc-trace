# CC Trace 设计方向与状态规范

> 状态：第 7 阶段基线，视觉方向已按 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 改为 HeroUI 风格
> 目标版本：`0.1.x`
> 基线日期：2026-07-27

## 1. 设计方向

CC Trace 采用 **HeroUI 风格**（见 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md)）：

- 阴影驱动层级：卡片静止时即带阴影，不靠色差或粗描边分层。
- 更大的圆角（12–14px）、更饱和且更常出现的语义色；克制不再是唯一的表达方式。
- 两个 Provider 使用稳定的平行信息语法，而不是自由排列的 Dashboard 卡片。
- 每项额度将“剩余多少”和“何时重置”放在同一阅读路径。
- 状态表达同时保留活动、快照新鲜度和失败原因，不把它们压成一个模糊颜色点。
- 品牌双 `C` 用于图标、启动识别和少量几何呼应，不作为页面背景水印反复出现。

首版仍然是高频、简短使用的场景，信息结构（Provider 顺序稳定、剩余额度与重置时间同一阅读路径、失败保留旧值）不因视觉方向改变；改变的是形状、阴影和颜色语言，视觉克制不再是唯一手段。

## 2. 设计反目标

- 不做终端模拟器、代码编辑器皮肤或黑底霓虹科技风。
- 不做暖米色、衬线标题、陶土色强调的模板化组合。
- 不做新闻排版、过度细线和装饰性编号。
- 不使用渐变标题、彩色 Icon Tile、玻璃堆叠或徽标堆叠。
- 不用大号百分比遮蔽重置时间、数据新鲜度和错误原因。
- 不通过动态重新排序制造“风险优先”，避免刷新后内容跳动。

> 原有的“不做 SaaS Dashboard 卡片墙”“不使用发光状态点”两条已被 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 正式撤销，与 HeroUI 方向直接冲突。

### 3.3 使用规则

- `live` 默认使用中性色，仅在刚完成刷新等明确成功反馈中短暂使用绿色。
- `no_credentials` 使用中性说明和可执行建议，不默认标红。
- `stale`、`rate_limited` 使用琥珀色并显示原因。
- `offline` 依据是否有旧快照使用中性或琥珀色，不能只显示灰色圆点。
- `error` 只在真实错误和需要处理的凭据／协议问题中使用红色。
- 色彩不能单独承担状态；必须同时出现状态词、图标或解释。
- 交互色不兼任成功、Provider 品牌色或装饰色。

### 3.4 实现映射

`src/styles/tokens.css` 是色值的唯一实现真值，本文件的语义名与它一一对应：

| 语义名 | CSS 变量 | 落地状态 |
|---|---|---|
| Canvas | `--surface-primary` | 已落地 |
| Surface | `--surface-raised` | 已落地 |
| Ink | `--text-primary` | 已落地 |
| Muted | `--text-secondary` | 已落地 |
| Hairline | `--border-subtle` | 已落地 |
| Track | `--track-background` | 已落地 |
| HeroUI Primary | `--action-primary` | 已落地 |
| Success | `--status-success` | 已落地 |
| Warning | `--status-warning` | 已落地 |
| Low | `--status-low` | 已落地 |
| Danger | `--status-error` | 已落地 |

`Low` 是余量四档里介于 `Warning` 与 `Danger` 之间的一档，HeroUI 官方语义色没有它；取值 `#f3730e`／深色 `#ff8a3d` 由 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md) 采纳。

语义名与变量名的任何新增或改名都要两处同时修改，不允许只改 CSS。

`tokens.css` 另有三组不属于颜色系统、但同样是实现真值的 token：

| 用途 | 变量 |
|---|---|
| 阴影与外壳 | `--radius-shell`（16px，与 `tauri.conf.json` 的 `windowEffects.radius` 必须一致）、`--shadow-panel`（紧凑面板悬浮层）、`--shadow-lane`（Provider lane 静止即带阴影）、`--ring-panel` |
| 圆角 | `--radius-control`（8px，紧凑面板小图标按钮）、`--radius-small`（12px）、`--radius-medium`（14px） |
| 动效 | `--motion-fast`（140ms）、`--motion-base`（200ms）、`--motion-panel`（320ms）、`--ease-out` |

`--rail-height`、`--rail-radius`、`--rail-tick` 三个 Reset Rail 专属几何 token 已随 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 删除；Quota Progress 的圆角进度条尺寸是组件内联值，不再单独对外暴露 token。

外观三态由根元素的 `data-appearance` 驱动：缺失或 `system` 跟随 `prefers-color-scheme`，`light`／`dark` 优先于系统。

| 角色 | macOS | Windows | 规则 |
|---|---|---|---|
| UI | `-apple-system` / `BlinkMacSystemFont` | `"Segoe UI Variable"` / `"Segoe UI"` | 跟随平台，中文使用系统回退 |
| 数据 | `"SFMono-Regular"` | `"Cascadia Mono"` | 再回退到 `ui-monospace` |
| 标题 | 系统 UI 600 | 系统 UI 600 | 使用负向轻微 tracking，不做营销型超大标题 |
| 正文 | 系统 UI 400 | 系统 UI 400 | `text-wrap: pretty`，错误说明保持短句 |
| 小标签 | 系统 UI 500 或数据字体 | 同左 | 只对极短稳定标签使用大写 |

所有动态百分比、计时和重置时间使用 `font-variant-numeric: tabular-nums`。窗口标题和 Provider 名称使用系统 UI 字体，不用 Monospace 模拟开发者工具。

## 5. 间距、尺寸与形状

### 5.1 基础节奏

`4 / 8 / 12 / 16 / 24 / 32`

- 控件内部：8～12。
- 同组字段：8～16。
- Provider lane 内部：16～24。
- 主要区域之间：24～32。
- 桌面控件最小点击区域：40 × 40。

唯一例外是紧凑面板头部的图标按钮：`32 × 32`。380px 宽度容不下四个 40px 按钮，`32 × 32` 仍满足 WCAG 2.5.8 AA，见 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md)。主窗口、设置和首次启动不适用这个例外。

### 5.2 圆角

| 对象 | 建议范围 |
|---|---:|
| 紧凑面板图标按钮 | `8px` |
| 小按钮、输入框 | `12px` |
| Provider lane | `14px` |
| 紧凑面板内容层 | `14px` |
| 紧凑面板外壳 | 跟随平台，约 `16px` |

嵌套表面遵循“外圆角 = 内圆角 + 间距”的同心原则。状态标签只有在文本稳定且确实需要独立识别时才使用胶囊形，不能把普通文案全部做成 Pill。

### 5.3 窗口尺寸

| 表面 | 尺寸 | 约束 | 状态 |
|---|---|---|---|
| 紧凑面板 | `380 × 392` | 最小 `340 × 260`，最大 `420 × 560`；高度由内容驱动 | 桌面壳已落地 |
| 主窗口 | `960 × 680` | 最小 `720 × 520`，额度总览窄时单列 | 设置同窗已落地；自动化已通过，待实机复核 |
| 首次启动 | `640 × 520` | 至多三个短步骤，不可缩放 | 已落地 |

设置不再拥有独立窗口尺寸。进入设置视图时保持主窗口当前尺寸与位置，不通过缩放窗口暗示层级变化；设置内容使用最大 `520px` 的单列阅读宽度，在主窗口内水平居中。窗口达到最小尺寸或文字缩放到 `200%` 时允许内容区垂直滚动，标题、返回入口和当前编辑项不得被遮挡。

第 7 阶段曾建议紧凑面板在 macOS 使用 `360px`、Windows 使用 `380px`。桌面壳验证后统一为 `380px`：两个平台只在锚点位置和外壳材质上区分，不再区分宽度。

#### 紧凑面板的高度规则

面板高度跟随内容，不是固定值。前端量出「头部 + lane 区内容 + lane 区留白」需要多高，交给 Rust 平台层收进 `[260, 560]` 后应用到窗口；超过上限的部分在 lane 区内部垂直滚动，头部与分隔线保持不动。

- `392` 是首帧高度，不是稳态高度。它对应当前的稳态形态——Claude 三个额度窗口、Codex 两个，都带套餐 chip、无状态提示条——挂载后立即被实测值覆盖。Windows 的系统字体行高更大，同样内容约 `400`，首帧向下补齐的差值不做特殊处理。
- 下限 `260` 是安全网，不是贴合值：它只保证面板在任何内容形态下都不塌成一条缝。
- 上限 `560` 是刻意的克制。两个 Provider 同时异常、且 Claude 返回四个额度窗口时内容约 `609`，此时滚动而不是继续长高。
- 面板可见时的高度变化直接生效，不做补间。窗口尺寸无法用 CSS 过渡，而额度变化引起的高度变化频率低、幅度小，为它引入分帧不划算。
- macOS 面板锚在顶边，高度变化不影响位置；Windows 锚在底边，每次高度变化都要连带重新锚定，否则面板会向下长出去盖住托盘图标。

已落地行的真值来源是 `src-tauri/tauri.conf.json`。高度上下限在 `src-tauri/src/platform/desktop.rs` 另有一份常量——Tauri 不提供 `minHeight` / `maxHeight` 的 getter，且它自己也按同样的边界截断 `set_size`。本表、配置、Rust 常量三处必须同时修改。

## 6. 深度与平台材料

- macOS 紧凑面板外壳可使用系统材质或受控半透明，内容 lane 保持实色。
- Windows 紧凑面板优先使用平台得体的实色或 Acrylic 外壳，必须验证 WebView2 对比度和性能。
- 主窗口的额度总览与设置视图使用同一套实色背景、色阶和结构分隔，不使用整窗玻璃。
- Provider lane **静止时即带阴影**（`--shadow-lane`），层级主要靠阴影表达，不用等交互才出现；交互时可以进一步增强，但不上移布局。
- 浅色阴影使用中性透明黑，深色使用低透明白 ring；深色下阴影本身不够可见，卡片保留一圈极淡描边兜底定义边界。
- 输入框保留清晰边界以保证可访问性；结构分隔线不被阴影替代。

## 7. 核心组件方向

### 7.1 Provider Lane

- 固定 Codex → Claude Code 顺序。
- 头部一行：Provider 名、套餐名胶囊、脱敏账号。账号靠右，过长省略，不换行也不挤压 Provider 名。
- 主额度紧随头部，专项额度用虚线与主额度分隔——它们是同一个 Provider 的次级信息，不是新的分区。
- 状态由提示条承担，不在头部重复状态词；刷新时间由 Overall Signal 统一显示。
- 失败时保持 lane 位置和既有数据，不切换成完全不同的错误卡片。
- 无凭据时保持相同骨架，读数位置显示占位符，不显示伪造的 `0%`。

### 7.2 Quota Progress

两种排布：

- 主额度：读数行在上（大百分比、窗口名、重置时间同一行），全宽圆角进度条在下。
- 专项额度：单行（窗口名、细进度条、百分比、重置时间），进度条吸收剩余宽度。

- 圆角进度条（pill track）表达剩余比例，不伪造历史或使用趋势。
- `stale` 时进度条保持旧值，并用明确状态层覆盖其新鲜度。
- `loading` 且有快照时不清空进度条。
- 不使用圆形 Gauge、速度表或动画计数。

#### 余量分档

百分比读数与进度条填充的颜色由**剩余百分比**决定，与可用性状态无关。分档、色值和它与状态基调的分工由 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md) 拥有，唯一实现是 `src/lib/quotaTone.ts`：

| 剩余百分比 | 表达 |
|---|---|
| `> 50` | 中性色 |
| `20 ≤ pct ≤ 50` | Warning |
| `0 < pct < 20` | Low |
| `= 0` | Danger |
| 无数值 | 次要文字色 |

快照不新鲜时整体降级为中性：旧数据不得用鲜艳颜色宣称当前额度紧张。

余量基调只驱动读数与填充；状态提示条、状态点和状态词由 `src/lib/status.ts` 的状态基调驱动。两者必须并存——「凭据失效」和「只剩 3%」是两件不同的事。

### 7.3 Overall Signal

- 总体状态只回答“现在最需要注意什么”。
- Provider 保持稳定顺序，总体信号负责提高最高风险的视觉权重。
- 没有风险时不显示夸张绿色成功横幅。

两个表面的标题都是**稳定的表面名**，不是状态句：紧凑面板「用量」，主窗口「额度总览」。不把总体状态写成整句——它长且在最不需要注意时占据最显眼的位置，见 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md)。稳定标题也是焦点恢复时要播报的那一个，见第 7.6 节。

副标题是最近一次成功刷新时间。标题右侧是状态点，承担总体状态：

| 状态点 | 含义 | 表达 |
|---|---|---|
| 全部实时 | 数据是最新的 | 绿色，带呼吸（reduced motion 下静止） |
| 有旧数据或受限 | 部分数据已过期 | 琥珀色 |
| 有需要处理的失败 | 有需要处理的问题 | 红色 |
| 尚无任何数据 | 尚未连接 | 静默灰点，不假装连接正常 |

状态点带可访问名称，因此颜色不是状态的唯一载体，第 3.3 节仍然成立。需要处理的事由对应 Provider 的提示条说清楚，不在标题重复。

### 7.4 Status Explanation

- 紧凑面板和主窗口都使用 tint 底色的提示条：neutral 是灰调，warning／critical 换成对应语义色。
- 图标嵌在同色圆底里，放在文字左侧；不使用左边框色块。需要处理的事用警告三角，中性说明用信息图标。
- 紧凑面板只放一行短说明；主窗口使用标题、影响和下一步三级结构。「下一步」用正文色，从解释里提出来。
- 错误文案不道歉、不使用“未知错误”作为最终用户解释。
- 不暴露 Rust 枚举、HTTP 原文、文件路径或凭据内容。

### 7.5 Controls

- 主窗口与首次启动的主要动作使用清晰文字，不依赖图标猜测。
- 紧凑面板头部的四个动作（刷新、打开 CC Trace、设置、退出）使用图标按钮，理由与例外范围见 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md)。
- 图标按钮必须有 Tooltip 和可访问名称。
- 主动作使用 solid 底色加同色发光阴影；次动作使用 flat 底色，不着色。
- 按压反馈使用 `scale(0.96)`，必要时允许静态模式。
- 焦点使用 `--action-primary` 高对比 ring，不只改变背景。
- 不使用 `transition: all`。

### 7.6 主窗口内导航

- 额度总览是主窗口默认视图；设置是二级视图，不与额度并排，也不形成常驻侧边栏或 Tab。
- 进入设置时，窗口标题栏、尺寸与位置保持稳定，只替换内容区，避免产生“打开了另一个应用窗口”的断裂感。
- 设置顶部使用带文字的“返回额度”入口，不只放一个方向箭头；中文、英文和辅助技术都必须能理解返回目标。
- 从额度总览进入设置后返回，焦点优先恢复到原设置入口；从紧凑面板或原生菜单进入时，返回后焦点进入额度总览首个有意义位置。
- 视图切换不使用模态遮罩、抽屉或 Sheet，也不移动或缩放整个窗口。只对内容区使用可打断的 `opacity` 过渡：退出使用 `--motion-fast`，进入使用 `--motion-base`，不使用 keyframes 或 `transition: all`。
- 主窗口首次显示不播放视图入场动画；只有用户明确在额度与设置之间切换时才过渡。切换不锁定输入，路由提交后立即移动焦点，不等待动画结束。
- reduced motion 下直接替换内容，保留焦点变化和可访问的视图标题作为反馈。
- “打开 CC Trace”始终落到额度总览；只有明确的设置入口和设置快捷键才落到设置视图。

## 8. 状态视觉矩阵

状态语义、失败原因分类和优先级由 [状态与错误模型](状态与错误模型.md) 定义，本节只定义视觉表达。

| 状态 | 数据处理 | 主要表达 | 动作 |
|---|---|---|---|
| `loading + empty` | 无数据 | 骨架与“正在检查” | 等待，允许关闭 |
| `refreshing + snapshot` | 保留现有值 | 刷新图标与状态文案 | 请求合并，不重复清空 |
| `live` | 当前快照 | 中性稳定展示，显示成功时间 | 可刷新 |
| `no_credentials` | 无额度 | 中性说明，不显示 0% | 检查对应 CLI 登录 |
| `offline + stale` | 保留旧值 | 琥珀状态、旧快照时间 | 网络恢复后刷新 |
| `offline + empty` | 无数据 | 离线空状态 | 重试 |
| `rate_limited + stale` | 保留旧值 | 琥珀状态、可重试时间 | 退避结束后刷新 |
| `error + stale` | 保留旧值 | 红色错误说明与旧值 | 全部刷新或按建议处理 |
| `error + empty` | 无数据 | 错误标题、影响和下一步 | 全部刷新或外部处理 |

状态变化不得导致 Provider lane 尺寸大幅跳动。错误说明在紧凑面板中折叠，在主窗口中完整展开。

## 9. 动效与反馈

- 紧凑面板从系统区域图标的方向产生，进入和退出沿同一路径。
- 默认使用无过冲、可打断的短过渡，响应约 `0.28–0.36s`。
- 普通菜单和主窗口视图切换不使用弹跳；只有真实动量手势才允许轻微回弹，首版没有该类手势。
- 点击时立即提供按压反馈，不等待请求完成。
- 刷新图标只在真实刷新任务进行时旋转，请求结束立即进入结果状态。
- Provider 更新使用数值替换和轻量交叉淡化，不做滚动计数。
- 错误出现不摇晃窗口、不闪烁整屏。
- 退出动效短于进入动效。

### Reduced motion

- 关闭位移、弹簧、模糊和旋转，改为短交叉淡化或静态替换。
- 刷新状态使用静态图标和文字，不依赖持续旋转。
- 降低透明度偏好时，平台材质切换为高不透明或实色。
- 高对比偏好时增加边界和文字对比，不能只加饱和度。

## 10. 键盘、焦点与文本

- 所有交互元素具备可见 `:focus-visible`。
- 紧凑面板打开时焦点进入第一个有意义的状态或动作，`Esc` 关闭。
- 主窗口当前可见视图与首次启动保持逻辑 Tab 顺序；隐藏的另一个主窗口视图不进入焦点序列。
- macOS 使用 `⌘R`、`⌘,`、`⌘W`、`⌘Q`；Windows 使用 `Ctrl+R`、`Ctrl+,`、`Ctrl+W`、`Ctrl+Q`、`Alt+F4` 和平台菜单。
- 状态播报使用节制的可访问区域，不重复播报无变化刷新。
- 英文、中文和 200% 文字缩放不得遮挡额度百分比、重置时间或恢复动作。
- 账号名和模型名优先单行省略，并提供可访问的完整值；核心状态和动作不能被省略。

## 11. 第 8 阶段验证重点

- 两个平台的紧凑面板是否在对应系统区域位置自然出现。
- Quota Progress 在最小、典型和长文本数据下是否仍然可读。
- 两个 Provider 分别处于成功和失败时是否互不干扰。
- 有快照刷新、离线旧快照、无凭据和 429 是否能被快速区分。
- 主窗口单页是否足以解释问题，不需要侧边栏或 Tab。
- 设置作为主窗口二级视图时，进入、返回、焦点恢复与窗口尺寸是否稳定。
- 设置和首次启动是否保持最小范围。
- 深浅色、reduced motion、键盘、焦点和文本缩放是否完整。

第 8 阶段确认后，再把验证通过的精确 Token 和组件行为落入正式代码；正式 UI 建立后重新运行 `impeccable document`，从实现提取真实 Token 并更新 `DESIGN.md`。
