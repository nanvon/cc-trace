# 视觉修复方向评审

> 状态：**候选方向，尚未定稿**。本文记录评审稿的位置、主张和它与现行文档的冲突，**不是规范**。
> 样式真值仍然是 `src/styles/tokens.css` 与[设计方向与状态规范](设计方向与状态规范.md)。
> 记录日期：2026-08-02

## 结论

[ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 确认的 HeroUI 方向在实机落地后暴露出四类观感问题。评审稿 [`prototypes/visual-refresh/`](../prototypes/visual-refresh/index.html) 针对这四类问题给出修复取值，**不改变视觉方向本身**。

评审稿明确保留不变的部分：信息架构、状态语义、Provider 稳定 lane、[ADR-0019](决策/ADR-0019-读数位改用定宽短码与紧凑倒计时.md) 的定宽短码。改的只有色值、阴影档位、字号和排版细节。

## 评审稿的性质

与 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md)、[ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md) 引用的 claude.ai Artifact 不同，这份稿子**在仓库内、受版本管理、离线可用**。

但性质相同：**它是决策依据的留档，不是样式真值来源**。在对应 ADR 写成之前，任何实现都不得以这份 HTML 为准。

稿件使用的额度与费用是实机截图的真实数据，不是合成示例。

## 要修的四类问题

| # | 问题 | 修复主张 |
|---|---|---|
| 1 | ok 档进度条是黑色 | 填充改用 `--status-success` |
| 2 | 大读数字号失衡 | 44px 压到 26px，补回中间层级 |
| 3 | 层级不显（canvas 与阴影） | 加深 canvas 拉开与白卡色差；lane 阴影加档 |
| 4 | 排版细节碎 | 状态点并入新鲜度副标题、花费行 label–value 成对内联、次级窗口改同族样式、图标统一 16 viewBox / stroke 1.5 |

## 与现行文档的冲突清单

稿内标 🚩 的取值**推翻或修改了已确认结论**。定稿前这些冲突必须逐条处理。

| 🚩 | 评审稿取值 | 现行取值 | 冲突文档 |
|---|---|---|---|
| Canvas 浅色 | `#F4F4F5` | `#FAFAFA` | [设计方向与状态规范](设计方向与状态规范.md) §3.1、[DESIGN.md](../DESIGN.md)、[ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 决策·颜色 |
| 暗色背景 | `#0E0E11` | `#000000` | [设计方向与状态规范](设计方向与状态规范.md) §3.2、[DESIGN.md](../DESIGN.md) |
| 暗色表面 | `#1C1C1F` | `#18181B` | [设计方向与状态规范](设计方向与状态规范.md) §3.2、[DESIGN.md](../DESIGN.md) |
| `--shadow-lane` | 加档至静止可见 | 现值 | [设计方向与状态规范](设计方向与状态规范.md) §3.4、[ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 决策·层级 |
| 大读数字号 | 26px | 44px | [设计方向与状态规范](设计方向与状态规范.md)、[DESIGN.md](../DESIGN.md)「strong but not theatrical」 |
| 进度条 ok 档 | `--status-success` | `--text-primary` | [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md) 余量四档色；[设计方向与状态规范](设计方向与状态规范.md) §3.3「`live` 默认使用中性色，仅在明确成功反馈中短暂使用绿色」 |

前三项与 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 「背景与卡片表面色值刻意非常接近，层级主要靠阴影而不是色差表达」的原则直接相关：评审稿认为纯靠阴影在实机上层级不足，因此**同时**加深 canvas 和加档阴影。这是对该原则的修正，不是简单换色值。

最后一项冲突面最大 —— ok 档常驻绿色会让「剩余充足」与「刚刚刷新成功」共用同一个绿，需要在 ADR 里说明两者如何继续可辨。

## 并排对比的处置

评审稿正文写有「可与 `prototypes/macos-native/` 并排对比后再定视觉方向」。

该目录不存在，且产品所有者 2026-08-02 确认**不再需要这次对比**：`visual-refresh` 是唯一候选方向。稿内那句引用**已作废**。

## 定稿门槛

方向已收敛为唯一候选，但仍未定稿。转为正式规范需要按 [文档地图](README.md) 第 4 节依次完成：

1. 写新 ADR，逐条推翻上表中 [ADR-0012](决策/ADR-0012-视觉方向改为HeroUI风格.md) 与 [ADR-0017](决策/ADR-0017-系统区域显示额度数字与余量分档.md) 的对应取值，并说明 ok 档绿色与成功反馈绿的分工。
2. 同步改写[设计方向与状态规范](设计方向与状态规范.md) §3.1、§3.2、§3.4 与 [DESIGN.md](../DESIGN.md)。
3. 同步改 `src/styles/tokens.css` —— 规则 2 要求实现值与文档值双向同步，不允许只改一侧。
4. 实机复核浅色与深色下的层级表现，结果写回本文。

在第 1 步完成前，本文所列取值一律视为**待确认**。
