# 数据存储与用量索引

> 本文件拥有以下事实：**用量数据库的物理布局、表结构、索引、事务边界、迁移规则、扫描协议**。
> 选型理由与被否决的替代方案由 [ADR-0018](决策/ADR-0018-用量数据用SQLite与JSON分域.md) 拥有，本文不重复论证。
> JSON 侧持久化（`settings.json`、`quota-cache.json`、`logs/`）的规则仍由 [技术架构](技术架构.md) §数据与恢复拥有，本文不改动它们。

**生效前提**：[ADR-0018](决策/ADR-0018-用量数据用SQLite与JSON分域.md) 状态为「已提议」，其文末三项条件未全部满足前不得据此建库。本文可以先行评审与细化。

## 1. 物理布局

应用数据目录（与 `settings.json` 同级）：

```text
settings.json          JSON   设置
quota-cache.json       JSON   额度快照缓存
pricing-catalog.json   JSON   价格目录
logs/                  文本   运行日志
usage.db               SQLite 用量、对话、扫描水位、额度历史
usage.db-wal                  WAL，勿单独删除
usage.db-shm                  共享内存索引，勿单独删除
```

删除或备份数据库必须按 `usage.db*` 整组处理；只删主文件会留下不一致的 WAL。

### 连接参数

打开连接后立即执行，顺序不可颠倒：

```sql
PRAGMA journal_mode = WAL;      -- 扫描写入时 UI 查询不被阻塞
PRAGMA synchronous  = NORMAL;   -- WAL 下断电最多丢最后一个事务，符合派生数据的容忍度
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

`journal_mode` 是持久属性，其余每次连接都要设。`synchronous = FULL` 不采用：本库除 `quota_events` 外均为可重建派生数据，为它付每次提交的 fsync 代价不成比例。

### 连接管理

- 单写连接 + 只读连接池。扫描线程持有唯一写连接，查询走只读连接。
- 依赖 `rusqlite`（feature `bundled`），留在 Rust 层。**不引入 `tauri-plugin-sql`**，理由见 ADR-0018。
- 前端不获得任何 SQL 执行能力，一律走既有 command 边界，返回脱敏 DTO。

## 2. 表结构

### 2.1 `scan_files` — 扫描水位

```sql
CREATE TABLE scan_files (
  path          TEXT PRIMARY KEY,
  source        TEXT    NOT NULL,          -- 'codex' | 'claude'
  mtime_ms      INTEGER NOT NULL,
  size_bytes    INTEGER NOT NULL,
  offset_bytes  INTEGER NOT NULL,          -- 已消费到的字节位置
  cursor_json   TEXT,                      -- 源特有的续扫状态，见下
  updated_at    TEXT    NOT NULL           -- ISO 8601 UTC
);
```

`cursor_json` 承载**不能从 entries 反推**的续扫状态：

- Codex：当前 `model`、`service_tier`、累计用量 signature。截断时重置这三项但保留 conversation identity。
- Claude：无内容，写 `NULL`。去重由 `usage_entries` 的唯一索引承担——旧版 `seen IDs` 上限 20,000 的妥协在此消失。

判定增量或全量的规则：`size_bytes` 变小 → 文件被截断，`offset_bytes` 归零并重置 `cursor_json`；`mtime_ms` 或 `size_bytes` 变大 → 从 `offset_bytes` 续读；两者不变 → 跳过。

### 2.2 `usage_entries` — 逐条事实

```sql
CREATE TABLE usage_entries (
  id                    INTEGER PRIMARY KEY,
  source                TEXT    NOT NULL,   -- 'codex' | 'claude'
  dedup_key             TEXT    NOT NULL,   -- Claude: message.id / Codex: conversation + 累计 signature
  conversation_key      TEXT    NOT NULL,
  model                 TEXT,               -- 缺失写 NULL，不写 'unknown' 字面量
  speed                 TEXT    NOT NULL,   -- 'fast' | 'standard' | 'unknown'
  occurred_at           TEXT    NOT NULL,   -- ISO 8601 UTC
  day_local             TEXT    NOT NULL,   -- YYYY-MM-DD，按归日边界计算，派生列
  input_tokens          INTEGER NOT NULL,
  output_tokens         INTEGER NOT NULL,
  cache_read_tokens     INTEGER NOT NULL,
  cache_creation_tokens INTEGER NOT NULL,
  cost_usd              REAL,               -- 派生列，未定价写 NULL 而非 0
  pricing_fingerprint   TEXT                -- cost_usd 依据的价格版本
);

CREATE UNIQUE INDEX ux_entries_dedup ON usage_entries(source, dedup_key);
CREATE INDEX ix_entries_day  ON usage_entries(day_local, source);
CREATE INDEX ix_entries_conv ON usage_entries(conversation_key, occurred_at);
CREATE INDEX ix_entries_repricing ON usage_entries(pricing_fingerprint)
  WHERE pricing_fingerprint IS NOT NULL;
```

**事实列与派生列必须分开，这是本设计的核心。** token 数与时间戳是从日志读出的事实，写入后不再改变；`cost_usd`、`pricing_fingerprint`、`day_local` 是可随配置重算的派生列。旧版把两者绑死，才导致价格变更必须重扫原始日志。

由此得到两条**不重扫**的重算路径：

```sql
-- 价格目录更新：只碰数据库，完全不读 1.25 GB JSONL
UPDATE usage_entries
   SET cost_usd = ?, pricing_fingerprint = ?
 WHERE model = ? AND speed = ?
   AND (pricing_fingerprint IS NOT ? OR pricing_fingerprint IS NULL);

-- 归日边界变更：同理
UPDATE usage_entries SET day_local = date(occurred_at, ?);
```

约定：

- 原始 Token 总量 = input + output + cache read + cache creation。**不把 Fast 倍率乘回原始 token**，倍率只作用于计费等效值（沿用旧版口径，见 [cc-bar-reference/05](cc-bar-reference/05-本地用量对话与计价口径.md)）。
- Codex 的 `input_tokens` 需先扣除 cached input 与 cache write，避免重复计费。
- 未知模型：token 照常聚合，`cost_usd` 写 `NULL`。用 `NULL` 而非 `0`，让「未定价」和「零费用」在聚合时可区分。

> **待确认**：归日边界目前无设置项——`contracts/settings.rs` 的 `Settings` 只有 language、appearance、refreshInterval、launchAtLogin、onboarding，没有旧版的 reset time。若首版补这项设置，`day_local` 按它计算；若不补，固定按本地日历日。假设错误的影响面：只需执行上面第二条 `UPDATE`，不涉及重扫，因此可以先按本地日历日实现。

### 2.3 `conversations` — 对话身份

```sql
CREATE TABLE conversations (
  conversation_key TEXT PRIMARY KEY,
  source           TEXT    NOT NULL,
  title            TEXT,
  project_path     TEXT,
  is_sidechain     INTEGER NOT NULL DEFAULT 0,
  first_at         TEXT    NOT NULL,
  last_at          TEXT    NOT NULL
);

CREATE INDEX ix_conv_recent ON conversations(last_at DESC);
CREATE INDEX ix_conv_project ON conversations(project_path);
```

**只存身份与元数据，不存聚合值。** 总 token、总费用一律从 `usage_entries` 现算。理由：对话数在千级、entries 在十万级，走 `ix_entries_conv` 的 `GROUP BY` 是毫秒级，物化列会引入「聚合与明细不一致」这一整类 bug。实测慢了再加物化表，不提前优化。

### 2.4 `quota_events` — 额度历史（Timeline）

```sql
CREATE TABLE quota_events (
  id                INTEGER PRIMARY KEY,
  provider          TEXT    NOT NULL,
  identity_key      TEXT,               -- 身份指纹（单向摘要），不是明文身份
  window_kind       TEXT    NOT NULL,
  window_id         TEXT,
  remaining_percent INTEGER NOT NULL,
  observed_at       TEXT    NOT NULL
);

CREATE INDEX ix_quota_series ON quota_events(provider, identity_key, observed_at);
```

- 沿用旧版规则：**只在整数剩余值发生变化时插入**，相同值不重复追加；`window_kind` 或 `window_id` 变化时先重设 baseline。
- `identity_key` 复用 `providers::credentials::identity_fingerprint` 的单向摘要，**不得写入明文 account id 或邮箱**。
- 身份变化时按 [额度领域模型](额度领域模型.md) §4.1 丢弃该 Provider 的快照与退避，但**历史事件不删除**——它们是已发生的观察记录，属于旧身份，按 `identity_key` 自然隔离。
- 本表是全库唯一**不可重建**的数据，迁移与清理规则见 §4。

> **待确认**：是否需要账号维度。旧版 Timeline 按账号绘制曲线并对导入账号做镜像去重。这取决于 Codex 账号导入（cc-bar F-11）是否进入本版——该功能尚未定档。假设错误的影响面：需要新增一列并回填，历史数据无法追溯补全，因此这一项必须在建表前定，不能事后补。

## 3. 事务边界

**一个扫描批次 = 一个事务。** 事务内完成三件事，缺一不可：

1. `INSERT OR IGNORE` 本批 `usage_entries`（唯一索引承担去重）
2. `UPSERT` 涉及的 `conversations`
3. `UPDATE scan_files` 推进 `offset_bytes` 与 `cursor_json`

这三者同生共死，是「崩溃可续扫」的全部依据：offset 永远不可能领先于已提交的 entries。旧版「先写 rollup、最后写 scan state，任一失败就 invalidate」的全量重扫由此消除。

其余规则：

- 批次大小按行数与字节数双阈值控制，避免单事务过大导致 WAL 膨胀。**具体阈值待首次全量扫描实测后填入**，初值建议 2000 行或 8 MB 先取其一。
- 首次全量扫描按文件粒度分批提交，中断后从已提交的 offset 继续，不从头开始。
- 价格重算是独立事务，不与扫描事务合并。

## 4. 版本与迁移

用 `PRAGMA user_version` 记录 schema 版本，不自建版本表。迁移在单个事务内执行，失败则整体回滚。

**两类数据的迁移策略必须区别对待：**

| 表 | 可重建性 | 迁移失败时 |
|---|---|---|
| `usage_entries`、`conversations`、`scan_files` | 可由外部 JSONL + 价格表完全重建 | 允许 `DROP` 后重建并触发全量重扫。代价是一次分钟级扫描，可接受 |
| `quota_events` | **不可重建**——是观察时点的记录，删了永久丢失 | **禁止 `DROP`**。必须保守迁移；无法安全迁移时保留原表改名留存，绝不删除 |

数据库整体损坏（`PRAGMA integrity_check` 不通过）时：先尝试导出 `quota_events`，再重建库并重扫。**不采用额度缓存那种「损坏就删」的策略**——那条规则成立的前提是数据可完全重建，本库不满足。

## 5. 安全边界

沿用 [技术架构](技术架构.md) §凭据与权限与 [日志与诊断](日志与诊断.md)，本库额外约束：

- **库内不得出现任何秘密**：access token、refresh token、PAT、API key、明文 account id、明文邮箱一律禁止入库。身份只以单向指纹形式存在。
- `conversations.title` 与 `project_path` 是**用户内容**：可以落盘（功能必需），但**不得进入日志**，也不得随诊断信息导出。
- 持有数据库连接或行数据的类型如含上述字段，按 [日志与诊断](日志与诊断.md) 手动屏蔽 `Debug`，不用 `#[derive(Debug)]`。
- 数据库不可 `cat` 审计，因此**用 schema 断言替代人工审计**：测试中枚举全部列名，出现白名单外的列即失败。这条是上述禁令的执行手段，必须实现。

## 6. 扫描协议

数据源与解析口径由 [额度领域模型](额度领域模型.md) 和 [cc-bar-reference/05](cc-bar-reference/05-本地用量对话与计价口径.md) 拥有，本节只定义与存储相关的部分。

| 源 | 扫描根 |
|---|---|
| Claude Code | `~/.claude/projects/**/*.jsonl` |
| Codex | `~/.codex/sessions/**/*.jsonl` + `~/.codex/archived_sessions/**/*.jsonl` |

- 按字节 offset 读取，**只消费完整换行行**；末尾没有换行的半行不消费，下次从同一 offset 继续。
- Claude：只解析 assistant 行，要求 sessionId、`message.usage`、`output_tokens > 0`；`stop_reason` 非空才算完整，半成品不入库。`message.id` 是 `dedup_key`。
- Codex：`last_token_usage` 作为本次增量；`total_token_usage` 的 signature 用于跳过总量未变的重复行。同一 UUID 在 sessions 与 archived 都存在时按较新 mtime 取一份。
- 首次全量扫描是分钟级操作（实测 1769 文件 / 1.25 GB），必须提供进度、可中断、后台执行与断点续扫。这是产品行为，需在 [信息架构与核心流程](信息架构与核心流程.md) 补对应流程后再实现。
