# 数据存储与用量索引

> 状态：首版生效规范
>
> 本文件拥有：**本地 JSONL 的 Token 标准化、价格目录与 API 等值费用口径；用量数据库的物理布局、表结构、索引、事务、迁移、恢复、扫描协议与查询契约**。
>
> SQLite 与 JSON 的分域理由由 [ADR-0018](决策/ADR-0018-用量数据用SQLite与JSON分域.md) 拥有。额度 API 字段与凭据规则仍由 [额度领域模型](额度领域模型.md) 拥有。

## 1. 边界与物理布局

CC Trace 只读 Codex、Claude Code 自己的 JSONL，不修改、移动、截断或删除它们。派生数据只写入 CC Trace 自己的应用配置目录：

```text
settings.json          JSON    设置
quota-cache.json       JSON    最新额度快照
pricing-catalog.json   JSON    公开远端价格缓存（schema v2）
logs/                  文本    运行日志
usage.db               SQLite  用量、对话元数据、扫描水位、额度历史
usage.db-wal                   WAL，和主库视为一个文件组
usage.db-shm                   共享内存索引，和主库视为一个文件组
```

数据库备份、恢复或人工移动必须按 `usage.db`、`usage.db-wal`、`usage.db-shm` 整组处理。实现不得用宽泛 glob 删除文件。

### 1.1 连接

Rust 使用 `rusqlite` 的 `bundled` feature；不引入 `tauri-plugin-sql`，前端不取得任意 SQL 能力。

写连接执行：

```sql
PRAGMA journal_mode = WAL;
PRAGMA synchronous = NORMAL;
PRAGMA foreign_keys = ON;
PRAGMA busy_timeout = 5000;
```

查询连接以只读方式打开，并执行 `foreign_keys` 与 `busy_timeout`。进程内只有一个逻辑写锁；扫描批次、费用重算与额度历史写入均经过它。WAL 允许查询与扫描并行。

数据库按需打开：数据库损坏或迁移失败不得阻断应用启动、额度刷新或设置。用量 command 返回稳定的不可用错误；下一次扫描可以触发恢复。

## 2. 标准化事实

### 2.1 Token 维度

每条 `UsageEntry` 固定保存六个非负整数事实：

| 字段 | 含义 | 总量关系 |
|---|---|---|
| `uncached_input_tokens` | 未由缓存命中的输入 | 计入输入与总量 |
| `output_tokens` | 全部输出，已经包含推理输出 | 计入总量 |
| `reasoning_output_tokens` | 输出中的推理子集 | **不再次加到总量** |
| `cache_read_input_tokens` | 缓存读取输入 | 计入输入与总量 |
| `cache_write_5m_input_tokens` | 5 分钟缓存写入输入 | 计入输入与总量 |
| `cache_write_1h_input_tokens` | 1 小时缓存写入输入 | 计入输入与总量 |

标准化总量：

```text
input_tokens =
  uncached_input_tokens
  + cache_read_input_tokens
  + cache_write_5m_input_tokens
  + cache_write_1h_input_tokens

total_tokens = input_tokens + output_tokens
```

原始 Token 永远不乘 Fast／Priority 或地域倍率。Fast 的计费等效 Token 另存为派生值，
不会覆盖六维 Token 事实；地域倍率只影响 API 等值费用。

### 2.1.1 缓存命中率

缓存命中率是**派生指标**，不落库，由查询层按聚合后的 Token 现算：

```text
cache_hit_rate = cache_read_input_tokens / input_tokens
```

分母是上面定义的标准化 `input_tokens`，**含缓存写入**。主窗口用量页的 Provider 卡、模型表
行与分组小计统一使用这个分母；不再在展示层另行排除缓存写入。

规则：

- `input_tokens` 为 `0` 时命中率为 `NULL`，展示为 `—`，不按 `0%` 处理——没有输入和「一次都没
  命中」是两回事。
- 聚合时始终用原始整数 Token 相除，不对各行已经算好的百分比求平均；四舍五入只发生在展示层。
- 它与费用无关；未定价条目照常参与命中率计算。

### 2.2 来源映射

Codex `token_count`：

- 使用 `last_token_usage` 作为单条增量事实。
- 原始 `input_tokens` 已包含 `cached_input_tokens` 与 `cache_write_input_tokens`，所以：

  ```text
  uncached_input =
    input_tokens - cached_input_tokens - cache_write_input_tokens
  ```

- 任一减法下溢、`total_tokens != input_tokens + output_tokens` 或 `reasoning_output_tokens > output_tokens` 时，丢弃该条并计入解析错误，不猜值。
- Codex Cache Write 依次兼容 `cache_write_input_tokens`、`cache_write_tokens`，以及
  `input_tokens_details`、`prompt_tokens_details`、`token_details` 下的
  `cache_write_tokens`；命中一个权威字段后不重复相加。标准化到 5 分钟缓存写入，1 小时写入为 `0`。
- `total_token_usage` 只用于识别重复累计快照和恢复游标，不作为另一条用量重复落库。

Claude Code assistant message：

- `message.usage.input_tokens` 已是未缓存输入。
- `cache_read_input_tokens` 映射缓存读取。
- `cache_creation_input_tokens` 存在时是写入 aggregate：1 小时明细先截断到 aggregate，
  剩余归 5 分钟，不能再把 5m／1h 明细整体相加。aggregate 缺失时才相加
  `cache_creation.ephemeral_5m_input_tokens` 与 `ephemeral_1h_input_tokens`。
- 只接受 `message.id` 非空、`stop_reason` 非空、usage 存在且 Token 全部非负的完整 assistant message。`output_tokens` 可以为 `0`，不能用它判断消息是否完整。
- 相同 `message.id` 多次出现时只保留一个逻辑事件；后到的完整记录可以补全先到记录，但不得重复累计。

### 2.3 时间、模型、速度与地域

- `occurred_at` 统一保存解析后的 ISO 8601 UTC。
- `day_local` 是扫描时按机器本地日历日派生的 `YYYY-MM-DD`。首版不新增归日设置；未来变更只重算该列，不重读 JSONL。
- 模型缺失写 `NULL`；禁止把缺失事实伪装成字符串 `"unknown"`。
- `speed` 只允许 `standard`、`fast`、`unknown`。Codex `service_tier=priority` 归一为 `fast`；
  Codex 尚未出现 tier 时沿用 Standard。Claude `speed=fast` 归一为 `fast`，缺少 speed
  必须写 `unknown`，不得默认 Standard。
- `inference_geo` 只允许 `global`、`us`、`unknown`；Claude 明确给出 `us` 才使用美国推理价格，`not_available` 归为 `unknown`。

## 3. 价格目录与费用

价格由“随二进制升级的内置政策”与“可重建的远端缓存”合并。内置目录永远直接从应用资源
加载，不会被旧磁盘文件遮住；`pricing-catalog.json` schema v2 只保存 LiteLLM、models.dev
各自的 ETag、成功／失败时刻、Standard／Codex Fast／Claude Fast 费率，以及缺价刷新冷却。
文件不含用户数据或秘密。旧版 schema v1 保留为 `.legacy-v1-*` 后创建空 v2 缓存；损坏或
不支持的文件保留带时间戳副本后恢复空缓存，离线计价继续使用新版内置目录。

内置目录包含 `asOf` 与官方 `sources` URL；来源必须是 HTTPS。当前内置值按 2026-07-30 的
OpenAI 模型／Priority 文档与 Anthropic Pricing 文档整理。

每个价格项按美元／百万 Token 保存：

```text
model pattern
speed
effectiveFrom / effectiveUntil
uncachedInputUsdPerMTok
cacheReadUsdPerMTok
cacheWrite5mUsdPerMTok
cacheWrite1hUsdPerMTok
outputUsdPerMTok
usInferenceMultiplier
longContextThresholdTokens / longContext multipliers（可选）
```

目录先做模型名规范化，再按最长 family prefix 匹配；只接受 family 本身或
`YYYY-MM-DD`／`YYYYMMDD` 日期 snapshot，`gpt-5.5-pro`、`gpt-5.5-2` 之类语义不同的
后缀不会误命中 `gpt-5.5`。同一来源、family、速度的生效区间不得重叠。最终目录按本机
实际出现过的 `(source, model, speed)` 生成 SHA-256 `pricing_fingerprint`；远端更新未使用
模型时不触发数据库重计价。

合并优先级：

- Standard：本地阶梯／分段／固定特殊规则 > LiteLLM > models.dev > 本地离线兜底；
- Fast：本地历史／已审计特殊规则 > models.dev Fast > LiteLLM OpenAI Priority > 本地离线兜底。

只读取 LiteLLM 的官方 `anthropic`、`openai`、`deepseek` 裸模型键，以及 models.dev 的同名
官方 Provider；第三方转售商不进入目录。远端条目缺少 input／output 基础价时拒绝该条目；缺少
cache read／cache write 子价格时按 `$0` 处理。没有 Fast 条目时绝不套 Standard 价格。

正常成功后 24 小时刷新一次；某一来源失败后该来源 30 分钟才重试。扫描发现已有用量但缺少
可靠价格时，立即检查在线目录；同一 `(source, model, speed)` 30 分钟最多一次，冷却持久化并
在 7 天后清理。缺价刷新可绕过成功间隔，但不得绕过来源失败退避。设置页“更新价格目录”绕过
24 小时与失败冷却；两个来源只成功一个时返回部分更新，界面不得伪称目录已是最新。网络刷新只
写 pending，扫描中 active 不变；扫描结束或下一次扫描前提交。失败、空目录或 Standard 型号数
相对旧目录可疑骤减时保留旧值；Fast 使用 last-known 合并以服务历史日志。pending 的磁盘写入与
内存发布在同一锁内完成；写入失败时不发布新快照。

费用使用整数 **USD nanos** 保存，避免 `REAL` 累加误差：

```text
api_equivalent_cost_nanos =
  round_half_up(
    Σ(token_dimension × usd_per_million_token × 1000)
    × inference_geo_multiplier
  )
```

`reasoning_output_tokens` 已包含在 `output_tokens`，不单独计费。无法匹配模型、`speed=unknown`、目录区间不覆盖或 input／output 基础价缺失时，费用与 fingerprint 均为 `NULL`，不是 `0`；远端 cache read／cache write 子价格缺失是唯一例外，按 `$0` 计。

“API 等值费用”只回答：**相同 Token 若按该时点公开 API token 标价会是多少**。它不代表
Codex／Claude Code 订阅实付、账单或发票，也不包含工具调用费、税、批处理折扣、企业折扣
等无法从本地条目可靠还原的项目。目录已显式处理 GPT-5.6 Sol／Terra／Luna 与
GPT-5.5／Codex 超过 272K 输入的 Standard 阶梯；Fast 对该区间没有适用价格时返回未定价。
Opus 4.7／4.6 历史 Fast 与 `gpt-5.5-pro` 等特殊价格固定由本地政策拥有，不能被远端当前值
覆盖。查询同时返回：

- `apiEquivalentCostNanos`：已定价行之和；
- `pricedEntries`；
- `unpricedEntries`；
- `assumedGeoEntries`：Claude 日志未给推理地域、按 global 基准估算的已定价行数；
- `pricingFingerprint`：当查询范围内只有一版时返回该值，多版或无已定价行返回 `null`。
- `fast.rawTokens`：Fast 原始 Token；
- `fast.billingEquivalentTokens`：十进制定点字符串；
- `fast.minimumMultiplier`／`maximumMultiplier`：混合模型的倍率范围；
- `fast.hasUnpricedEquivalent`：存在无法安全确定倍率的 Fast 用量。

价格目录更新只重算 `usage_entries` 的费用派生列，不读取外部 JSONL。

## 4. Schema v2

Schema 版本使用 `PRAGMA user_version = 2`。v1 在单个事务中新增 Fast 派生列与
`pricing_state`，原始 Token、扫描水位和额度历史不重写。

### 4.1 `scan_files`

```sql
CREATE TABLE scan_files (
  file_key           TEXT PRIMARY KEY,
  source             TEXT NOT NULL CHECK(source IN ('codex', 'claude')),
  mtime_ms           INTEGER NOT NULL,
  size_bytes         INTEGER NOT NULL,
  offset_bytes       INTEGER NOT NULL,
  prefix_fingerprint TEXT NOT NULL,
  cursor_json        TEXT,
  updated_at         TEXT NOT NULL
);
```

`file_key` 不保存路径明文，按来源使用不同的稳定输入后计算 SHA-256：

- Codex 使用 `source + JSONL 文件 stem（会话 UUID）`。会话从 active 移到 archived 后
  key 不变，水位可以继续；同一 stem 的候选只取 mtime 较新者。
- Claude Code 使用 `source + .claude/projects 根目录下的相对物理路径`。不同项目目录可能
  同时存在相同会话 UUID 的 JSONL，必须各自维护水位，不能因 stem 相同而互相重置；
  跨文件的相同逻辑消息仍由 `source + message.id` 唯一索引去重。

`prefix_fingerprint` 取文件开头最多 4096 字节的 SHA-256。文件增长时先按上次记录长度复核旧前缀，再写入新前缀，避免小文件正常 append 被误判为改写。以下任一条件触发该文件从 `0` 重扫并重置源游标：

- 当前大小小于已提交 offset；
- 前缀指纹变化；
- 水位中的 offset 大于当前文件大小。
- 文件大小不变但 mtime 改变；
- source cursor 无法按当前 schema 解码。

仅比较 `size` 与 `mtime` 不能识别同尺寸覆盖或部分改写，因此不足以作为恢复判据。

Codex `cursor_json` 保存当前 conversation、model、speed 与上一份累计 Token signature；Claude 保存 conversation 元数据游标。游标不得含路径、标题正文或身份明文。

### 4.2 `usage_entries`

```sql
CREATE TABLE usage_entries (
  id                          INTEGER PRIMARY KEY,
  file_key                    TEXT NOT NULL,
  source                      TEXT NOT NULL CHECK(source IN ('codex', 'claude')),
  dedup_key                   TEXT NOT NULL,
  conversation_key            TEXT NOT NULL,
  model                       TEXT,
  speed                       TEXT NOT NULL CHECK(speed IN ('standard', 'fast', 'unknown')),
  inference_geo               TEXT NOT NULL CHECK(inference_geo IN ('global', 'us', 'unknown')),
  occurred_at                 TEXT NOT NULL,
  day_local                   TEXT NOT NULL,
  uncached_input_tokens       INTEGER NOT NULL CHECK(uncached_input_tokens >= 0),
  output_tokens               INTEGER NOT NULL CHECK(output_tokens >= 0),
  reasoning_output_tokens     INTEGER NOT NULL CHECK(reasoning_output_tokens >= 0),
  cache_read_input_tokens     INTEGER NOT NULL CHECK(cache_read_input_tokens >= 0),
  cache_write_5m_input_tokens INTEGER NOT NULL CHECK(cache_write_5m_input_tokens >= 0),
  cache_write_1h_input_tokens INTEGER NOT NULL CHECK(cache_write_1h_input_tokens >= 0),
  api_equivalent_cost_nanos   INTEGER,
  billing_equivalent_tokens_nanos INTEGER,
  fast_multiplier_nanos       INTEGER,
  pricing_fingerprint         TEXT,
  CHECK(reasoning_output_tokens <= output_tokens)
);

CREATE UNIQUE INDEX ux_entries_dedup
  ON usage_entries(source, dedup_key);
CREATE INDEX ix_entries_file
  ON usage_entries(file_key);
CREATE INDEX ix_entries_time
  ON usage_entries(occurred_at, source);
CREATE INDEX ix_entries_day
  ON usage_entries(day_local, source, model, speed);
CREATE INDEX ix_entries_conversation
  ON usage_entries(conversation_key, occurred_at);
CREATE INDEX ix_entries_repricing
  ON usage_entries(pricing_fingerprint);

CREATE TABLE pricing_state (
  id          INTEGER PRIMARY KEY CHECK(id = 1),
  fingerprint TEXT NOT NULL
);
```

`dedup_key` 是稳定业务签名的 SHA-256：

- Claude：`source + message.id`；
- Codex：`source + conversation_key + occurred_at + model + speed + total_token_usage signature`。

数据库唯一索引是最终去重边界，内存 set 只能是批内优化。

文件重扫的第一个事务先删除该 `file_key` 的旧 entries，再写入新事实和新水位；因此截断或覆盖不会让已被源文件替换的事实永久残留。Codex file key 在 active／archived 移动时稳定，正常归档不会触发这条删除路径。Claude 物理路径变化会形成新 file key，重复消息继续由唯一 `dedup_key` 合并。

### 4.3 `conversations`

```sql
CREATE TABLE conversations (
  conversation_key TEXT PRIMARY KEY,
  source           TEXT NOT NULL CHECK(source IN ('codex', 'claude')),
  title            TEXT,
  project_hint     TEXT,
  is_sidechain     INTEGER NOT NULL DEFAULT 0 CHECK(is_sidechain IN (0, 1)),
  first_at         TEXT NOT NULL,
  last_at          TEXT NOT NULL
);

CREATE INDEX ix_conversations_recent
  ON conversations(last_at DESC);
CREATE INDEX ix_conversations_source_recent
  ON conversations(source, last_at DESC);
```

只存身份与最小元数据，不保存消息正文或绝对项目路径。`project_hint` 只能是路径末段的脱敏提示。Token 与费用从 `usage_entries` 聚合，不在此表复制。

### 4.4 `quota_events`

```sql
CREATE TABLE quota_events (
  id                INTEGER PRIMARY KEY,
  provider          TEXT NOT NULL CHECK(provider IN ('codex', 'claude')),
  identity_key      TEXT NOT NULL,
  window_kind       TEXT NOT NULL,
  window_id         TEXT,
  remaining_percent INTEGER NOT NULL CHECK(remaining_percent BETWEEN 0 AND 100),
  observed_at       TEXT NOT NULL
);

CREATE INDEX ix_quota_series
  ON quota_events(provider, identity_key, window_kind, window_id, observed_at);
```

- `identity_key` 始终存在，只能使用既有不可逆身份指纹，禁止明文账号。
- 相同 provider、identity、window kind、window id 的最后整数值未变化时不插入。
- window kind／id 或身份变化会形成新序列，不删除旧身份历史。
- debug 合成场景不得写入额度历史。

`quota_events` 是唯一不可由 JSONL 重建的表。

## 5. 扫描协议

### 5.1 根目录和文件选择

| 来源 | 根目录 |
|---|---|
| Codex | `~/.codex/sessions/**/*.jsonl`、`~/.codex/archived_sessions/**/*.jsonl` |
| Claude Code | `~/.claude/projects/**/*.jsonl` |

- 根目录不存在等价于该来源为空，不是全局失败。
- 目录枚举失败、单个文件打不开、权限不足或存在无效行时记录脱敏计数并继续其他文件。
- Codex 相同会话 UUID 同时存在于 sessions 与 archived 时，只扫描 mtime 较新的候选；去重索引仍作为第二道保障。
- 枚举只跟随普通文件，不跟随目录符号链接，不访问根目录之外。

### 5.2 字节 offset

- 从已提交 `offset_bytes` 开始按字节读取。
- **只消费以 `\n` 结束的完整行**。文件末尾半行不解析、不推进 offset。
- 单行上限 16 MiB。已完整换行但超限的行计为错误并推进；未换行的超限尾部仍不推进。
- 批次在先达到 `2000` 行或 `8 MiB` 时提交。
- 每批同一事务提交 entries、conversation UPSERT 与 scan watermark。事务回滚时三者一起回滚。
- 取消只在行或批次边界生效；已经提交的批次保留，下一次从水位继续。

### 5.3 状态与并发

扫描状态只有 `idle`、`running`、`cancelling`。同一进程同时只允许一个扫描任务；重复触发返回 `usageScanBusy`，不排队创建第二个任务。

完成引导后立即触发首次扫描，之后每 5 分钟自动触发一次增量扫描；紧凑面板不提供手动扫描
按钮，额度刷新不触发扫描。扫描开始时一次读取全部 `scan_files` 水位，避免为每个文件重复打开
SQLite 连接；未变化文件只读取一次短前缀做改写校验，不重新解析内容。发生增长、截断、mtime
变化、前缀变化或 cursor 失效时才进入增量／重扫路径。每个批次提交后主动让出线程时间片。

状态与扫描报告只包含：

- 已发现／已完成文件数；
- 已读取字节数；
- 已插入、重复、无效行数；
- 脱敏的失败文件数量；
- 当前来源；
- 是否取消、是否部分失败、开始与结束时刻。

不得包含绝对路径、文件名、原始行、标题、项目路径或系统错误原文。

## 6. 查询契约

本轮 Rust command：

```text
usage_scan_start
usage_scan_cancel
usage_scan_status
usage_get_summary
usage_list_conversations
usage_get_conversation
usage_reprice
usage_refresh_pricing_catalog
```

### 6.1 通用输入

- `from`／`to` 是可选 ISO 8601 UTC，范围为 `[from, to)`；`from >= to` 返回 `invalidUsageQuery`。
- `source`、`model`、`speed` 是可选精确筛选。字符串最大 200 字符；空字符串按未提供处理。
- 分页 `limit` 为 `1...200`，默认 `50`；`offset` 为 SQLite 可表示的非负 64 位整数，超出范围返回 `invalidUsageQuery`。
- SQL 只能使用固定语句与参数绑定，前端不能传列名、排序表达式或 SQL 片段。

### 6.2 汇总

`usage_get_summary` 按请求的 `day`、`source`、`model` 或 `speed` 维度分组，返回六个 Token
维度、总输入、总输出、总 Token、Fast 原始／计费等效 Token 与倍率范围、请求事件数、
已定价／未定价数与 API 等值费用。空库返回空 rows 和全零 totals，不返回错误。

### 6.3 Conversations

列表按 `last_at DESC, conversation_key ASC` 稳定排序，返回：

- conversation key、source；
- 可空 title 与 project hint；
- first／last time；
- 六个 Token 维度、总量；
- 已定价费用和未定价条数。

详情按 conversation key 精确查询；不存在返回 `null`，不把它视为系统错误。列表和详情都不返回原始消息正文或路径。

### 6.4 错误

command 只暴露稳定 code：

| code | 含义 |
|---|---|
| `invalidUsageQuery` | 输入范围、筛选或分页非法 |
| `usageUnavailable` | 数据库、目录或价格目录暂不可用 |
| `usageScanBusy` | 已有扫描正在运行 |

文件级解析错误进入扫描报告，不把路径或内部错误提升到 command。

## 7. 迁移与恢复

### 7.1 迁移

- `PRAGMA user_version` 大于当前版本：拒绝写入，返回 `usageUnavailable`；不得降级或覆盖。
- 版本小于当前版本：在单个事务内顺序迁移；失败整体回滚。
- `scan_files`、`usage_entries`、`conversations` 可由外部 JSONL 重建。
- `quota_events` 不可重建，任何迁移不得无备份 `DROP`。

### 7.2 损坏恢复

打开已有数据库先执行 `PRAGMA quick_check`。不为 `ok` 时：

1. 尽力只读导出 schema 可识别的 `quota_events`；
2. 关闭全部连接；
3. 将 `usage.db`、`usage.db-wal`、`usage.db-shm` 分别改名为同一 `.corrupt-<UTC>` 后缀，保留诊断证据；
4. 创建空 schema v2；
5. 恢复通过字段约束的额度事件；
6. 下次扫描重建派生表。

不得静默删除损坏数据库。恢复失败不能阻断额度主路径；用量 command 返回 `usageUnavailable`。

### 7.3 价格目录恢复

价格缓存损坏只影响在线补价，不影响 Token 索引或内置离线计价。保留损坏文件、恢复空 v2
缓存并合并内置目录后执行数据库重算；重算失败时 Token 查询仍可用，费用保持 `NULL` 或旧
fingerprint，不能伪装为最新价格。

## 8. 安全与测试门槛

- 数据库列名使用白名单测试；出现 access token、refresh token、cookie、api key、明文 email、account id、path、body、content 等非批准列即失败。
- 脱敏 Fixture 必须覆盖 Codex 累计值重复、service tier 切换、顶层／嵌套 Cache Write、
  Claude message 重复、缺失 speed、Cache Write aggregate／5m／1h 不一致、不同目录相同
  文件 stem、半行、截断、同尺寸改写、无效 Token、未知模型与空数据源。
- 测试必须证明：offset 不领先事务、取消后可续、唯一索引去重、价格更新不访问 JSONL、
  在线 Standard／Fast 解码、第三方过滤、缺失 cache 子价格为 `$0`、24 小时刷新、来源失败
  30 分钟退避与缺价冷却、active／pending 边界、缓存写入失败不发布、无关模型不重算、v1→v2
  迁移、Fast 等效倍率、整数费用无浮点漂移、损坏库保留并重建、绝对路径不进入 contract。
- 自动化验证必须按任务授权执行；Rust 定向验证通过也不能据此宣称 Vue、macOS／Windows
  实机、GitHub Release 或安装产物已验证。
