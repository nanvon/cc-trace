# CC Trace 测试策略

> 状态：首版基线
> 目标版本：`0.1.x`
> 基线日期：2026-07-25

本文件定义 CC Trace 首版的测试范围和最低门槛。2026-07-30 起首版加入本地用量、Conversations 元数据、额度历史与 Pricing；其 Rust 数据门槛由本文件纳入，Vue 展示仍待后续 UI 切片补充。

## 1. 原则

- 每个纵向切片同时完成 Rust 核心、command 契约、Vue 展示和对应测试，不把测试推到最后。
- 测试只使用 CC Trace 自己的脱敏 Fixture，见 [fixtures/README.md](../fixtures/README.md)，不把 Swift 版 cc-bar 的缓存文件作为输入。
- 本地用量测试不得扫描开发者真实 `~/.codex` 或 `~/.claude`；测试根目录必须显式指向临时目录中的脱敏 JSONL Fixture。
- 旧版测试只作为规则参考，不自动成为新应用的验收要求。
- 没有运行过的验证不得记为通过；平台相关结论必须标注验证平台。
- 未经用户要求不自动运行耗时构建、平台打包或实机测试。

## 2. Rust 单元测试

- Provider 响应解析与字段标准化。
- 额度窗口分类：主要额度与必要专项额度。
- token 续期与失效判定。
- 三维状态映射：活动、快照新鲜度、可用性／失败原因。
- 额度标准化：`remainingPercent` clamp、窗口 `kind` 判定、`unknown` 不被猜成已知窗口、reset 保留规则。
- 身份变化时丢弃旧快照、清除退避。
- token 刷新提前量、进程内单飞与刷新失败分类。
- 节流、429 退避、网络退避、`Retry-After` 解析，以及手动刷新不绕过退避。
- 快照序列化、反序列化与 `schemaVersion`。
- 原子写入、写入失败保留上一份有效文件、损坏恢复与重建。
- 首次启动完成标记的写入、缺失与写入失败处理。
- 日志脱敏：构造带 token 的凭据与响应，断言输出不含任何秘密；持有秘密的类型有 `Debug` 屏蔽测试。
- 日志轮转、保留数量与写入失败时的降级路径，见 [日志与诊断](日志与诊断.md) 第 7 节。
- 完整行 JSONL offset、末尾半行不消费、16 MiB 单行上限、2000 行／8 MiB 批次边界。
- 文件缩短、前缀变化、同尺寸改写、取消续扫，以及事务回滚时 offset 不领先 entries。
- Codex 累计 signature 去重、Claude message id 去重、不同目录相同 Claude 文件 stem、重复文件与流式完整生命周期。
- 六维 Token 标准化、不变量校验、推理输出不重复计数、未知模型与未知速度。
- SQLite schema 白名单、唯一索引、聚合、稳定分页、损坏文件组保留、可派生表重建与额度事件尽力恢复。
- 价格目录校验、整数 USD nanos、Fast／Priority 与地域倍率、未知价格为 `NULL`，以及重算不读取 JSONL。

## 3. Tauri 契约与集成测试

- 每个 command 的输入校验与返回契约。
- 事件载荷：`quota://updated`、`quota://refresh-state`、`settings://updated`、`navigation://main`。
- 三个状态维度在 command 边界独立序列化，没有被压成互斥枚举。
- 载荷不含 access token、refresh token、Cookie、凭据原文或本机绝对路径。
- capabilities 只包含已声明窗口与最小权限。
- 错误分类映射到可展示的 `AppError`，且 `no_credentials`、`rate_limited` 不被降级成普通 `error`。
- CC Trace 的数据目录、设置文件和安全存储 namespace 与 cc-bar 隔离。
- usage 查询的时间范围、筛选长度、分页边界与稳定错误码。
- 空库返回空结果；不存在的 conversation 返回 `null`；扫描进度、取消与部分失败载荷不含路径和原始内容。

## 4. Vue 与状态测试

- Pinia 状态由 command 返回值驱动，不通过空值推断状态。
- 覆盖 [状态与错误模型](状态与错误模型.md) 第 2 节组合矩阵的全部场景，包括“刷新中保留旧快照”。
- 单个 Provider 失败不影响另一个 Provider 的展示。
- 中文、英文与跟随系统语言；无硬编码语言、无死 key，两种语言下的错误文案完整。
- 时间与数字格式按 [文案与国际化](文案与国际化.md) 第 3 节，相对时间同时提供绝对值。
- 浅色、深色与跟随系统外观。
- 键盘路径、焦点顺序与 `Esc` 行为。
- 长账号名、长模型名和 200% 文字缩放不遮挡额度、重置时间与恢复动作。
- reduced motion 下不依赖持续旋转或位移表达刷新。
- 主窗口额度总览与设置视图同窗切换：外部入口落到正确视图、返回额度、焦点恢复、隐藏视图不进入 Tab 顺序。
- “打开 CC Trace”始终显示额度总览，不意外恢复上次停留的设置视图。
- 本地用量 Vue 展示尚未实现；实现时补从未扫描、扫描中、取消、部分失败、空数据、未知价格、数据库不可用和分页状态，不能把 Rust 契约测试记为页面已验证。

## 5. 平台验证

- macOS Menu Bar 与 Windows System Tray 的实机显示、主点击和原生菜单。
- 紧凑面板锚点、多显示器与不同缩放比例。
- 三个窗口的打开、重新打开、聚焦、关闭与单实例。
- 主窗口额度总览／设置同窗切换时，窗口尺寸和位置稳定，不创建第二个窗口。
- 关闭窗口与退出应用的区别。
- 开机自动启动。
- 应用数据目录、设置文件与系统安全存储。
- 新旧应用并行运行且互不影响。
- 安装、启动、卸载与 CC Trace 自身版本升级。

## 6. 业务结果对照

需要时使用相同的脱敏输入与 Swift 版 cc-bar 做只读对照，用于发现业务规则偏差：

- `QuotaSnapshot` 字段与额度窗口语义。
- Provider 错误分类边界。

差异必须区分为“新产品决策 / 新实现缺陷 / 旧版遗留行为”，不得因为对照而复刻旧版行为或读取旧缓存。

- 第 2 节全部项目有对应测试。
- 第 3 节的秘密不外泄与状态独立序列化有测试覆盖。
