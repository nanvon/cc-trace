# CC Trace 产品定义

> 状态：已确认
> 基线日期：2026-07-25

## 一句话定位

CC Trace 是一款面向使用 Codex 与 Claude Code 的开发者的跨平台桌面应用，让用户通过 macOS 菜单栏或 Windows 系统托盘，快速查看 AI 编程工具的额度、重置时间、刷新状态与异常风险。

## 目标用户

- 在个人电脑上使用 Codex、Claude Code，或同时使用两者的开发者。
- 希望快速判断额度是否紧张，而不想频繁打开 Provider 网页或执行诊断命令的用户。
- 需要 macOS 与 Windows 上具备一致核心能力的用户。

首版以单机、单用户、本机凭据自动发现为前提，不面向团队配额管理、云端账号中心或企业审计。

## 首要用户任务

### 1. 快速判断额度风险

用户从菜单栏或系统托盘打开 CC Trace 后，立即知道 Codex、Claude Code 哪个 Provider 接近额度限制。

### 2. 理解额度状态

用户能看清剩余额度、重置时间、最近刷新时间，以及数据当前属于 `live`、`stale`、`offline`、`loading` 还是 `error`。

### 3. 可靠地刷新与恢复

用户可以手动或自动刷新额度。网络失败、单个 Provider 异常或触发 429 时，应用保留上一份有效快照，并且一个 Provider 的失败不影响另一个 Provider。

## 产品关系

CC Trace 是独立于 Swift 版 cc-bar 的新产品：

- 使用独立仓库、应用标识、数据目录、缓存、版本和发布体系。
- 不作为 cc-bar 的原地升级，不读取、迁移、覆盖或删除 cc-bar 的应用数据。
- 可以只读访问 Codex、Claude Code 自身的凭据与 Provider 接口。
- cc-bar 源码仅用于核对已经验证的业务事实、错误边界、Fixture 和平台经验。
- 不复制 Swift、SwiftUI、AppKit 工程或旧页面结构。

开发与验收期间，CC Trace 与 cc-bar 必须能够在同一台机器上独立安装和运行。

## 体验原则

- 风险优先：最紧张的额度和异常状态优先于完整数据陈列。
- 快速可读：打开紧凑入口后无需进一步导航即可完成主要判断。
- 状态诚实：明确区分实时数据、旧快照、离线和错误，不用旧数据伪装成功。
- 平台得体：macOS 与 Windows 完成相同核心任务，但遵循各自系统区域和窗口习惯。
- 权限克制：只申请首版能力真正需要的权限，秘密不进入 Vue 层或普通日志。
- 渐进扩展：首版验证额度监控闭环，后续能力按独立价值和真实需求进入产品。

## 产品非目标

CC Trace 首版不是：

- 通用 AI 聊天客户端。
- Provider 登录器或账号注册工具。
- 团队配额、组织账单或云端管理后台。
- Swift 版 cc-bar 的页面复刻或数据迁移工具。
- 本地对话浏览器、Token 统计器或费用分析工具。
- Provider 网站的 WebView 包装或抓取工具。

具体功能边界、数据来源和验收标准见 [产品范围](产品范围.md)。
