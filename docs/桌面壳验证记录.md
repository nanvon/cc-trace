## 实现范围

当前实现验证桌面壳与完整状态模型，不接入任何 Provider：

- Rust 创建并持有 Tray Icon 与原生菜单，菜单文案随语言设置重建。
- Rust 管理四个窗口的显示、聚焦、隐藏、锚定与退出。
- **三维状态契约已是最终形态**：活动、快照新鲜度、可用性各自独立序列化。
- 刷新编排、请求合并、30 秒节流、429 与网络退避使用真实实现，参数取自
  [技术架构](技术架构.md) 首版参数基线。
- 额度数据来自 `providers::synthetic`，走与真实 Provider 完全相同的路径，
  见 [ADR-0009](决策/ADR-0009-合成数据下沉Rust并提前使用正式契约.md)。
- `settings.json` 已持久化：语言、外观、刷新间隔、开机启动、首次启动完成标记，
  见 [ADR-0010](决策/ADR-0010-最小设置持久化提前落地.md)。
- 不读取凭据、外部日志、旧 cc-bar 数据或真实额度。
- 不创建额度缓存 `quota-cache.json`，不创建日志系统。

debug 构建提供 `dev_set_scenario` 与主窗口底部的场景切换器，覆盖 9 个验证场景；
release 构建里两者都不存在。

## 系统入口

### macOS

- 使用 `ActivationPolicy::Accessory`，不占用 Dock。
- 使用 CC Trace Tray Symbol 的 RGBA 模板图标，随 Menu Bar 外观着色。
- 左键松开时打开／关闭紧凑窗口，带 250ms 去抖。
- 紧凑窗口按 Tray 点击位置定位，并在当前显示器工作区内约束。
- 失焦时自动隐藏紧凑窗口。
- 右键显示原生菜单。
- 紧凑面板使用透明窗口 + `popover` 材质 + 16px 圆角（需要 `macos-private-api`）。

### Windows

- 使用应用 Bundle Icon 作为 System Tray 图标。
- 使用与 macOS 相同的左键紧凑入口语义与去抖。
- 使用右键原生菜单。
- 紧凑窗口定位到 Tray 点击点上方，并约束在当前显示器工作区。
- 紧凑面板是透明窗口但不套材质，内容层实色；`windowEffects` 的 `popover` 在
  Windows 被忽略。**WebView2 下透明窗口的对比度与性能未验证**，若表现不佳需要
  回退为不透明外壳并记录。

Windows 分支只做过条件编译，没有 Windows 主机，因此不得标记为实机通过。

## 主点击去抖

点击系统区域图标时，紧凑面板会先失焦（从而隐藏），随后 tray 的点击事件才到达。
只看 `is_visible()` 会让第二次点击变成「隐藏后立刻重新显示」，表现为面板关不掉。

当前实现记录最近一次隐藏时刻，250ms 内的点击一律视为「关闭」。这是必须重点回归的
交互：**连续点击图标 5 次，面板应当开、关、开、关、开**。

## 窗口策略

| 窗口 | 初始状态 | 关键行为 |
|---|---|---|
| `compact` | 隐藏 | 无装饰、透明、不可缩放、置顶、不进任务栏、失焦隐藏、`Esc` 关闭 |
| `main` | 隐藏 | 打开已存在实例并聚焦；关闭时隐藏，进程继续驻留 |
| `settings` | 隐藏 | 同上 |
| `onboarding` | 隐藏 | 仅在完成标记缺失时启动打开；完成后隐藏并打开紧凑面板 |

四个窗口都由配置预创建，重复操作不会创建第二个实例。进程级单实例由
`tauri-plugin-single-instance` 保证：二次启动聚焦已有实例的紧凑面板。

## 键盘

快捷键在前端统一处理 `metaKey || ctrlKey`，因此业务代码不做平台判断：

| 快捷键 | 行为 |
|---|---|
| `Esc` | 关闭紧凑面板（仅紧凑面板） |
| `⌘R` / `Ctrl+R` | 刷新全部额度 |
| `⌘,` / `Ctrl+,` | 打开设置窗口 |
| `⌘W` / `Ctrl+W` | 关闭当前窗口，应用继续驻留 |
| `⌘Q` / `Ctrl+Q` | 退出应用 |

因为是 Accessory 应用，没有应用菜单栏，快捷键只在某个窗口聚焦时生效。这符合菜单栏
应用的常见范式，但需要在实机确认没有与系统快捷键冲突。
