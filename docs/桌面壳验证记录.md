## 系统入口

### macOS

- 与 Swift 版 cc-bar（`../cc-bar/Main/MainWindowRootView.swift`、`AppDelegate.swift`）一致的动态 `ActivationPolicy`：启动时是 `Accessory`（不出现在 Dock，纯 Menu Bar / Tray 应用）；主窗口显示期间临时切到 `Regular`（出现在 Dock、可被 Cmd+Tab 切到），主窗口隐藏（含关闭即隐藏）时切回 `Accessory`。紧凑面板与引导窗口不参与这个切换。当前代码已落地，macOS 27 日常使用验证（2026-08-10），Windows 未验证。
- 常驻 `Regular` 曾导致的问题：主窗口打开但停留在背景时，点击状态栏图标触发的系统级应用激活会把它连带顶到最前；改成动态策略后，主窗口不在前台时应用本身也不是 `Regular`，不会被系统一并提到最前。
- 使用 CC Trace Tray Symbol 的 RGBA 模板图标，随 Menu Bar 外观着色。
- 左键松开时打开／关闭紧凑窗口，带 250ms 去抖。
- 紧凑窗口按 Tray **图标矩形**（不是光标位置）定位到图标正下方，并在锚点所在显示器的
  工作区内约束。坐标全程用逻辑点，见下方 2026-07-28 的实机发现。
- 失焦时自动隐藏紧凑窗口。
- 右键显示原生菜单。
- 紧凑面板使用透明窗口 + `popover` 材质 + 16px 圆角（需要 `macos-private-api`）。
- macOS 27 起行为分叉：状态栏图标不再绑定 `NSMenu`（绑定后系统接管左键，tray-icon
  的点击回调收不到事件）。运行时探测到 `expandedInterfaceDelegate:`（macOS 27 Beta
  API）时改由 expanded interface session 管理左键的展开与收起，右键菜单由 local
  monitor 弹出未绑定菜单；macOS 26 及以下与 Windows 保持原路径。实现与理由见
  `src-tauri/src/platform/macos_status_item.rs` 与 `tray.rs` 的 `install`。

### Windows

- 使用应用 Bundle Icon 作为 System Tray 图标。
- 使用与 macOS 相同的左键紧凑入口语义与去抖。
- 使用右键原生菜单。
- 紧凑窗口定位到 Tray **图标矩形**上方，并约束在锚点所在显示器工作区。坐标沿用物理
  像素：Windows 的物理坐标是真实像素，全程可比，不需要 macOS 那套逻辑点换算。
- 紧凑面板是透明窗口但不套材质，内容层实色；`windowEffects` 的 `popover` 在
  Windows 被忽略。**WebView2 下透明窗口的对比度与性能未验证**，若表现不佳需要
  回退为不透明外壳并记录。

Windows 分支只做过条件编译，没有 Windows 主机，因此不得标记为实机通过。

## 主点击去抖

点击系统区域图标时，紧凑面板会先失焦（从而隐藏），随后 tray 的点击事件才到达。
只看 `is_visible()` 会让第二次点击变成「隐藏后立刻重新显示」，表现为面板关不掉。

当前实现记录最近一次隐藏时刻，250ms 内的点击一律视为「关闭」。这是必须重点回归的
交互：**连续点击图标 5 次，面板应当开、关、开、关、开**。

## 窗口策略

| 窗口 | 初始状态 | 关键行为 |
|---|---|---|
| `compact` | 隐藏 | 无装饰、透明、不可缩放、置顶、不进任务栏、失焦隐藏、`Esc` 关闭 |
| `main` | 隐藏 | 额度与设置同窗切换；打开已存在实例并聚焦；关闭时隐藏，进程继续驻留；显示时 macOS 切到 `Regular`，隐藏时切回 `Accessory` |
| `onboarding` | 隐藏 | 仅在完成标记缺失时启动打开；完成后隐藏并打开紧凑面板 |

三个窗口都由配置预创建，重复操作不会创建第二个实例。进程级单实例由
`tauri-plugin-single-instance` 保证：首次启动未完成时二次启动聚焦引导；完成后聚焦主窗口默认视图（按 [ADR-0020](决策/ADR-0020-主窗口改为本地用量页.md) 已是用量页；下方走查记录写于该 ADR 之前，当时该视图是额度总览）。

## 键盘

快捷键在前端统一处理 `metaKey || ctrlKey`，因此业务代码不做平台判断：

| 快捷键 | 行为 |
|---|---|
| `Esc` | 关闭紧凑面板（仅紧凑面板） |
| `⌘R` / `Ctrl+R` | 刷新全部额度 |
| `⌘,` / `Ctrl+,` | 聚焦主窗口并打开设置视图 |
| `⌘W` / `Ctrl+W` | 关闭当前窗口，应用继续驻留 |
| `⌘Q` / `Ctrl+Q` | 退出应用 |

系统应用菜单与 Dock 入口只在主窗口显示期间出现（见上文动态 `ActivationPolicy`）；
窗口内快捷键仍由前端统一处理，只在对应窗口聚焦时生效。该行为需要在 macOS 实机走查中确认。

### macOS 27 Expanded Interface Session 专项（2026-08-09 新增）

上方通用项在 macOS 27 下走的是另一条路径：左键由系统管理 expanded interface

### 钥匙串授权

**每次重新编译后都会重新要求授权**（2026-07-27 发现）。dev 构建是 adhoc 签名，没有稳定签名标识，钥匙串 ACL 只能按 CDHash 记录授权对象，而 CDHash 随二进制内容变化。详见 [ADR-0013](决策/ADR-0013-macOS读取ClaudeCode钥匙串凭据.md) 的实机记录。

**2026-07-28 已解决。** `scripts/dev-sign.sh` 作为 cargo runner 在启动前用固定身份重签，签名标识钉死成 `tauri.conf.json` 的 `identifier`。实测授权一次后重新编译不再弹窗。用的是免费 Apple ID 的 Apple Development 证书而非原计划的自签名证书——后者的 designated requirement 绑定证书指纹，换证书即失效，见 [ADR-0016](决策/ADR-0016-不购买Apple开发者账号.md) 的 2026-07-28 修订。

Release workflow 使用 ad-hoc 签名且不上传个人证书。后者的 CDHash 会随版本变化，因此安装
新版本后首次访问钥匙串可能需要再次选择「始终允许」；这是已接受的发布代价，实际安装包仍
需在对应架构真机验证。

状态实机复核。

## 实机发现（macOS，2026-07-28）：紧凑面板锚点

来自真实运行的结论，不是自动化检查结果。

### 症状

面板不在菜单栏图标正下方；在外接显示器点击图标时，面板落到主屏而不是外接屏。

### 根因：macOS 上 Tauri 的「物理坐标」不是统一坐标系

macOS 上 Tauri／tao 的 physical 值实际是「逻辑点 × **被问对象自己的** scale factor」。
定位链上四个环节各按各的算，单显示器时 scale 相同、恰好互相抵消，多显示器（尤其
混合 Retina 与 1x）立刻散架：

| 环节 | 实际含义 |
|---|---|
| tray 事件的 `position` / `rect` | 逻辑点 × **托盘所在屏**的 scale |
| `monitor_from_point(x, y)` | 参数直接与**纯逻辑**的显示器边界比较，不做任何换算 |
| `monitor.work_area()` | 逻辑点 × **该显示器**的 scale |
| `set_position(Physical)` | 除以**窗口当前所在屏**的 scale 后当逻辑点用 |

最后一条是「跑回主屏」的直接原因：面板上次停在 2x 主屏，为 1x 外接屏算出的坐标被
除以 2，正好落回主屏中部。

同时锚点取的是事件里的 `position`（光标位置）而非 `rect`（图标矩形），面板水平位置
跟着「点中图标的哪个像素」漂移，顶边还会压进菜单栏。

### 处理

`platform/desktop.rs` 引入 `Anchor` 与 `to_anchor_space()`：macOS 全程换算成逻辑点，
最后用 `Position::Logical` 输出；Windows 恒等，保持物理像素。锚点改用图标矩形。

`tray-icon` 只给出按托盘所在屏换算后的矩形，**不告诉我们是哪块屏**，且数值区间无法
区分——逻辑 x=2500 在 1x 屏上是 2500，按 2x 反推出的 1250 同样落在主屏范围内。因此
`tray_rect_scale()` 从图标高度反推：菜单栏厚度是全系统统一的逻辑值（现代 macOS 为
24pt），Mac 的 backing scale factor 只有 1 或 2。这个前提如果哪天不成立，退化结果是
回到修复前的行为。

### 已验证

macOS 内建 Retina 2x + 1x 外接（混合缩放，scale 反推的两个分支都走到）：

- 面板落在菜单栏图标正下方。
- 在哪块屏点击就在哪块屏打开，不再跑回主屏。
- 额度刷新导致面板高度变化后，位置仍锚在图标下。

**Windows 全部未验证。** 那边的物理坐标是真实像素，换算路径是恒等的，改动只多了
「锚定图标中心而非光标」这一项，但没有 Windows 主机，不得标记为通过。
