# CC Trace 日志与诊断

> 状态：首版基线
> 目标版本：`0.1.x`
> 基线日期：2026-07-25

本文件是 CC Trace 日志位置、级别、格式、轮转和脱敏规则的唯一来源。数据目录与持久化策略见 [技术架构](技术架构.md)；凭据边界见 [额度领域模型](额度领域模型.md) 第 5 节。

## 1. 首版范围

- 只写本地文件日志，供开发与用户主动排查使用。
- 不做远程上报、不做崩溃收集、不做匿名统计。
- 不提供应用内日志查看器、日志导出按钮或诊断面板。
- 设置窗口的“关于”只提供数据与隐私边界的简短说明，不展示日志内容。

高级诊断与隐私模式属于后续版本评估项，见 [产品范围](产品范围.md)。

## 2. 位置与轮转

| 项 | 首版值 |
|---|---|
| 位置 | CC Trace 数据目录下的 `logs/` |
| 文件名 | `cc-trace.log`，轮转文件加序号后缀 |
| 单文件上限 | `1 MB` |
| 保留数量 | 最近 `3` 个文件 |
| 总占用上限 | 约 `4 MB` |
| 清理 | 超出保留数量时删除最旧文件，不做压缩归档 |

规则：

- 日志目录不存在时创建；创建失败不得阻断应用启动，降级为不写日志。
- 写日志失败不得反复重试导致刷新阻塞。
- 不写入任何 cc-bar 的目录，也不读取 cc-bar 的日志。

## 3. 级别

| 级别 | 用途 | 默认 |
|---|---|---|
| `error` | 功能失败且用户可感知：Provider 请求失败、设置写入失败、缓存损坏 | 开启 |
| `warn` | 已自动降级的异常：快照被判定为过期、退避生效、字段缺失回退 | 开启 |
| `info` | 关键生命周期：启动、退出、刷新开始与结束、设置变更、身份变化 | 开启 |
| `debug` | 排查细节：调度时序、窗口解析中间结果 | 关闭 |

`debug` 只能通过环境变量在开发或用户主动排查时开启，不提供界面开关。首版没有 `trace` 级别。

## 4. 格式

单行结构化文本，字段之间不换行，便于 `grep`：

```text
<ISO 8601 UTC 时间戳> <级别> <模块> <事件名> key=value key=value
```

- 时间戳统一 UTC，与界面展示的本地时间刻意不同，避免时区歧义。
- 模块使用 Rust 内部模块名：`providers`、`scheduler`、`storage`、`platform`、`commands`。
- 事件名使用稳定的英文小写下划线标识，便于跨版本检索；日志不做本地化。
- 字段值包含空格时加引号；不输出多行 JSON、不输出堆栈以外的大段文本。

## 5. 脱敏

### 5.1 永不记录

- access token、refresh token、id token、Personal Access Token。
- `Authorization` 头、Cookie、CSRF token、任何请求头原文。
- 凭据文件的内容、片段或哈希。
- 完整邮箱、account id、user id、订阅标识。
- Provider 请求体与响应体原文。
- 本机绝对路径与用户名。

以上内容也不得出现在错误信息、`Debug` 输出、panic 消息和事件字段里。为 Rust 类型实现 `Debug` 时必须手动屏蔽秘密字段，不使用 `#[derive(Debug)]` 直接暴露持有 token 的结构。

### 5.2 可以记录

- Provider 标识：`codex`、`claude`。
- 内部失败原因枚举与 HTTP 状态码。
- 重试次数、退避秒数、`Retry-After` 秒数。
- 快照年龄、窗口 `kind`、窗口数量。
- 身份是否发生变化（布尔），不记录变化前后的值。
- 凭据来源的语义名，例如 `codex_auth_file`、`claude_credentials_file`，不记录真实路径。

### 5.3 判定规则

拿不准某个字段能不能记时，按“它是否能帮助定位问题”和“它是否能识别到人或账号”两项判断：两者都成立时也不记录，改为记录它的分类或布尔特征。

## 6. 与状态模型的关系

- 日志级别不代表用户可见状态：`no_credentials` 是正常状态，记 `info`，不记 `error`。
- 退避生效记 `warn`，退避期内被拦截的手动刷新记 `info`，不记 `error`。
- 每次刷新只记开始与结束两条 `info`，不为每个窗口逐条记录。
- 用户可见文案不从日志文本派生，见 [文案与国际化](文案与国际化.md) 第 4 节。

## 7. 测试要求

- 日志脱敏必须有单元测试：构造带 token 的凭据与响应，断言输出中不含任何秘密。
- 持有秘密的类型必须有 `Debug` 屏蔽测试。
- 轮转与保留数量必须有测试，包括写入失败时的降级路径。

以上并入 [测试策略](测试策略.md) 第 2、3 节。
