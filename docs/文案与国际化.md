# CC Trace 文案与国际化

> 状态：首版基线
> 目标版本：`0.1.x`
> 基线日期：2026-07-25

本文件是 CC Trace 文案组织方式、i18n key 规范、时间与数字格式，以及错误文案目录的唯一来源。文案语气原则见 [设计方向与状态规范](设计方向与状态规范.md) 第 7.4 节；状态语义见 [状态与错误模型](状态与错误模型.md)。

## 1. 语言范围

| 项 | 首版 |
|---|---|
| 支持语言 | 简体中文 `zh-CN`、英文 `en` |
| 默认 | 跟随系统 |
| 用户可选 | 跟随系统、中文、English |
| 回退 | 缺失 key 回退到 `en`，不显示 key 名 |

规则：

- “跟随系统”的系统语言由 Rust 平台层提供并随设置一起下发，不在 Vue 里读 `navigator.language`。
- 语言选择保存在 CC Trace 自己的设置文件，切换后立即生效，不需要重启。
- 只有这两种语言进入首版；不为其他语言预留空文件。
- 所有用户可见字符串都必须来自 i18n，不允许在组件里硬编码任何一种语言。

### 1.1 实现位置

- 文案：`src/i18n/locales/zh-CN.ts` 与 `src/i18n/locales/en.ts`，两份 key 完全一致。
- 语言判定：`resolveLocale()`（`src/i18n/index.ts`）是唯一一处，输入是设置值与 Rust 下发的系统语言。
- 原生托盘菜单由 Rust 创建，无法走 Vue I18n，因此有一份等价物在 `src-tauri/src/platform/strings.rs`；它与 `locales/*` 的同名 key 必须同时修改。
- 切换语言时同步 `document.documentElement.lang`，并重建托盘菜单。

`preview.*` 命名空间只服务桌面壳的合成数据标注，Provider 接入时整块删除。

## 2. key 规范

按**表面**划分顶层命名空间，第二层按语义分组，键名用小驼峰：

```text
common      通用动作与词汇：refresh、settings、quit、retry、close、details
provider     Provider 名称与身份提示
quota        额度窗口、剩余、重置相关标签
status       状态词：live、stale、offline、rateLimited、loading
error        错误标题、影响与下一步，见第 4 节
compact      紧凑面板专属文案
main         主窗口用量页专属文案
settings     主窗口设置视图专属文案
onboarding   首次启动专属文案
a11y         纯无障碍文本：aria-label、屏幕阅读器说明
```

硬规则：

- **按语义命名，不按位置命名。** 用 `common.refresh`，不用 `compact.button1`。
- **不拼接句子。** 一条完整句子是一个 key；需要变量时用命名参数：`quota.resetsAt: "{time} 重置"`。
- 复数与计数使用 vue-i18n 的复数形式，不用 `if (n > 1)` 拼字符串。
- 状态词不写进句子模板里；句子引用状态 key，保证状态词只有一处译法。
- 同一概念只有一个 key：`refresh` 不允许同时存在 `refreshAll`、`doRefresh`、`refreshNow` 三个近义 key。
- 一个 key 只有一种语气，不因为出现在两个表面就复制两份。
- 删除功能时同时删除它的 key，不留死 key。
- 价格目录动作使用 `settings.pricingCatalog*`：按钮必须区分更新、更新中、成功和失败；
  还必须区分部分更新；部分更新与失败文案都必须说明未更新部分继续使用旧目录，不能只写“发生错误”。

## 3. 时间与数字格式

### 3.1 数据形态

- Rust 下发的所有时刻是 ISO 8601 UTC 字符串，展示层负责本地化。
- 需要按语言变化的格式统一使用 `Intl.DateTimeFormat` 与 `Intl.NumberFormat`，locale 取当前界面语言。
- 界面一律显示**本地时区**，不显示 UTC 标记，不做时区选择。
- **例外：紧凑时长**（`6d2h`、`1h42m`）刻意语言中立，`Intl` 也产不出这种形态。唯一实现是
  `src/lib/format.ts` 的 `compactDuration`，见 [ADR-0019](决策/ADR-0019-读数位改用定宽短码与紧凑倒计时.md)。
  它只用在定宽读数位；提示条里的解释句继续用 `Intl` 的自然语言。

### 3.2 格式规则

| 内容 | 规则 | 中文示例 | 英文示例 |
|---|---|---|---|
| 剩余百分比 | 整数，四舍五入，`tabular-nums`；大于 0 但不足 1 显示 `<1%`。大读数把数字与 `%` 分设字号 | `37%` | `37%` |
| 重置时刻 | 读数位用紧凑倒计时，最长 6 个字符；绝对时刻退到 `title` 与无障碍名称 | `6d2h`、`1h42m`，下方标签「重置」 | 同左，标签为 `reset` |
| 最近成功刷新 | 紧凑时长加「前已刷新」；不足 1 分钟说「刚刚已刷新」 | `1m 前已刷新`、`刚刚已刷新` | `refreshed 1m ago`、`refreshed just now` |
| 可再次尝试 | 相对倒计时，精度到分钟；不足 1 分钟显示 `不到 1 分钟` | `4 分钟后可再试` | `retry in 4 min` |
| 提示条里的数据新鲜度 | 自然语言相对时间，超过 24 小时改绝对日期 | `5 分钟前`、`7月24日` | `5 min ago`、`Jul 24` |
| 窗口长度 | 读数位用语言中立的大写短码；完整窗口名进 `title` 与无障碍名称 | 读数位 `5HOUR`、`WEEKLY`、`ALL`；完整名 `5 小时窗口` | 读数位同左；完整名 `5-hour window` |
| API 等值费用 | USD nanos 用 `Intl.NumberFormat`；紧凑读数取整，`0 < value < $1` 显示 `<$1`；完整金额进 `title` 与无障碍名称 | `今日 <$1`、`本周 $12` | `today <$1`、`this week $12` |
| 用量页金额 | 保留两位小数；`0 < value < $0.01` 显示 `<$0.01`；价格目录未覆盖显示「未定价」，两者不得互相替代 | `$128.40`、`<$0.01`、`未定价` | `$128.40`、`<$0.01`、`Unpriced` |
| Token 数量 | 中文用万／亿，英文用 `K`／`M`／`B`；紧凑数值四舍五入为整数，不显示小数位；完整整数通过 `title` 与无障碍名称提供；`tabular-nums` | `6644万`、`12亿` | `66M`、`1B` |
| 缓存命中率 | 一位小数百分比；输入为 `0` 时显示 `—`，不写 `0%` | `84.0%`、`—` | 同左 |

紧凑时长与短码为什么是这个形态，见 [ADR-0019](决策/ADR-0019-读数位改用定宽短码与紧凑倒计时.md)：
读数位定宽是它们存在的理由，会随日期变宽的读数在 380px 面板里没有可预测布局。

补充规则：

- 所有会变化的数字使用 `font-variant-numeric: tabular-nums`，宽度不得随刷新跳动。
  刻意**不换字体族**——等宽字体族更宽，还会让中英文混排字形错位。
- 相对时间必须同时提供绝对值：通过 `title` 或 `aria-label` 暴露完整本地时间。紧凑倒计时
  对屏幕阅读器没有意义，因此它的 `aria-label` 就是带绝对时刻的完整说法。
- 相对时间不做秒级自动跳字。倒计时按分钟推进（`src/lib/useNow.ts`），不随刷新周期才更新。
- `resetsAt` 缺失时读数位显示 `—`，旁边的「重置」标签仍在；完整说明「重置时间未知」
  由 `title` 与 `aria-label` 承担，不猜测取值。
- 语言中立的短码不进 i18n，两种语言共用同一套；它们永远是大写拉丁字母，因此字距不随
  界面语言归零。
- 中文数字与单位之间不加空格，英文加空格。紧凑时长内部无空格也无单位词。
- Token 数量单位（万／亿、`K`／`M`／`B`）字号小于数值并弱化，使表格里的数字列仍能按位对齐；
  单位不能是这个量级的唯一载体，完整数值通过 `title` 与无障碍名称提供。
- 「未定价」是价格目录未覆盖，`<$0.01` 是已定价但金额极小。两者语义不同，不得合并写法，
  也不得任一显示为 `$0.00`，见 [数据存储与用量索引](数据存储与用量索引.md) 第 3 节。
- `$0` 只用于已完成扫描后的真实空结果；存在已定价记录时显示当前可计算金额，不追加 `+`；
  未扫描、全部未定价或读取失败显示 `—`。扫描中保留上一份完成结果。
- Popover 第一行显示今日／本周及金额，第二行只显示“花费 / Cost”；不增加“API 等值”、
  “扫描中”“含未定价”等状态说明。完整金额与“不代表订阅实付”的边界保留在 Tooltip 与
  无障碍说明中。

## 4. 错误与状态文案目录

下表是首版必须覆盖的全集，与 [状态与错误模型](状态与错误模型.md) 第 4 节一一对应。

紧凑面板用一行短说明。

> 待确认：**标题 / 影响 / 下一步**三级结构原本由主窗口承担，该分工已随
> [ADR-0020](决策/ADR-0020-主窗口改为本地用量页.md) 失效——主窗口不再显示额度。倾向让紧凑面板的
> 异常 Provider 可展开来承接。未解决前，下表的「下一步」列没有展示位置，
> [产品范围](产品范围.md) 首版完成标准中的错误状态完整性不成立。

| 状态 | 中文标题 | 中文下一步 | English title | English next step |
|---|---|---|---|---|
| `loading` + 无快照 | 正在检查额度 | — | Checking quota | — |
| `refreshing` + 有快照 | 正在刷新，显示上一份数据 | — | Refreshing, showing last data | — |
| `live` | 额度状态正常 | — | Quota is healthy | — |
| `stale` | 显示的是旧数据 | 刷新以获取最新额度 | Showing older data | Refresh to get the latest quota |
| `no_credentials` | 未发现可用凭据 | 在对应 CLI 登录后刷新 | No credentials found | Sign in with the CLI, then refresh |
| `unsupported` | 凭据形式暂不支持 | 首版只支持自动发现的 OAuth 凭据 | Credential type not supported | This release supports auto-discovered OAuth credentials only |
| `offline` + 有快照 | 当前离线，显示旧数据 | 网络恢复后刷新 | Offline, showing older data | Refresh once you are back online |
| `offline` + 无快照 | 当前离线，没有可显示的额度 | 检查网络后重试 | Offline, no quota to show | Check your connection and retry |
| `rate_limited` | 刷新受限 | 冷却结束后可再次刷新 | Refresh rate-limited | You can refresh again after the cooldown |
| `error` 凭据类 | 凭据已失效 | 在对应 CLI 重新登录 | Credentials are no longer valid | Sign in again with the CLI |
| `error` 协议类 | 无法读取额度数据 | 稍后重试；持续出现请更新 CC Trace | Could not read quota data | Try again later; update CC Trace if it persists |

“影响”一句由状态与数据组合决定，例如“Codex 额度仍可查看，Claude Code 显示的是 2 小时前的数据”。它必须说明**用户实际损失了什么**，不重复标题。

### 4.1 文案禁止事项

- 不道歉，不写“抱歉”“很遗憾”。
- 不用“未知错误”“出错了”作为最终解释。
- 不暴露 Rust 枚举名、HTTP 状态码原文、请求头、文件绝对路径、token 或邮箱。
- 不用感叹号，不用营销语气，不用“智能”“无缝”“强大”这类空词。
- 不把技术动作当用户动作：写“在 Codex CLI 登录”，不写“刷新 OAuth token”。
- 紧凑面板的收起态只有一行；完整解释的位置待确认，见第 4 节。
- 不用“请稍后重试”作为唯一下一步，除非确实没有别的可执行动作。

## 5. 无障碍文本

- 图标按钮必须有 `a11y.*` 下的可访问名称，不依赖 Tooltip。
- 进度轨道提供文本等价：无可用额度时读作“无可用额度”，不读成 `0%`。
- 状态变化通过节制的 `aria-live` 区域播报；不重复播报无变化的刷新结果。
- 长账号名与长模型名单行省略时，完整值必须可被辅助技术获取。

## 6. 翻译与验收

- 中文与英文同时提交，不允许只写一种语言就合并。
- 英文使用句首大写，不使用全大写标签（除已确认的极短稳定标签）。
- 每个新增 key 必须在两种语言下检查：长度、换行、是否遮挡额度与恢复动作。
- 200% 文字缩放下第 4 节全部文案必须仍然完整可读，见 [测试策略](测试策略.md) 第 4 节。
