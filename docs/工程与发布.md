# CC Trace 工程与发布

> 状态：首版基线
> 目标版本：`0.1.x`
> 基线日期：2026-07-25

本文件是 CC Trace 本地环境、常用命令、CI 基线、版本规则和发布流程的唯一来源。技术选型与分层见 [技术架构](技术架构.md)；测试内容见 [测试策略](测试策略.md)。

## 1. 本地环境

| 依赖 | 要求 |
|---|---|
| Node.js | 22 或更高 |
| pnpm | 11（`packageManager` 已固定具体版本） |
| Rust | 当前稳定工具链 |
| 平台依赖 | 见 [Tauri prerequisites](https://v2.tauri.app/start/prerequisites/) |
| 最低运行平台 | macOS 13、Windows 10 22H2（系统 WebView2） |

最低平台版本目前只写在文档里，`src-tauri/tauri.conf.json` 尚未声明 `minimumSystemVersion` 与 WebView2 安装策略，属待补配置。

## 2. 常用命令

| 命令 | 作用 |
|---|---|
| `pnpm install` | 安装前端依赖 |
| `pnpm dev` | 只启动 Vite，用于纯前端调试 |
| `pnpm tauri dev` | 启动桌面应用开发模式 |
| `pnpm build` | `vue-tsc --noEmit` + `vite build` |
| `pnpm tauri build` | 构建平台产物 |
| `cargo check` | Rust 编译检查（在 `src-tauri/` 下执行） |
| `cargo clippy --all-targets -- -D warnings` | Rust lint |
| `cargo fmt --check` | Rust 格式检查 |
| `cargo test` | Rust 测试 |

AI 未经用户要求不运行以上任何命令，见 `AGENTS.md`。

## 3. CI 基线

首版 CI 只保证“代码能编译、类型正确、格式与 lint 通过、测试通过”，不承担打包与发布。

| 项 | 首版值 |
|---|---|
| 平台 | GitHub Actions |
| 触发 | 向 `main` 的 push 与 pull request，以及手动触发 |
| 运行环境 | `macos-latest` 与 `windows-latest` 两个 job |
| 前端步骤 | `pnpm install --frozen-lockfile` → `pnpm build` |
| Rust 步骤 | `cargo fmt --check` → `cargo clippy --all-targets -- -D warnings` → `cargo test` |
| 缓存 | pnpm store、Cargo registry 与 `target/` |
| 失败策略 | 任一 job 失败即失败；两个平台都必须通过 |

CI 明确不做：

- 不执行 `tauri build`、不产出安装包、不签名、不公证、不创建 Release。
- 不发起任何真实 Provider 请求，也不注入凭据；Provider 相关测试只用脱敏 Fixture。
- 不依赖相邻的 `../cc-bar` 仓库存在。
- 不运行需要真实桌面会话的 Tray、窗口或多显示器验证；这些属人工实机验证，见 [桌面壳验证记录](桌面壳验证记录.md)。

CI 配置尚未建立（`.github/` 目录不存在），对应执行清单第 10 阶段的两个未完成项。

## 4. 版本规则

- 开发阶段使用 `0.x`，首个正式版为 `1.0.0`。
- 版本号在三处出现且必须完全一致：`package.json`、`src-tauri/Cargo.toml`、`src-tauri/tauri.conf.json`。当前三处均为 `0.1.0`。
- 改版本号时三处一起改；CI 应在后续加入一致性检查。
- 持久化数据的 `schemaVersion` 与应用版本相互独立，不跟随版本号变化，见 [技术架构](技术架构.md)。

## 5. 发布边界

- macOS 签名与公证、Windows 代码签名、安装器与自动更新在公开分发前单独设计与验收，不进入首版开发流程。
- macOS 与 Windows 分别构建平台产物，不做跨平台交叉打包假设。
- 首版发布说明必须明确：CC Trace 不是 Swift 版 cc-bar 的无损升级，不迁移旧设置、缓存与账号，也不会自动卸载或清理旧应用，见 [ADR-0003](决策/ADR-0003-独立应用身份不迁移数据.md)。
- 旧 cc-bar 的维护或归档计划在 CC Trace 发布之后再决定。

## 6. 发布检查单

首个公开版本发布前逐项确认：

- [ ] 逐项对照 [产品范围](产品范围.md) 的“首版完成标准”，没有遗漏，也没有把后续能力带入首版。
- [ ] [测试策略](测试策略.md) 第 7 节的最低门槛全部满足。
- [ ] macOS 与 Windows 各完成一次实机验收并写入验证记录。
- [ ] 三处版本号一致，且与 Release 标签一致。
- [ ] 文档与实现值同步：窗口尺寸、色值、参数基线、command 与 event 清单。
- [ ] 日志脱敏测试通过，产物中无秘密写入路径，见 [日志与诊断](日志与诊断.md)。
- [ ] 中英文文案完整，无死 key、无硬编码语言，见 [文案与国际化](文案与国际化.md)。
- [ ] 新旧应用并行运行互不影响，已审计数据目录与安全存储隔离。
- [ ] 变更记录已更新。
- [ ] 许可证已确定。
