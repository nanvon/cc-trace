# 01 · 产品定位与功能清单

## 一句话定位

当前 cc-bar 是一个 macOS 菜单栏 App：把 Codex、Claude Code、Antigravity 的额度和刷新状态放进紧凑入口，同时读取本地 Codex / Claude Code 会话日志，计算本地 Token、对话和 API 等值费用，并提供统计窗口、设置和可选桌面 HUD。**代码已确认**：入口、Provider、额度、扫描、统计、设置、引导和 HUD 都存在于当前工程；**文档声称**：产品形态为 macOS 14 Sonoma+ 的 accessory 菜单栏应用。

业务边界不是“提供模型服务”，而是“观察本机已有服务的额度与本地日志”。它不会在 App 内登录 Provider，也没有自己的云端账户系统。**代码已确认**：Codex / Claude 的凭据从本地文件或 Keychain 读取，Antigravity 从本机 Language Server 读取。

## 当前产品的几个关键“看起来像功能、实际有边界”的地方

1. **Antigravity 的全局开关与运行状态不是一回事。** 设置可以显示/隐藏它；实际额度还要求本机安装并运行被识别的 Language Server。`installed` 不是“已拿到额度”，`running` 也不等于请求一定成功。**代码已确认**。
2. **手动刷新不是 Provider 请求的绝对强制刷新。** 它绕过周期的 60 秒最小成功间隔，但遇到 429 仍遵守 10 分钟退避。**代码已确认**。
3. **Claude CLI fallback 不是常规数据源。** 只有用户手动整体刷新、API 已失败且当前没有 Claude 快照时才尝试；它和 Claude 的 delegated token refresh 是两条不同链路。**代码已确认**。
4. **“本地费用”不等于订阅真实费用。** 读取本地 Token 后按本地定价表和动态价格目录计算；未知模型的 Token 仍聚合，但费用显示为 0 并保留未定价标志。**代码已确认、测试已确认**。
5. **当前统计不包含 Antigravity。** `UsageApp` 只有 Codex 和 Claude；Antigravity 仅有 quota snapshot 和本地 Provider 状态。**代码已确认**。

## 新版不能直接继承的旧功能清单

跨端草案把本地用量、对话、Timeline、Pricing、其他账号、HUD、隐私模式等列为“首版后再评估”的候选，而不是自动的 v1 要求。**文档声称**：新版首版核心更偏向额度、刷新、缓存、错误、基础设置和双平台桌面壳；旧版功能必须重新分为首版必须 / 简化 / 后续 / 不做。
