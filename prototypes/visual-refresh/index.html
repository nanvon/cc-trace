CC Trace · HeroUI 修复方向评审稿

基于当前实机截图的真实数据与内容,只修四类已确诊的问题:ok 档黑色进度条、大读数字号失衡、层级(canvas/阴影)不显、排版细节碎。信息架构、状态语义、ADR-0019 定宽短码全部保持不变。

🚩 = 该取值推翻或修改了现有文档结论(ADR-0017 的 ok 档色、DESIGN.md 的 canvas/阴影档位),确认方向后需补 ADR 并同步文档。可与 prototypes/macos-native/ 并排对比后再定视觉方向。

1 · 紧凑面板(popover)

数据与截图一致:Codex 每周窗口剩 65%;Claude 5 小时窗口剩 100%、周窗口仅剩 1%。注意风险层级:现在最醒目的是橙色的 1%,不再是健康的黑条。

改动注记

  • 🚩ok 档填充 → success 绿(原 --text-primary 黑,推翻 ADR-0017 取值)。四档色阶 绿→黄→橙→红 完整;stale 降级灰不再与健康态撞色。
  • 🚩大读数 44px → 26px;% 号降为 15px。原「strong but not theatrical」补上具体标尺。
  • 读数行合并:% 、窗口短码、重置倒计时同一行,消 Z 字阅读路径;「重置」「花费」不再是吊着的孤立灰字。
  • 次窗口同族化:ALL 行用同款条(4px)与同款读数行,1% 用 low 橙,危险自然比健康醒目。
  • 状态点并入副标题「● 刚刚已刷新」,右侧变纯动作区;图标统一 16/1.5 线宽。

2 · 主窗口 · 本地用量页

结构不变(筛选 → 按 Provider → 每日花费 → 按模型),统一到与紧凑面板同一套卡片、字号与阴影语言;选「今天」,数值与 popover 花费一致。

改动注记

  • 三卡同排:总计卡与两张 Provider 卡等高并列,总计不再是孤立窄条;26px 读数与 popover 同标尺。
  • 卡片语言统一:主窗口卡与 popover lane 共用同一套 14px 圆角、边框与 🚩 加档阴影,不再「主窗口一套、面板一套」。
  • 命中率条复用余量条组件形态(4px),染 Provider 品牌色的降饱和版,不占用语义色。
  • 表格数字右对齐、行分隔降到 55% 透明度;「—」代表未定价/无值,沿用现有文案规则。
  • 图表高亮语义:非所选范围降到 20% 透明度,「今天」一眼可辨,不再整图同权重。

3 · 设置(主窗口子路由)

分组卡片承载现有全部设置项;控件行左 label 右控件,与用量页共用同一套卡片与分组标题语言。

改动注记

  • 分组卡片化:通用 / 外观与语言 / 用量与计价 / 关于,四组各一张卡,组标题沿用用量页的小标题语言。
  • 行式控件:label 左、控件右,行间 65% 透明分隔线;segmented 与用量页筛选同款。
  • 开关用 success 绿:与「健康余量」同色系,交互蓝仍只留给焦点与主动作。
  • 设置项零增减:内容与现有 i18n 完全一致,不带入后续能力。

4 · 余量四档色阶(修改后)

唯一的语义变化点:ok 档不再是 Ink 黑。其余三档取值不动,stale 降级灰与 ok 绿从此可区分。

ok · >50%72%
warning · 20–50%38%
low · <20%12%
danger · 0%0%
stale 降级(旧数据)65%

为什么 ok 档必须有颜色

  • 原方案 ok = Ink 黑:健康态反而是全面板视觉重量最大的元素,100% 满黑条看起来像出了事——风险层级倒挂。
  • 改成「安静灰」也不行:灰已经被 stale 降级占用。若 ok 也是灰,「新鲜且健康」与「数据过期」将无法区分。
  • 所以 ok 档只能是 success 绿:「当前成功数据」语义的自然延伸,且绿→黄→橙→红是最直觉的余量语言。
  • 需要推翻 ADR-0017 的 ok → --text-primary 一行,并同步 DESIGN.md 与 docs/设计方向与状态规范.md §3.4。
